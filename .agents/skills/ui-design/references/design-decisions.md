# 디자인 개념을 적용하는 판단 기준

화면을 설명하거나 critique할 때 필요한 항목을 골라 쓴다. 개념은 진단을 돕는 도구이며, 모든 화면에 같은 카드 구성이나 장식을 적용하는 이유가 아니다. 확인된 사용성 문제, 코드에서 예상한 위험, 시각적 선호를 구분한다.

## 정보를 읽고 비교하는 화면

| 관찰할 문제 | 관련 개념 | 적용할 판단 |
| --- | --- | --- |
| 가격이 커도 조건을 비교하기 어렵다 | 정보구조, 시각 위계 | 사용자가 비교할 속성을 먼저 고른다. 회당/시간당 같은 단위와 소요 시간을 함께 보여 주고, 중요도에 따라 읽는 순서를 정한다. |
| 모든 요소가 진하고 눈에 띈다 | 대비 | 강조할 대상과 보조 정보를 구분한다. 크기, 굵기, 색을 모두 키우는 대신 필요한 차이를 주며, 색 대비의 접근성 충족은 별도로 측정한다. |
| 레이블이 어느 입력과 연결되는지 모호하다 | 근접성 | 그룹 내부 간격보다 그룹 사이 간격을 크게 둔다. 특정 픽셀 값을 보편 규칙으로 복사하지 않고 기존 간격 토큰과 콘텐츠를 기준으로 관계를 확인한다. |
| 같은 상태의 필터가 서로 다른 기능처럼 보인다 | 유사성, 일관성 | 역할과 상태가 같은 요소는 같은 표현을 쓰고 선택/비선택 차이를 공통 규칙으로 드러낸다. 색만으로 상태를 전달하지 않는다. |
| 카드가 많지만 정보 묶음은 드러나지 않는다 | 공통 영역 | 같은 경계 안에 넣을 이유가 있는 정보를 묶는다. 여백만으로 충분한 관계에 테두리를 더하지 않으며, 개별 항목의 카드가 상위 묶음을 가리지 않게 한다. |
| 카드마다 같은 값을 다른 위치에서 찾아야 한다 | 정렬, 그리드 | 제목의 시작선, 숫자의 끝점, 반복 항목의 열을 맞춘다. 모바일에서는 같은 비교 속성이 사라지지 않도록 읽는 순서를 다시 정한다. |
| 화면은 넓게 비었는데 비교하려면 계속 스크롤해야 한다 | 정보 밀도 | 읽기와 비교를 구분한다. 여러 항목의 같은 속성을 비교하는 작업에는 목록이나 표도 검토하며, 내용을 줄이는 것과 판단 부담을 줄이는 것을 혼동하지 않는다. |
| 제목, 레이블, 보조 정보의 크기가 화면마다 다르다 | 타이포그래피, 타이포 스케일 | 기존 역할별 글자 토큰을 사용한다. 크기뿐 아니라 굵기, 행간, 긴 제목과 글줄 길이를 함께 확인하고 임의의 새 크기 체계를 늘리지 않는다. |

코칭 목록에서 조건을 먼저 보여 주는 판단은 조건 비교가 핵심일 때의 예시다. 소개 글, 사진 피드, 관리 도구에 같은 우선순위나 낮은 밀도를 강제하지 않는다.

## 행동 전과 행동 후

- **어포던스와 시그니파이어:** 가능한 행동과 그 행동을 알아차리게 하는 단서를 구분한다. 손잡이, 화살표, 밑줄은 실제 드래그·선택·이동 동작과 맞아야 한다. 단서를 그리는 것만으로 기능을 구현했다고 판단하지 않는다. 공통 primitive의 키보드 조작과 접근 가능한 이름도 함께 확인한다.
- **매핑:** 조작이 어느 대상에 영향을 주는지 위치와 레이블로 설명한다. 항목 옆의 삭제는 대상이 분명해야 하고, 설정과 미리보기의 관계가 화면 폭 변경으로 엇갈리지 않아야 한다.
- **피드백:** 클릭 접수, 요청 진행, 서버 성공, 실패를 구분한다. 눌림 효과나 요청 시작을 저장 성공으로 표현하지 않는다. 대기 중 재입력·중복 실행 정책과 완료 후 이동을 기존 동작에 맞추고, 상태 안내를 애니메이션이나 색에만 맡기지 않는다.
- **제약과 오류 예방:** 허용되는 선택 수, 필수 입력, 처리 중 실행 제한을 필요 지점에서 설명한다. 비활성 버튼의 원인을 알 수 있어야 하며, 화면에서 막은 것만으로 서버 권한·정합성을 보장한다고 설명하지 않는다.
- **오류 복구:** 실패 후 남아야 할 입력, 다시 실행할 작업, 취소하거나 돌아갈 곳을 구분한다. 작성한 값을 지운 뒤 재입력을 요구하거나 일부 성공을 전체 성공으로 안내하지 않는다. 저장 흐름은 해당 프로젝트의 상태·폼·IO 소유권을 따른다.

## 기억과 이동 상태

- **재인과 회상:** 이미 알고 있는 계정이나 선택을 기억해서 입력하게 하기보다 보고 고르게 할 수 있는지 검토한다. 긴 선택 목록 자체의 탐색 부담과 개인정보 노출도 함께 고려하며, 이 원리만으로 최근 기록 수집 기능을 새로 추가하지 않는다.
- **인지 부하:** 글자 수 대신 사용자가 해야 할 기억, 계산, 비교를 본다. 가격 단위가 다른 값을 큰 글자로 나열하는 것만으로 비교가 쉬워지지는 않는다.
- **점진적 공개:** 사용 빈도와 작업 중요도를 근거로 기본 정보와 부가 선택을 나눈다. 주요 조건, 가격 단위, 필수 오류까지 숨겨 화면만 짧게 만들지 않는다. 접힌 필터에도 현재 적용 상태를 알 수 있는 단서를 둔다.
- **멘탈 모델과 일관성:** 사용자가 다음에 기대할 화면과 상태를 확인한다. 검색 결과에서 상세로 갔다 돌아올 때 검색어, 필터, 위치가 어떻게 복원되는지 본다. 비슷한 레이블이 다른 동작을 하거나 같은 동작의 이름이 화면마다 달라지지 않게 한다. 현재 서비스에 없는 사용자 기대를 실제 조사 결과처럼 단정하지 않는다.

## 검토 결과를 남길 때

사용자 과업, 확인한 불편, 바꾼 표현이나 상태, 검증 결과를 연결해 짧게 설명한다. 예시 도해와 실제 서비스 캡처를 구분하고, 가상의 비교를 사용자 실험이나 전환율 개선으로 보고하지 않는다. 검증 범위와 수치 보고는 루트 AGENTS.md를 따른다.

개념의 구분이 필요하면 [NN/g의 시각 디자인 원칙](https://www.nngroup.com/articles/principles-visual-design/), [공통 영역](https://www.nngroup.com/articles/common-region/), [Don Norman의 signifier 설명](https://jnd.org/signifiers-not-affordances/), [점진적 공개](https://www.nngroup.com/articles/progressive-disclosure/), [멘탈 모델](https://www.nngroup.com/articles/mental-models/)을 참고한다. 원문 정의와 현재 제품에 적용한 판단은 구분한다.
