# UI 디자인

사용자가 정한 화면 역할과 기존 이동 흐름을 먼저 확인한다. 별도 소개 페이지를 요청받았으면 기존 메인을 교체하거나 앱의 첫 진입 경로를 바꾸지 않는다. 프로젝트의 디자인 토큰과 컴포넌트 규칙을 함께 따른다.

## 개념을 화면 판단으로 연결하기

- 읽기, 조건 비교, 검색, 작성, 실패 복구 중 사용자가 하려는 일을 먼저 정한다. 읽는 순서를 정하는 위계와 이를 표현하는 대비를 구분하며, 가격이나 사진을 모든 화면의 최우선 정보로 고정하지 않는다.
- 정보 밀도를 무조건 낮추지 않는다. 비교 화면에서는 단위가 같은 값과 일관된 위치가 필요하고, 설명을 읽는 화면에서는 글줄 길이와 묶음이 중요하다. 여백이나 카드 수 자체를 품질 목표로 삼지 않는다.
- 레이아웃의 관계나 상호작용이 어색하면 [개념별 판단과 적용 예시](references/design-decisions.md)의 관련 항목을 읽는다. 용어를 나열하는 대신 어느 요소의 관계나 어느 행동 전후를 바꿀지 설명하고 실제 화면에서 확인한다.

## 서비스별 우선순위

- Game Mate(`game-feedback`)와 피식(`photo-contest`)은 모바일 우선으로 설계한다. 휴대폰의 주요 행동, 터치 영역, 읽기 순서와 입력 흐름을 먼저 정하고 작은 화면의 기본 스타일부터 작성한다.
- 두 서비스는 360~430px 휴대폰 화면을 먼저 확인한다. 하단 메뉴, 안전 영역, 긴 글과 입력 중 줄어든 화면에서도 콘텐츠와 주 행동이 가려지지 않아야 한다.
- 데스크톱은 같은 흐름이 자연스럽게 확장되고 가로 넘침, 과도한 늘어짐, 겹침이 없을 정도로 대응한다. 기존 탐색 구조는 유지하되 데스크톱 전용 장식이나 별도 화면 구성에 과하게 투자하지 않는다.
- 검증 순서는 모바일의 실제 사용 흐름을 먼저, 데스크톱의 기본 배치를 나중으로 둔다. 이 우선순위를 블로그와 관리자 화면에 자동으로 확대하지 않는다.

## 서비스 레퍼런스

- 같은 도메인과 비슷한 사용 맥락에서 **2016년 이후 출시됐고 현재까지 주기적으로 업데이트되는 서비스**를 레퍼런스로 고른다. 출시 시점과 유지보수 여부는 별개의 조건으로 확인한다. 최근에 만들어졌다는 이유만으로 도메인 적합성보다 앞세우지 않는다.
- 공식 서비스 화면, 출시 공지, 변경 이력이나 앱스토어 버전 기록에서 날짜를 확인한다. 검색 노출 순서, 페이지 수집 날짜, 한 번의 최근 업데이트만으로 최근 출시와 꾸준한 운영을 단정하지 않는다.
- 적용할 레퍼런스를 소수로 정하고 서비스 이름, 링크, 확인한 출시 시점과 업데이트 근거, 이번 화면에서 참고할 부분을 짧게 남긴다. 조건을 확인할 수 없으면 확인한 범위와 부족한 근거를 밝히고, 오래된 서비스를 최근 서비스처럼 제시하지 않는다.
- 장식보다 정보 밀도, 핵심 행동의 위치, 정렬과 여백, 모바일 탐색 흐름을 참고한다. 레퍼런스의 브랜드나 문구를 복제하거나 그 서비스의 기능을 이유 없이 추가하지 않는다. 사용자가 지정한 레퍼런스가 있으면 함께 검토한다.
- 특정 서비스의 화면 구성, 색상, 타이포그래피, 아이콘과 상호작용을 통째로 따라 하지 않는다. 색이나 문구만 바꾼 복제 화면도 만들지 않는다. 여러 레퍼런스에서 필요한 원리를 골라 현재 서비스의 목적과 콘텐츠에 맞게 다시 구성한다.

## 콘텐츠와 문구

- 화면의 모든 공간을 콘텐츠로 채우지 않는다. 빈 공간도 구성의 일부다. 현재 화면에서 필요한 정보와 주요 행동부터 남기고, 설명과 보조 행동은 필요한 맥락으로 옮긴다.
- 배치가 허전하다는 이유로 카드, 통계, 배지, 기능 소개, 샘플 게시물을 추가하지 않는다. 사용자가 승인한 콘텐츠 범위 안에서 작업하고, 예시 데이터는 예시임을 밝힌다.
- 제품 문구에 가운데 점 `·`이나 앰대시 `—`를 사용하지 않는다. 자연스러운 문장, 쉼표, 줄바꿈, 간격으로 구분한다. 사용자 원문이나 데이터 자체를 임의로 바꾸지는 않는다. Game Mate 웹은 `projects/game-feedback/apps/web/src/shared/i18n/messages.test.ts`가 `.tsx`의 따옴표 문자열·JSX 텍스트와 번역 사전에서 U+00B7·U+2014를 검사한다(일본어 번역의 `・`는 허용, 템플릿 리터럴은 검사 밖). 피식 web은 `projects/photo-contest/apps/web/src/product-copy.test.ts`가 `.ts`·`.tsx`의 따옴표 문자열, 템플릿 리터럴 조각, JSX 텍스트에서 같은 두 글자를 검사한다(TypeScript 구문 트리로 읽어 주석은 검사 밖).
- 뜻 없이 붙이는 영문 소제목, 반복 구호, 제목을 다시 설명하는 문장을 덜어낸다. 문구를 추가하기 전에 사용자의 이해나 다음 행동에 필요한지 판단한다.

## 정렬과 여백

- 본문, 제목, 카드와 버튼의 시작선을 맞춘다. 화면마다 읽기 폭을 정하고, 넓은 화면에서도 내용을 끝까지 늘리지 않는다.
- 같은 역할의 요소에는 같은 간격과 안쪽 여백을 적용한다. 관련된 요소는 가까이, 다른 영역은 충분히 떨어뜨려 묶음이 드러나게 한다.
- 여백은 기존 간격 토큰으로 조절한다. 빈칸을 메우기 위한 장식이나 임의의 위치 보정 대신 부모 레이아웃과 요소의 크기를 먼저 확인한다.
- 주요 행동이 눈에 들어오도록 시각적 우선순위를 정한다. 모든 영역을 테두리 카드로 감싸거나 강조색을 반복하지 않는다.
- 입력창 안에 둔 버튼은 한 줄 입력 상태에서 위, 아래, 옆 여백이 같은지 실제 값을 재서 확인한다. 피식 댓글 입력창은 높이를 버튼과 같은 44px로 맞췄다(2026-11-05 사용자 지적). 여러 줄로 늘어나면 버튼은 아래에 붙여 둔다.

## 폼과 주 행동

- 피식·Game Mate의 공통 버튼·입력·모달·색·타이포는 `@side/design-system`이 소유한다. 블로그는 기존 UI 구성을 유지하며 같은 패키지 사용을 강제하지 않는다.
- 범용 컴포넌트의 모양은 공통 primitive의 variant로 더한다. 앱 전용 cva는 재사용되는 다축/다값 변형에만 쓰고 단순 켜짐/꺼짐은 기존 cn 또는 data/aria 상태로 처리한다. 같은 버튼·칩 모양을 앱마다 복제하지 않는다.

- 여러 필드, 미디어 선택, 반복 항목, 긴 설명 등으로 스크롤이 필요한 복잡한 폼은 별도 페이지로 만든다. 바텀시트를 늘리거나 입력을 압축해 긴 폼을 넣지 않는다. 시트는 짧은 입력, 선택, 확인에만 사용한다.
- 전용 작성·수정·가입 설정 페이지의 저장·제출 영역은 화면 하단에 항상 보이도록 둔다. 본문만 독립적으로 스크롤하고 고정 영역이 마지막 필드나 오류를 덮지 않게 한다. 키보드로 화면이 줄어들 때도 같은 구조와 안전 영역을 유지한다.
- 전용 폼 페이지에서는 사이트 푸터를 숨긴다. 저장 영역과 하단 탐색이 겹치지 않게 하며, 정보와 사진처럼 같은 편집 목적의 변경은 저장 버튼 하나로 제출한다. 일부 요청만 성공해도 남은 초안을 버리거나 완료 화면으로 이동하지 않고 실패한 변경을 재시도할 수 있게 한다.
- 취소와 주 행동은 같은 높이와 너비로 나란히 두고, 주 행동 하나뿐이면 읽기 폭 안을 채운다. 기존 공통 컴포넌트를 사용하며 인라인 댓글·검색 폼까지 화면 하단으로 옮기지 않는다.
- 문구만으로 행동이 분명한 전용 폼의 제출 버튼에는 아이콘을 붙이지 않는다. Game Mate의 `게시글 등록` 버튼에서 화살표를 지운 사용자 피드백(2026-11-05)에 따른 기준이며, 칩이나 문구 없는 버튼의 아이콘까지 일괄 제거하지 않는다.
- 문구 없이 아이콘만 쓰는 전송 버튼은 보내기를 뜻하는 아이콘과 `aria-label`을 함께 둔다. 피식 댓글 전송 버튼은 사용자의 교체 요청(2026-11-05)에 따라 위쪽 화살표 대신 Game Mate 댓글 폼과 같은 `Send`를 쓰고, 원형 대신 공통 버튼의 기본 모서리를 쓴다. 아이콘은 공통 `Button`의 `icon` prop으로 넘겨 전송 중에는 진행 표시로 바뀌게 한다.

## README 화면 갱신

- README에 실린 버튼, 화면, 흐름을 바꾸면 `docs/media`에서 그 화면이 나오는 파일을 모두 찾는다. 영상만 다시 찍고 같은 화면의 스크린샷을 빠뜨리지 않는다(2026-11-05 사용자 지적).
- 기존과 같은 예시 데이터와 흐름을 production 빌드의 격리 테스트 포트에서 찍는다. 화면은 430×860, 배율 1로 맞추고 사용자 개발 서버와 DB를 쓰지 않는다. 기존 이미지의 테마를 유지해 Game Mate는 다크, 피식은 라이트로 찍는다. 일회용 촬영 설정과 저장소 대역은 저장소에 남기지 않는다.
- README는 공개 문서이므로 로컬 `.env` 값이 화면에 찍히지 않게 한다. Game Mate 푸터의 문의 메일은 `GAME_FEEDBACK_CONTACT_EMAIL`을 따르므로 빌드 환경에서 공개 주소로 지정하고, 찍은 첫 프레임과 마지막 프레임을 눈으로 확인한다.
- `docs/media/manifest.json`의 크기, 바이트, 해시, 기준 커밋을 실제 파일과 맞추고, 길이가 달라지면 README의 안내 문구도 고친다. 저장소 대역으로 찍었다면 실제 S3를 검증한 것으로 보고하지 않는다.

## 모바일 확인

- 데스크톱을 줄여 넣지 않는다. 작은 화면에서는 보조 문구와 중복 행동을 줄이고, 글줄 길이와 제목 줄바꿈을 다시 조정한다.
- 사진 비율과 본문을 보존하며 가로 넘침, 겹치는 고정 바, 안전 영역과 터치 영역을 확인한다. 앱의 기존 탭과 인증 흐름을 유지한다.
- 구현 후 실제 모바일 폭과 데스크톱 폭에서 화면을 확인한다. 정보가 과한 부분, 어긋난 시작선, 불규칙한 간격을 수정한다. 웹뷰 대역이나 브라우저 검증을 실기기 검증으로 보고하지 않는다.
