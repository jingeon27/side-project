# 카카오 대화와 SillyTavern 최소 연동

기준일 2026년 11월 12일. 장비는 Mac M5 Pro 48GB이며 한국어 대화가 필수다. 이번 제안은 로컬에서 기존 도구를 최대한 그대로 실행하고, 카카오 내보내기 파일을 검토 가능한 캐릭터 카드로 바꾸는 부분만 구현한다. 실제 사용자 파일·서비스·모델은 접근하거나 설치하지 않았다.

## 무엇을 재사용하고 무엇만 직접 만들 것인가

### Takeaway

SillyTavern의 채팅 UI·캐릭터 편집·대화 기록·World Info를 재사용한다. 직접 만들 코드는 한국어 카카오 파일 파서, 동의 범위·마스킹 검토, 관찰된 말투 초안, 승인된 Character Card 내보내기의 작은 로컬 도구로 한정한다.

### Cited Findings

- SillyTavern의 Characters는 AI가 수행하는 역할이며, 파일 가져오기·카드 내보내기·캐릭터 편집·lore 연결·그룹 대화 등의 관리 기능이 있다. — [공식 Characters 문서](https://docs.sillytavern.app/usage/characters/), [공식 문서 저장소 본문](https://raw.githubusercontent.com/SillyTavern/SillyTavern-Docs/main/Usage/Characters/index.md)
- SillyTavern의 Persona는 사용자가 대화에 참여할 때 사용하는 이름·아바타·설명이다. Character를 Persona로 변환하면 이름·설명은 쓰지만 Personality나 Scenario 같은 다른 카드 필드는 쓰지 않는다. — [공식 Personas 문서](https://docs.sillytavern.app/usage/core-concepts/personas/)
- World Info는 키워드가 대화에 나타날 때 관련 내용을 프롬프트에 넣는다. 캐릭터·사용자 Persona·대화별로 연결할 수 있고, 캐릭터 내보내기에는 연결한 주 World Info 하나만 포함된다. 출력에 반드시 반영됨을 보장하지 않는다. — [공식 World Info 문서](https://docs.sillytavern.app/usage/core-concepts/worldinfo/)
- Character Description·Personality·Scenario는 반복적으로 프롬프트에 포함되고, 예시 대화는 대화 이력이 차면 제외될 수 있다. 따라서 장문의 원본을 카드 필드에 넣으면 대화용 문맥 예산을 소비한다. — [공식 Character Design 문서](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)

### Inferences

- 초기에 ST를 fork하거나 React 채팅 UI, 자체 메시지 DB, RAG 서비스, 워크플로 엔진을 만들 필요가 없다. 승인된 카드 파일을 저장하고 ST의 기본 Import Character로 넣는다. 카드·대화·로어 편집은 ST UI가 맡는다.
- 사용자에게 부르는 '페르소나 챗봇'은 UI 용어와 구별한다. **AI가 대화할 상대의 역할 = Character**, **사용자가 연기할 나의 역할 = Persona**다. 대상 인물의 말투를 AI가 사용해야 한다면 Character Card로 내보내고, 사용자 Persona 칸에 넣지 않는다.
- 최소 도구 흐름은 `파일 선택 → 화자/기간/권리 범위 확인 → 개인정보 마스킹 미리보기 → 한국어 말투 초안 → 사용자 수정·승인 → 카드 JSON 저장 → ST 가져오기`다. 첫 검증은 샘플 파일과 단일 CLI로 가능하고, 반복 사용의 마스킹 검토가 불편할 때만 간단한 로컬 검토 화면을 추가한다.
- 한국어로 카드 내용, 생성 지침, 첫 인사, 예시 대화, 오류 안내, 설정 안내, README를 작성한다. Character Card의 표준 JSON 키와 API 프로토콜 필드, 코드 식별자는 규격·저장소 스타일을 유지한다. 한국어 키로 바꾸면 호환성이 깨지므로 값과 사용자 설명을 한국어로 제공한다.
- 기본 지침 예: '자연스러운 한국어로 답한다. 상대와 상황에 맞는 존댓말을 유지하고, 명시적으로 합의된 상황에서만 반말을 사용한다. 관찰한 말투를 참고하되 실제 당사자라고 주장하지 않으며 알 수 없는 사생활을 꾸며내지 않는다.' 이 문구만으로 품질을 보장하지 않고 아래 검증을 한다.
- Dify와 n8n은 지금 입력 1개·분석 1개·내보내기 1개인 흐름에는 운영 비용이 크다. 비개발자가 다수 외부 시스템의 조건·재시도를 편집해야 할 때 재검토한다. LangChain은 여러 검색기·도구·체인 공통화가 실제로 중복될 때, pgvector는 승인된 장기 기억이 커져 키워드 기반 World Info로 필요한 검색을 재현하지 못하고 여러 사용자가 검색해야 할 때 검토한다. 이 선택은 제품 범위에 대한 설계 판단이며 각 제품의 불가능을 주장하는 것은 아니다.
- 초기에는 별도 벡터 DB·임베딩·LoRA 없이 작은 카드와 승인된 World Info로 시작한다. 긴 소설에서는 장·장면별 설정 요약을 사람이 정리한 로어로 추가하고, 누락·충돌이 실제로 반복되는지 확인한 뒤 검색 계층을 늘린다.

### Gaps

- ST에서 사용하는 추론 엔진의 Qwen 모델 호환성과 한국어 품질은 별도 모델 조사 및 실제 실행 대상이다. 한국어 문서나 카드 형식 지원은 한국어 생성 품질의 증명이 아니다.
- UI 전체 한국어 번역 상태와 특정 ST 버전의 모든 V3 필드 동작은 이번 조사에서 실행 검증하지 않았다. 이를 '완전 한국어 지원' 또는 'V3 완전 호환'으로 표현하지 않는다.

## 어떤 카드 규격과 라이선스를 사용할 것인가

### Takeaway

최초 출력 계약은 Character Card V2 JSON과 필요할 때 내장 character_book으로 고정한다. ST가 가져와 다시 내보낸 파일에서 필수 내용이 보존되는지 검증한 뒤 지원 버전을 고정한다. PNG 카드·V3·CHARX는 필요해질 때 추가한다.

### Cited Findings

- V2 원규격은 식별자와 버전, `data` 안의 이름·설명·성격·상황·첫 메시지·예시 대화, 메타데이터, 선택적인 character_book을 정의한다. creator_notes는 프롬프트 내용이 아니며, extensions는 알 수 없는 확장 값도 손실시키지 않도록 정의되어 있다. — [원작성자의 V2 규격](https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md)
- V3 원규격은 JSON, PNG/APNG의 ccv3 메타데이터, CHARX의 card.json을 정의하고, 자산과 다국어 제작자 노트 등의 필드를 확장한다. 다국어 제작자 노트는 사용자에게 보여주는 카드 메타데이터이며 한국어 생성 기능 자체가 아니다. — [원작성자의 V3 규격](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md)
- V3 규격 저장소 LICENSE는 MIT 조건이며 저작권·허가 고지를 유지하도록 규정한다. — [V3 LICENSE](https://github.com/kwaroran/character-card-spec-v3/blob/main/LICENSE)
- SillyTavern의 release LICENSE는 GNU AGPL v3이다. 수정 버전의 네트워크 제공이나 배포 시 소스 제공 등 해당 조건을 검토해야 한다. — [SillyTavern LICENSE](https://github.com/SillyTavern/SillyTavern/blob/release/LICENSE)
- n8n의 2026-10-06 갱신 공식 도움말은 self-hosted Community에 Sustainable Use License를 적용하고, 조직 외 사용자가 workflow를 구성하는 제품 등은 상업 라이선스 영역이라고 설명한다. 무제한 오픈소스로 묶어 소개하면 부정확하다. — [n8n 공식 라이선스 설명](https://support.n8n.io/article/can-i-use-your-license-for-my-use-case)

### Inferences

- 최소 exporter는 표준 필수 필드와 빈 기본값을 빠짐없이 넣고, 승인한 관찰 요약을 description/personality, 한국어 첫 인사를 first_mes, 재작성한 짧은 한국어 대화 예시를 mes_example, 승인한 맥락 지식을 character_book에 둔다. meta에는 변환기 버전 정도만 두고, 원문·실명·카카오방 이름·메시지 ID·로컬 파일 경로를 숨겨 넣지 않는다.
- 원본 추적·동의 기록·근거 메시지 ID는 로컬 검토 데이터에만 남긴다. 내보낸 카드는 복사·전달될 수 있는 별도 데이터 사본이므로, 공유 전에 전체 JSON과 포함된 로어를 미리 보게 한다. 원문 재인용보다 승인된 말투를 반영한 새 예시를 기본으로 사용한다.
- 체계적인 역할 지침은 직접 작성한 한국어 템플릿으로 유지하고, 원문에서 추출한 문장을 system_prompt 또는 post_history_instructions로 옮기지 않는다. 처음에는 이 override 필드를 비워 ST의 사용자 설정을 따르게 한다. 다운받은 외부 카드도 이 필드를 검토해야 한다.
- V2/JSON은 이미지 처리 라이브러리와 메타데이터 파서를 새로 도입하지 않고도 결과를 눈으로 검토하기 쉽다. 외형이 필요한 PNG 내보내기는 ST에 맡긴다. V3는 음성·표정 등 묶음 자산이 필요하고 대상 도구의 지원이 확인된 이후 도입한다.
- ST를 upstream 그대로 로컬에서 실행하고, 우리 도구는 파일 형식으로 연결한다. 제3자 코드를 모노레포에 복사하거나 ST 자체 UI를 수정·재배포하는 작업은 초기 범위 밖이다. 이 구조를 법적 면제라고 단정하지 않고, 실제 배포 조합을 정할 때 라이선스를 검토한다.
- 스펙 저장소의 라이선스, ST 프로그램 라이선스, 가져온 카드의 콘텐츠·이미지 이용권은 서로 별개다. 호환 포맷이라는 이유로 타인의 카드·대화·초상권까지 자유롭게 이용 가능한 것은 아니다.

### Gaps

- V2 규격 저장소의 라이선스와 파서 유틸리티 라이선스는 이번에 별도로 검증하지 않았다. 해당 패키지 코드를 바로 의존성으로 채택했다고 보고하지 말 것. 규격을 참고하는 최소 exporter와 ST 자체 import를 기본 제안으로 둔다.
- 실제 JSON import/export 왕복, 카드 로어 import 활성화, 알려지지 않은 필드 보존, PNG 메타데이터 안전성은 아직 실행하지 않았다. 호환 완료 주장은 검증 이후 한다.

## 한국어 카카오 데이터와 개인정보는 어떻게 검증할 것인가

### Takeaway

카카오 파일 파싱은 한국어 날짜·시각·여러 줄·화자 매핑부터 실제 동의된 샘플로 확인해야 한다. 대화에서 관찰된 표현 경향과 근거를 검토한 뒤 승인된 요약만 카드로 옮기며, 카카오 개인 대화 읽기 API가 생긴 것처럼 설명하지 않는다.

### Cited Findings

- 카카오 공식 답변은 개인 간 메시지 내용을 타 시스템에 연동하도록 제공하지 않는다고 명시한다. 오픈소스 파서나 n8n 커넥터를 붙이는 것으로 이 제품 제약을 해결할 수 있는 것은 아니다. — [2026-02-09 공식 DevTalk 답변](https://devtalk.kakao.com/t/topic/148362)
- 카카오 채널 스킬의 현재 공식 콜백은 일반 5초 제한을 넘는 처리에 사용하며, URL은 5분 동안 1회 사용할 수 있다. 과거 대화 파일 가져오기와 별도 기능이다. — [공식 콜백 가이드](https://kakaobusiness.gitbook.io/main/tool/chatbot/skill_guide/ai_chatbot_callback_guide)
- 개인정보 보호법 제15조는 동의 등 적법한 수집·이용 근거와 목적 범위 내 이용을 요구한다. '전체 대화 참가자 동의를 기본 제품 정책으로 받자'는 보수적 권고와 '모든 경우 법적으로 전원 동의만이 유일한 근거'라는 주장은 다르다. — [제15조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334803)
- 개인정보위 생성형 AI 안내서는 기성 오픈 모델을 활용·미세조정하는 서비스도 고려 대상으로 설명한다. 로컬 모델이라는 이유만으로 개인정보 이슈가 없어지는 것은 아니다. — [2025-08-06 개인정보위 안내서 발표](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000%22&nttId=11410)

### Inferences

- 로컬 입력에서 먼저 날짜·시각·화자를 파싱하되 원문 줄 위치와 원래 화자 관계를 보존한다. 한 사람 발화만 끊어 추출하면 농담·반박·인용을 본인 의견으로 오인할 수 있으므로, 허용된 주변 맥락을 함께 분석하고 근거를 검토한다. 대상 사람 발화와 상대 발화를 구분한다.
- 검증 fixture는 실제 동의된 파일을 마스킹한 형식 샘플과 공개 가능한 합성 fixture를 구분한다. 저장소에는 개인정보가 없는 합성·검증된 비식별 샘플만 넣는다. 테스트 항목: 오전/오후와 날짜 경계, 여러 줄 메시지, 화자명에 구두점, 같은 표시 이름, 닉네임 변경, 잘못된 인코딩, 중복 가져오기, 삭제된 메시지 표시, 입퇴장·초대 같은 시스템 알림, 사진·음성·파일 자리표시자. 첨부 내용은 해석·복원 지원하지 않는다고 표시한다.
- 정규식 하나로 모든 OS 내보내기를 지원한다고 주장하지 않는다. 지원하지 않는 변형은 감지해 한국어 오류를 보여주고, 미해석 줄 수와 샘플을 검토 화면에 남긴다. 화자를 확인하지 못하면 카드 생성으로 진행하지 않는다.
- 이름·전화·주소·계좌·비밀 URL 등 마스킹 결과를 사용자가 확인한다. 자동 마스킹으로 완전 익명화했다고 부르지 않는다. 카드 내용에서는 건강·정치·종교·성적 지향과 같은 민감한 속성을 추정하지 않는다. 관찰한 말투를 성격 진단·확정 MBTI로 표현하지 않는다.
- 한국어 출력 검증은 존댓말/반말 일관성, 문장 자연스러움, 불필요한 번역투·중국어/영어 혼입, 자음 표현과 이모지 사용 강도, 맥락에 따른 반응, 모르는 사생활에 대한 불확실성 표현을 포함한다. 분리해 둔 한국어 질문으로 카드 적용 전후를 비교하고, 예시를 그대로 반복하거나 실명/원문 비밀을 유출하는지 본다.
- lorebook 키워드는 한국어 조사·띄어쓰기·별칭 때문에 의도대로 활성화되는지 확인한다. 중요한 말투 규칙은 키워드가 없어도 유지되는 카드 기본 설명에 짧게 두고, 승인한 배경 지식만 lorebook에 둔다.
- 모든 파일·초안·승인 카드·ST 대화 기록은 Mac 로컬에 둔다. ST 추론 연결을 loopback 모델 서버로 고정하고 외부 URL 카드 import·외부 API를 사용하지 않는다. 모델 설치 후 인터넷을 차단한 상태로 파일 분석→카드 가져오기→한국어 대화를 시험한다. ST 데이터 폴더·생성 카드도 삭제 대상에 포함한다.
- 카카오 채널은 이후 선택 기능이며, 그때는 신규 발화가 Kakao/relay를 거친다는 데이터 흐름을 별도로 설명한다. 기존 원문을 클라우드 큐로 올리지 않는다. 채널 기능을 켜지 않은 로컬 도구에는 cloud delivery·CDN·서버 인증 계층을 미리 만들지 않는다.
- Amplitude를 넣는 자체 UI를 만들면 저장소 기존 카탈로그를 따르고 클릭과 성공을 구분한다. 대화·카드·성격 추정값·실명·검색어·토큰은 보내지 않고, 키가 없는 기본 로컬 실행은 전송하지 않는다. 자체 화면이 없는 최초 CLI 검증에는 사용자 행동 계측용 외부 연결을 새로 만들 필요가 없다.

### Gaps

- 카카오 내보내기의 OS별 메뉴·확장자·포맷 공식 본문은 이전 조사에서도 접근하지 못했다. 파일을 확보하기 전에는 '모든 카카오 내보내기 완벽 지원'을 약속하지 않는다.
- 프로그램·모델 설치, 한국어 품질 평가, import/export fixture 시험을 실행하지 않았다. 이번 결과는 선택과 구현 경계에 대한 계획이다.
