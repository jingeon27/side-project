# 카카오톡 연동과 성격 추론 설계

기준일: 2026년 11월 12일. 사용자 장비는 Mac M5 Pro 48GB로 확정됐다. 아래의 사실은 공식 원문을 확인했고, 설계 선택은 Inferences에 분리했다. 모델·클라우드 공급자 선택은 다른 조사 범위다.

## 카카오톡의 어떤 대화를 공식적으로 가져올 수 있는가

### Takeaway

일반 카카오톡 개인·그룹 대화방의 수발신 이력을 서비스가 실시간으로 읽는 공식 API 연동을 전제로 시작하면 안 된다. 과거 대화는 사용자가 제공하는 파일을 로컬에서 가져오는 흐름으로, 향후 챗봇 대화는 카카오톡 채널의 스킬 요청을 받는 흐름으로 분리한다.

### Cited Findings

- 카카오 DevTalk의 공식 담당자 tim.l은 2026-02-09 답변에서 개인 간 메시지 내용 및 수발신 내역을 타 시스템에 연동하도록 제공하지 않는다고 설명한다. 상담톡은 채널·상담톡 딜러 계약을 통한 별도 영역이다. — [공식 연동 가능 여부 답변](https://devtalk.kakao.com/t/topic/148362)
- 카카오톡 메시지 REST API는 같은 서비스 사용자 사이의 발송 기능이며, 나에게 보내기와 친구에게 보내기를 제공한다. 친구 발송에는 권한과 동의 및 쿼터 제약이 있다. 이것은 내 개인 채팅함의 읽기 API가 아니다. — [카카오톡 메시지 REST API](https://developers.kakao.com/docs/ko/kakaotalk-message/rest-api)
- 공식 REST API 목록의 카카오톡 영역은 프로필·친구·메시지 발송·채널 관계 등의 기능을 제시하며 개인 대화 이력 읽기 기능을 열거하지 않는다. 이 목록만으로 부재를 증명하기보다 위 공식 답변과 함께 판단해야 한다. — [REST API 레퍼런스](https://developers.kakao.com/docs/ko/rest-api/reference)
- 채널 챗봇의 스킬은 봇으로 들어온 요청을 HTTP POST JSON으로 전달하며, payload에 사용자, 발화, 블록 등의 정보가 포함된다. 일반 개인 채팅방 전체를 읽는 구조가 아니다. — [스킬 만들기](https://kakaobusiness.gitbook.io/main/tool/chatbot/skill_guide/make_skill)

### Inferences

- MVP의 데이터 입력은 카카오 대화 내보내기에서 얻은 텍스트 파일을 사용자가 직접 선택하는 가져오기, 혹은 동의받은 예시 문장을 붙여넣기로 설계한다. PC 알림 가로채기, DB 복호화, 비공식 계정 자동화, 화면 상시 수집은 제품 의존성에서 제외한다.
- Mac M5 Pro 48GB의 초기 기본 모드는 엄격한 로컬 분석으로 한다. 파일 선택·파싱·마스킹·임베딩·프로필 생성·벡터 검색·원문/프로필/채팅 저장을 모두 Mac에서 수행하고, 원문·메시지 청크·임베딩·개인 프로필을 클라우드 API/작업 큐/오브젝트 저장소/오류 리포트에 올리지 않는다. 이 기능의 큐도 로컬 소유다. 모델 설치가 끝난 뒤 외부 통신을 차단한 상태로 정상 작동하는지 검증한다. 클라우드 UI가 필요해져도 개인정보가 없는 작업 상태만 전달하고, 웹사이트가 로컬 추론 포트를 임의 호출하지 못하도록 loopback 바인딩·인증·Origin 검증을 설계한다.
- 먼저 로컬 파서가 날짜·화자·본문을 분리하고 업로더가 화자 매핑·기간·대상 메시지를 확인하도록 한다. 실명 대신 프로젝트 내부 별칭을 사용한다. 외부로 전송하기 전에 개인정보 마스킹 미리보기를 제공한다.
- 대화 원본을 통째로 LLM에 넣지 않는다. multiline, 시스템 메시지, 동일 표시 이름, 닉네임 변경, 이모티콘/사진 자리표시자, 중복 파일 가져오기, 누락된 시각을 파서 검증 항목으로 둔다. 파일 형식별 지원은 실제 동의된 샘플로 검증하고 알 수 없는 형식은 실패를 표시한다.
- 카카오 로그인은 로그인 사용자 식별이며 대화 읽기 권한이 아니다. 웹 계정과 채널 봇 사용자 키 연결은 별도 명시적 연결 흐름으로 구현하고 전화번호나 이름의 추정 매칭을 사용하지 않는다.
- 실제 인물을 모방한 봇은 해당 사람의 승인 범위 안에서 생성하고, UI에 AI 페르소나라는 점을 표시한다. 초기에는 웹에서 작성·확인하는 답변 초안 기능으로 제한하며 다른 사람의 계정인 것처럼 자동 발송하는 기능을 넣지 않는다.

### Gaps

- 카카오 고객센터의 내보내기 도움말은 검색 인덱스에서 충분한 본문을 확보하지 못했고 발견한 공식 도움말 URL 열기도 실패했다. 따라서 OS별 메뉴명, 확장자, 모든 메시지 보존 여부는 이번 조사에서 공식 확인하지 않았다. 문서에는 내보낸 텍스트 가져오기라는 설계와 실제 파일 형식 검증 과제를 쓰고, 특정 OS 경로·CSV 지원·사진 추출을 검증된 사실로 단정하지 말 것.
- 상담톡의 계약·가격·개별 권한은 조사하지 않았다. 일반 개인 채팅 이력 대안으로 제시하지 말 것.

## 채널 챗봇을 로컬 모델에 연결할 때의 시간과 네트워크 제약은 무엇인가

### Takeaway

일반 스킬 응답 제한은 5초이고, 현재 공식 원문의 콜백 URL은 5분 유효·1회 사용이다. 짧은 대화는 큐와 콜백으로 처리하고 긴 소설·영상은 웹 작업 상태 페이지에서 확인하도록 설계한다.

### Cited Findings

- 현재 공식 콜백 문서 본문은 일반 스킬 제한을 5초, callbackUrl 유효시간을 5분, 사용 횟수를 1회로 명시한다. payload의 callbackUrl로 결과를 보내려면 최초 SkillResponse에 version 2.0 및 useCallback true를 반환한다. — [콜백 개발 가이드](https://kakaobusiness.gitbook.io/main/tool/chatbot/skill_guide/ai_chatbot_callback_guide)
- 같은 URL의 검색 결과 스니펫은 오래된 1분 및 별도 AI 챗봇 신청 설명을 보여줬으나, 실제 열린 최신 원문은 5분과 블록의 콜백 설정을 설명한다. 원문을 우선했다. 현재 계정에서의 사용 가능 상태는 관리자센터에서 확인해야 한다. — [콜백 개발 가이드 원문](https://kakaobusiness.gitbook.io/main/tool/chatbot/skill_guide/ai_chatbot_callback_guide)
- 스킬 요청은 HTTP POST JSON으로 오며 스킬 서버는 카카오가 접근할 수 있는 공인 IP 또는 공중망 도메인을 사용해야 한다. 일반 타임아웃 5초는 스킬 서버 구현에서 맞춰야 한다. — [스킬 만들기](https://kakaobusiness.gitbook.io/main/tool/chatbot/skill_guide/make_skill)

### Inferences

- 카카오 → 공개 HTTPS 게이트웨이 → 인증·요청 검증 → 작업 큐 → 로컬 GPU 워커 → 게이트웨이 콜백 구조를 권한다. 로컬 추론 서버 자체를 인터넷에 공개하지 않는다. 로컬 워커는 outbound 연결이나 사설 터널로 작업을 가져오게 한다.
- 게이트웨이는 5초 안에 접수 응답을 반환하며, 콜백은 만료 여유를 두고 완료한다. deadline 초과, GPU 오프라인, OOM, 중복 요청, 생성 중 취소, 콜백 단일 사용, 콜백 결과 불명확 시 중복 전송 방지를 설계한다. 5분은 답변 UX 목표가 아니라 플랫폼 상한이다.
- 영상 생성처럼 수분 이상 소요되는 작업은 접수 단계에서 인증된 웹 상태 페이지 링크를 제공한다. 일반 메시지 API로 임의의 완료 푸시가 가능하다고 가정하지 않는다. 추가 발송 채널은 권한·상품 정책을 따로 확인한다.
- callbackUrl은 URL 자체가 권한 성격을 지니므로 비밀로 취급하고 로그·Amplitude에 넣지 않는다. 검증된 카카오 콜백 목적지 외 임의 URL로 보내지 않아 SSRF를 막는다.
- 카카오를 경유하는 메시지와 클라우드 게이트웨이를 지나는 메시지는 기기 밖으로 이동한다. 이를 완전 로컬·외부 전송 없음이라고 홍보하면 안 된다. 로컬 파일 분석 모드와 채널 대화 모드의 데이터 흐름을 UI에서 구분한다.
- 위 공개 게이트웨이 구조는 사용자가 명시적으로 켠 카카오 채널 대화 모드에만 적용한다. 로컬에서 가져온 과거 대화 원본은 이 큐로 전송하지 않는다. 채널을 새로 연결할 때 그 채널에 입력한 신규 메시지는 Kakao와 relay 서버를 경유한다는 점 및 보존 위치를 고지한다. 개인 프로필을 클라우드에 올리지 않고 로컬 워커 안에서 적용하며, 출력에 과거 대화의 비밀이 섞여 전달되지 않도록 검증한다.

### Gaps

- 실제 봇 설정, 계정 권한, 요청 인증 수단, 쿼터, 발송 형식은 아직 앱을 만들지 않았으므로 검증하지 않았다. 1분이 아니라 5분인 점은 공식 원문에 확인했지만 계정에서 동작 확인이 필요하다.

## 성격 추론과 사적인 대화의 저장은 어떻게 제한할 것인가

### Takeaway

제품은 사람의 본질적 성격을 진단하는 대신, 동의받은 대화에서 관찰한 말투·표현 선호·상황별 반응을 설명하고 당사자가 고쳐 확정하는 페르소나를 만든다. 초기에는 원문 학습·LoRA 없이 프로필과 제한된 예시 검색을 사용해 수정·철회·삭제가 가능한 상태를 유지한다.

### Cited Findings

- 개인정보보호위원회는 2025-08-06 생성형 AI 개발·활용 안내서를 공개했으며, 기성 오픈 모델 미세조정 등 서비스 개발 방식도 대상으로 설명한다. 자체·로컬 모델이라는 배포 형태만으로 개인정보 처리 고려사항이 사라지는 것은 아니다. — [개인정보위 안내서 발표](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000%22&nttId=11410)
- 개인정보 보호법 제15조는 수집·이용의 적법한 근거와 목적 범위 내 이용을 규정하며 정보주체 동의를 그 근거 중 하나로 둔다. 서비스가 다른 사람의 대화를 처리하는 데 업로더가 파일을 보유한다는 사실만을 충분한 근거로 삼지 않아야 한다. — [개인정보 보호법 제15조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029334803)
- 제23조는 건강·정치적 견해·성생활 등의 민감정보 처리를 제한하며 별도 동의 또는 법령 근거의 예외를 둔다. — [제23조](https://www.law.go.kr/lsLinkCommonInfo.do?ancYnChk=&chrClsCd=010202&lsJoLnkSeq=1020398539)
- 제21조는 목적 달성·보유기간 경과 등 불필요해진 개인정보를 원칙적으로 지체 없이 파기하고 복구·재생되지 않도록 조치하도록 규정한다. 별도 법령 보존 예외는 분리 보관한다. — [제21조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335641)
- 제28조의8은 국외 제공·처리위탁·보관을 포함한 이전을 규율하며, 별도 동의나 일정 조건의 계약 이행 관련 고지 등 적법한 근거를 정한다. 해외 GPU, 로그, 스토리지, CDN도 실제 데이터 흐름에 따라 확인 대상이다. — [제28조의8](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034515803)
- OWASP는 외부 문서 등에 섞인 지시가 간접 prompt injection 경로가 되며 RAG·fine-tuning만으로 해결되지 않는다고 설명한다. 외부 콘텐츠 구분, 최소 권한, 코드에서 도구 실행 통제, 공격 시나리오 검증을 권한다. — [OWASP Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)

### Inferences

- 동의 정책은 기본적으로 본인·명시적으로 참여한 사람의 대화만, 승인한 목적과 기간만 다루도록 만든다. 프로필 생성·챗봇 대화·소설/영상 활용·공개·학습을 하나의 포괄 동의로 묶지 않는다. 다른 사람과 주고받은 대화라면 당사자별 데이터 권리와 처리 근거를 검토한다. 이것은 보수적 제품 정책 제안이며 모든 개인 사용에 항상 전원 동의만이 유일한 법적 근거라는 단정이 아니다.
- 관찰 가능한 프로필 필드 예: 말 길이, 존댓말/반말 상황, 유머 표현, 직접적/완곡한 표현, 질문 사용, 명시적으로 드러낸 창작 취향, 피해야 할 표현. 각각 관찰 범위·기간·근거 메시지 내부 ID·충돌 사례·사용자 수정값을 둔다. 모델의 confidence를 검증된 확률처럼 표시하지 않는다.
- '이 사람은 우울증이다', 성적 지향·정치성향·종교 추론, 확정 MBTI, 성격에 기반한 채용·신용 결정은 초기 제품 범위에서 제외한다. 답장 지연을 무관심 또는 성격으로 단정하지 않는다. 대화 상대·상황·기간의 편향을 보이고 자료가 부족하면 보류한다.
- 보고서는 '이 대화에서는 짧은 문장과 농담을 자주 사용했다' 정도로 표현하고 당사자 검토 → 수정 → 저장 단계를 거친다. 원본 발화의 비밀을 그대로 재현하는 것과 말투 유사성을 별개 품질로 평가한다.
- 데이터 수명: 원문 파일 → 정규화 메시지 → 마스킹 데이터 → 임베딩 → 관찰 프로필 → 승인 페르소나 → 생성 대화·작품의 lineage를 내부적으로 추적한다. 삭제·철회는 관련 원문/청크/벡터/요약/프로필/캐시/작업 큐/생성물과 백업 복원 시 재삭제 처리까지 포함한다. 보존 정책은 제품 출시 전에 확정한다.
- 초기에는 원문을 모델 가중치에 학습시키지 않는다. 추후 LoRA를 쓴다면 동의 철회 시 해당 adapter 폐기·재학습 정책을 먼저 정한다. 단순 DB 삭제를 학습 가중치에서의 삭제라고 보고하지 않는다.
- 통합 검색은 tenant/persona 권한 필터를 모델 프롬프트가 아닌 DB 질의와 API 권한 계층에서 강제한다. 검색할 수 없는 다른 사람 데이터가 같은 벡터 인덱스에서 노출되는 회귀 시나리오를 만든다.
- 업로드 텍스트의 '앞의 규칙 무시', 비밀 전송 URL, 시스템 프롬프트 모방은 지시가 아닌 분석 데이터로 처리한다. 입력과 출력 구조 검증, 도구 기본 비활성화, 네트워크 allowlist, 비밀 미제공, 렌더링 escaping을 둔다. 프롬프트 한 줄만으로 해결했다고 보지 않는다.
- Amplitude에는 원문·생성문·실명·전화번호·대화방 이름·성격 프로필·검색어·콜백/초대 토큰을 보내지 않는다. import_started와 import_completed, persona_save_clicked와 persona_saved처럼 클릭/서버 성공을 분리하되 기존 이벤트 카탈로그를 먼저 확인한다. 파일 크기 구간, 입력 형식, 모델 버전, 처리시간 구간, 에러 코드 정도의 비내용 메타데이터만 후보로 둔다.
- 검증: 삭제 후 검색 0건 및 백업 복원 후 비복구, 미동의 데이터 제외, 테넌트 간 검색 차단, 로그/Amplitude payload의 개인정보 금지, 인젝션·대량 업로드·중복 가져오기·형식 실패 후 초안 보존, 관찰에 없는 민감 성향 추정 억제를 확인한다. 일반 개인정보 법률 적용은 개인 취미인지 외부 이용자 대상 서비스인지·지역·보유 목적에 따라 달라지므로 공개 서비스 전 법률 검토 범위를 확정한다.

### Gaps

- 카카오 대화만으로 성격·MBTI를 정확하게 확정할 수 있다는 검증 근거는 확보하지 않았으며 이 보고서는 그러한 정확도를 주장하지 않는다. 관찰형 말투 프로필과 사용자 확인이 제품 권고다.
- 별도 원문 가이드 PDF 전체나 기업별 법률 의견을 검토한 것은 아니다. 제15조 근거 선택, 제3자 수집·제공·위탁, 미성년자·국외이전·정보주체 권리 등 구체 적용은 사업 형태를 정한 뒤 검토해야 한다.
