# Qwen 로컬 모델과 창작 파이프라인

## 최신 공개 Qwen과 어떤 모델을 선택할 것인가

### Takeaway

2026-11-12에 확인한 Qwen 공식 모델 목록과 공식 GitHub를 기준으로, 이 용도의 로컬 범용 모델은 **Qwen3.8 계열**에서 선택한다. 사용자가 후속 답변으로 **16인치 MacBook Pro, M5 Pro, 통합 메모리 48GB**를 확인했다. 이 장비에서 **Qwen3.8-27B 4bit를 품질 후보로 바로 검증**하고 Qwen3.5-9B 4bit를 빠른 응답/개발용 비교군으로 둔다. 4B는 배선 점검용으로 충분하며 주력으로 고집할 이유가 없다. Qwen3.8-27B가 모든 Qwen 제품 중 가장 최근 발표라고 표현하지 말고, “확인 가능한 최신 공개 범용 계열에서 로컬에 적합한 후보”라고 표현한다.

### Cited Findings

- 공식 GitHub는 Qwen3.8-27B 공개를 2026-08-14, Qwen3.8-2.4T-A95B를 2026-08-12로 기록한다. 검색 집계의 다른 날짜보다 공식 News를 따른다. — [Qwen 공식 저장소](https://github.com/QwenLM/Qwen3.8)
- 공식 Hugging Face의 생성일순 목록에서 Qwen3.8-Flash-Next와 27B, 2.4T-A95B를 확인했다. 이후 생성된 이미지 특화 모델 등과 범용 LLM의 세대는 구분한다. Qwen4-27B의 공식 다운로드 모델은 이번 조사에서 확인되지 않았다. 검색에서 발견한 동명 커뮤니티 예고·변환 프로젝트는 공식 출시 근거로 사용하지 않는다. — [Qwen 공식 모델 생성일순 목록](https://huggingface.co/models?author=Qwen&sort=created), [공식 컬렉션](https://huggingface.co/Qwen/collections)
- Qwen3.8-27B는 Apache-2.0, 27B 언어모델과 vision encoder를 갖고 이미지·영상 입력을 이해하여 텍스트를 생성한다. 기본 262,144 문맥과 확장 문맥은 모델 사양이며 로컬 장비에서 그 길이로 서비스할 수 있다는 보장은 아니다. thinking은 기본 켜짐이고 요청별로 끌 수 있다. 공식 카드가 Transformers, vLLM, SGLang 등의 실행 예제를 제공한다. — [공식 모델 카드](https://huggingface.co/Qwen/Qwen3.8-27B)
- 작은 공식 대안 Qwen3.5-4B와 9B도 Apache-2.0이며 이미지·텍스트 입력 모델이다. — [4B 카드](https://huggingface.co/Qwen/Qwen3.5-4B), [9B 카드](https://huggingface.co/Qwen/Qwen3.5-9B)
- Qwen3.8-Flash-Next는 125B 본체/6B 활성에 51B n-gram embedding과 4B MTP가 추가된다. Apache가 아닌 qwen-community-1.0을 사용하므로 “Qwen은 전부 Apache”라고 판단하면 안 된다. — [공식 Flash Next 카드](https://huggingface.co/Qwen/Qwen3.8-Flash-Next), [해당 모델 LICENSE](https://huggingface.co/Qwen/Qwen3.8-Flash-Next/blob/main/LICENSE)

### Inferences

- 27B를 최신 계열의 품질 비교 기준으로 삼고, 4B/9B와 한국어 고정 평가를 비교해서 실제 운용 모델을 정한다. 최신성 자체보다 응답 지연, 문체 유지, 운영 가능 메모리가 선택 기준이다.
- 처음에는 사용자가 가진 장비로 4B/9B를 실험하고 장비 구매를 미룬다. 모델 버전·리비전·양자화 방식·chat template·런타임 버전을 묶어 고정하고 업그레이드 때 동일 평가를 재실행한다.
- MoE의 활성 파라미터 수를 전체 모델 메모리로 오해하면 안 된다. 활성 수는 연산 경로 설명이고, 전체 가중치를 보관하거나 offload할 메모리는 별도로 필요하다. Flash Next/2.4T는 이 개인용 MVP의 기본 선택에서 제외한다.

### Gaps

- Qwen 공식 웹 블로그는 본문 추출이 되지 않았고 Qwen4 공식 로컬 가중치를 확인하지 못했다. 따라서 Qwen4 전체 제품이 절대 발표되지 않았다는 단정은 하지 않는다.
- 한국어 소설·카카오톡 문체 모방 품질이나 사용자 장비 성능은 실행하지 않았다. 공식 코딩·추론 점수를 한국어 창작 품질의 증거로 대체하지 않는다.

## 로컬 하드웨어와 추론 런타임은 어떻게 잡을 것인가

### Takeaway

초기 실행은 단일 사용자·8K 정도의 제한된 입력 문맥·짧은 출력으로 시작하고, 지연과 최대 메모리를 측정한다. 아래 용량은 **예산 설계용 추정이며 구매 보장이나 실측 벤치마크가 아니다**.

### Cited Findings

- llama.cpp는 Apple Silicon Metal, NVIDIA CUDA, CPU/GPU 혼합 추론과 여러 비트 양자화를 지원하고 OpenAI 호환 서버를 제공한다. — [llama.cpp 공식 문서](https://github.com/ggml-org/llama.cpp)
- vLLM은 온라인 서버 인터페이스를 제공하며, 선택한 Qwen3.8 모델 카드는 vLLM과 SGLang 실행을 문서화한다. — [vLLM 온라인 서빙](https://docs.vllm.ai/en/latest/serving/online_serving/), [Qwen3.8-27B 카드](https://huggingface.co/Qwen/Qwen3.8-27B)
- MLX-VLM의 개발 프로젝트 문서가 `mlx-community/Qwen3.8-27B-4bit`의 생성과 서버 실행 예제를 명시한다. 해당 변환 모델 카드도 존재한다. 따라서 이 Mac에서는 **MLX-VLM + Qwen3.8-27B 4bit**가 구체적인 검증 후보이며, MLX-LM의 지원을 막연히 동일시할 필요는 없다. 원본 Qwen과 MLX Community 변환의 출처·revision을 각각 기록한다. — [MLX-VLM 개발 프로젝트](https://github.com/Neywa-Labs/mlx-vlm), [MLX 변환 카드](https://huggingface.co/mlx-community/Qwen3.8-27B-4bit)
- Ollama 공식 라이브러리도 `qwen3.8:27b`와 `qwen3.8:27b-mlx`를 제공하며 다운로드 크기를 18GB로 표시한다. 다운로드 용량은 실행 최대 메모리와 다르다. 편한 설치/API 운영이 우선이면 Ollama로 먼저 실행하고 MLX-VLM을 같은 프롬프트로 비교할 수 있다. — [Ollama 공식 Qwen3.8 라이브러리](https://ollama.com/library/qwen3.8)

### Inferences

| 출발 장비                                 | 첫 비교 후보                                                    | 계획상 제약                                                    |
| ----------------------------------------- | --------------------------------------------------------------- | -------------------------------------------------------------- |
| GPU VRAM 8–12GB 또는 Mac 통합 메모리 16GB | Qwen3.5-4B Q4, 여유가 확인되면 9B Q4                            | OS·앱 메모리 별도, 영상 생성 제외, 동시 생성 1개               |
| GPU VRAM 16GB 또는 Mac 24–32GB            | Qwen3.5-9B Q4                                                   | 한국어 품질 기준선, 긴 원문은 청크 처리                        |
| GPU VRAM 24–32GB 또는 Mac 48–64GB         | Qwen3.8-27B Q4 검증                                             | 짧은 문맥부터; 24GB는 양자화·비전 입력·동시성에 따라 부족 가능 |
| 다중 사용자/영상 동시 운영                | 텍스트 추론과 영상 워커를 별도 GPU 또는 별도 실행 시간으로 분리 | 실제 동시성 부하시험 이후 증설                                 |

- 27B 언어 가중치를 정확히 4bit로만 담는 산술 하한은 `27 × 10^9 × 4 / 8 = 13.5GB`(약 12.6GiB)다. 실제 파일·VRAM은 양자화 scale/metadata, 비양자화 tensor, vision encoder, KV cache/상태, 임시 연산 공간, 런타임 때문에 더 크다. “27B Q4니까 14GB면 운영 가능”이라는 계산은 잘못이다.
- Mac의 통합 메모리는 OS와 앱이 공유하며, VRAM과 일대일 비교하거나 메모리 용량으로 속도를 추정하면 안 된다.
- Mac/혼합 하드웨어 개발에는 llama.cpp 계열의 로컬 API를 우선 비교한다. NVIDIA 서버에서 동시 요청이 생기면 vLLM/SGLang을 비교한다. 동일 OpenAI 호환 API여도 thinking·structured output·multimodal 처리 차이는 adapter와 계약 검사로 다룬다.
- **사용자 장비에 맞춘 최종 우선순위:** MLX-VLM의 검증된 Qwen3.8-27B 4bit 경로를 주력 후보로, Ollama를 설치 편의 대안으로 비교한다. 둘을 동시에 상주시켜 메모리를 쓰지 않는다. 초기 문맥은 8K, 동시 생성 1개, 출력은 채팅 512–1024토큰/소설 장면별 2K–4K 상한을 제안한다. 이는 운영 출발 설정이며 측정 후 16K/32K를 단계적으로 시험한다. OS·IDE·브라우저에 10–12GB 이상 여유를 남기는 것을 예산 목표로 잡고 memory pressure/swap 증가 시 문맥·배치를 줄인다. 강제로 OS GPU 메모리 한도를 풀어 억지로 로드하는 설정은 기본 계획에서 제외한다.
- 48GB 통합 메모리는 NVIDIA 48GB VRAM과 같은 성능·실행 호환성을 뜻하지 않는다. 이 Mac은 텍스트 MVP에 먼저 사용하고 GPU를 새로 구매하지 않는다. CUDA를 전제로 한 Wan 공식 명령을 그대로 macOS에 적용할 수 있다고 말하지 않는다. Mac에서 영상 생성은 Metal/MPS/MLX 지원 경로와 실제 품질·시간을 별도 검증해야 하며, 첫 서비스 계획에서는 **로컬 텍스트 + 선택적 클라우드 영상 워커**를 권한다. 사용자 원문·프로필을 영상 클라우드로 자동 전달하지 않는다.
- 노트북의 덮개 닫기·절전·전원·네트워크 변경·재부팅으로 요청이 중단될 수 있어 공개 24시간 서비스 서버로 간주하지 않는다. 장시간 부하에서 발열과 응답 편차를 측정하고, 서비스용 워커는 heartbeat/lease/retry로 중단을 처리한다.
- 상담형 캐릭터 대화는 non-thinking 설정을 품질·지연 비교의 출발점으로, 소설 구상·대본 계획은 별도 모델 파라미터 프로파일로 둔다. 생각 토큰을 사용자 화면이나 일반 로그에 자동 노출하지 않는다.
- 측정 항목: 첫 토큰 지연 p50/p95, 생성 속도, 실제 최대 메모리, 입력 길이별 지연, 동시 1/2/4 요청의 대기·실패율, GPU OOM 뒤 복구, 장시간 발열·throttling. 수치는 목표·측정치·추정을 구분한다.

### Gaps

- 사용자 장비는 M5 Pro 48GB로 확인했으나 GPU 코어 수·동시 접속·예산과 실제 모델별 tokens/s는 없다. 동일 메모리의 다른 M 시리즈 벤치마크를 이 기기의 성능으로 대체하지 않는다. MLX/Ollama의 문서상 호환은 확인했으며 실제 실행은 하지 않았다.

## 영상 소설 페르소나를 어떤 순서로 구현할 것인가

### Takeaway

Qwen은 대화·소설·영상 기획 및 분석을 담당하고, 영상의 실제 픽셀 생성은 별도 비디오 생성 모델에 맡긴다. 사용자가 영상은 **생성·편집 모두**, cloud delivery는 **웹서비스 클라우드 배포와 영상 CDN 전달**이라고 확인했다. 개인 개발·소규모 비공개 파일럿 가정으로, 최초 MVP는 동의된 대화 내보내기 파일 → 편집 가능한 말투 프로필 → 웹 챗봇 → 소설 → 짧은 영상 순서로 확장한다.

### Cited Findings

- Wan2.2-TI2V-5B는 텍스트·이미지 기반 720p 24fps 영상 생성을 지원한다. 공식 예제는 offload, dtype 변환, T5 CPU 배치 옵션을 사용하면 최소 24GB VRAM GPU에서 실행할 수 있다고 설명한다. 이 수치는 실시간 생성 보장이나 Qwen 동시 상주 메모리가 아니다. — [Wan2.2 공식 저장소](https://github.com/Wan-Video/Wan2.2)
- 로컬 검색용 Qwen3-Embedding-0.6B는 Apache-2.0이며 100개 이상 언어, 최대 32K 입력, 최대 1024차원 벡터를 지원한다. — [공식 embedding 카드](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)
- LoRA는 기반 가중치를 동결하고 작은 업데이트 행렬을 학습하는 방식이며, adapter를 기반 모델에 병합하는 방법도 있다. — [Hugging Face PEFT LoRA 문서](https://huggingface.co/docs/peft/main/en/conceptual_guides/lora)

### Inferences

- **챗봇:** persona card(존댓말/반말, 문장 길이, 감탄사·이모지, 농담 강도, 대화 방식, 선호, 피해야 할 행동)와 사용자 편집/버전을 먼저 만든다. 자유 텍스트 프로필만 두지 말고 근거 메시지 참조, 관찰 기간, 관찰량, 불확실성, 관계별 맥락을 분리한다. personality는 심리 진단·고정 정체성 대신 관찰된 대화 성향으로 표현한다.
- 카카오톡 원문은 명령이 아니라 분석 대상 데이터다. 원문 속 “지침 무시” 등을 시스템 지시로 승격하지 않는다. 프로필 생성과 실제 대화의 tool 권한을 분리한다.
- **기억:** 시스템 프롬프트는 캐릭터 행동 규칙, 최근 대화는 짧은 세션 기억, RAG는 필요한 사실·이야기 설정 검색을 담당한다. 전 대화 원문을 매번 통째로 입력하지 않는다. 사람/작품/tenant별 검색 공간과 접근 제어를 분리한다. 소규모면 먼저 명시적 프로필+요약 저장으로 시작하고 검색 필요가 확인되면 embedding/RAG를 추가한다.
- **소설:** 세계관/인물 설정집 → 전체 시놉시스 → 회차별 목표 → 장면 초안 → 사실·타임라인·시점·문체 점검 → 사용자 편집 → 확정 설정 반영. 미승인 초안이 확정 설정을 덮어쓰지 않게 한다. 작품별 원문, 설정 버전, 편집 이력을 관리하고 장편을 단일 요청으로 만들지 않는다.
- **영상:** 사용자 브리프 → Qwen 대본/shot list JSON → 승인된 캐릭터 reference image → shot별 Wan 생성 → 음성/음악 권리 확인 → 자막/FFmpeg 편집 → 미리보기 → 선택적 게시. 첫 영상은 5–10초 단일 shot 또는 짧은 클립 조립으로 제한하고 캐릭터 일관성·한글 자막·립싱크는 각각 다른 품질 문제로 평가한다. Wan2.2는 확인된 로컬 출발 후보이며 최신 영상 제품 전체를 대표한다고 주장하지 않는다.
- **Mac에서 먼저 완성할 편집 경로:** 보유하거나 사용 권리가 있는 소스 영상을 가져와 구간 자르기·장면 순서·자막·오디오·해상도/export 설정을 사용자 편집 가능한 타임라인 JSON으로 저장하고 FFmpeg worker가 렌더한다. 원본은 불변으로 보존하고 재렌더는 새 artifact를 만든다. 실패해도 타임라인 초안·생성된 shot을 잃지 않고 실패 구간만 재시도한다. Qwen이 임의 셸 명령을 만들어 실행하게 하지 말고 허용된 편집 연산을 JSON schema로 받고 서버가 검증해 실행한다. 이렇게 하면 GPU 영상 모델이 늦어져도 기획→편집→내보내기 흐름을 먼저 검증할 수 있다.
- **LoRA 시점:** 프롬프트와 검색으로 해결되지 않는 반복적인 문체 실패를 평가셋으로 확인한 뒤 검토한다. 개인 대화 원문을 바로 학습하지 않는다. 삭제/철회가 예상되는 정보는 수정·삭제 가능한 저장소에서 관리하는 편이 운영하기 쉽다. 학습 시 권리 확인, train/eval 대화 분리, 개인정보 노출·문장 암기 검사를 별도로 수행한다.
- **평가셋 초안:** 한국어 대화 30–50 시나리오(존대 전환·갈등·모르는 정보·장기 대화·원문 복제 유도), 짧은 소설 10편(설정/시점/중복), 영상 10 brief(인물 유지/시간적 일관성/대본 준수). 이는 계획상의 표본이며 통계적 품질 보장으로 표현하지 않는다. 사람의 blind 비교와 수정률, 근거 없는 프로필 단정률, 개인정보 재현률을 확인한다.

### Gaps

- 실제 한국어 생성, persona drift, 영상 생성 시간/성공률을 측정하지 않았다. 영상 생성·편집 범위는 확인했으며 목표 길이/해상도는 아직 미정이어서 짧은 720p 클립을 파일럿 가정으로 둔다.
- 음성 합성 모델, 음원 라이선스, 실존 인물의 초상·목소리 동의는 별도 선택/검증 대상이다. 이번 MVP는 실존인물의 얼굴·목소리 복제를 필수 기능으로 두지 않는다.
