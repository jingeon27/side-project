## develop 재감사와 처리 범위

2026-10-31에 최신 `origin/develop`의 `aa293438`을 기준으로 다시 감사했다. PR 변경분이 아니라 세 서비스·공통 패키지·배포 구성의 자동 검사와 인증·권한·업로드·폼·네이티브 탐색의 핵심 경로를 검토했다. 전체 코드의 모든 분기를 검증한 것은 아니다. 당시 `yarn check`, Game Mate 단위 검사와 포맷 검사를 통과했고 기존 테스트 2,352개가 성공했다. 같은 커밋의 Services·Blog·Static analysis·Terraform·Commits CI도 성공했다.

이번 후속 변경은 **피식 그룹 사진의 부분 실패 재시도**를 수정한다. 의존성 업데이트, 커버리지 수집, Knip 후보 삭제, 전체 날짜 처리 전환과 운영·실기기 검증은 완료로 바꾸지 않고 아래의 소유 영역·완료 기준으로 관리한다. 기존 감사 점수를 새 변경의 자동 측정 결과처럼 사용하지 않는다.

### 해결: 피식 그룹 사진의 부분 실패 재시도

- 그룹 생성·수정에서 두 전송 중 하나가 실패하면 `Promise.all`이 다른 전송보다 먼저 끝나 제출 잠금이 풀렸고, 성공한 사진의 완료 ID도 사라져 재시도에서 두 사진을 모두 다시 올렸다. 수정 전 두 화면의 중복 전송과 수정 화면의 조기 잠금 해제를 세 UI 회귀 검사로 재현했다.
- 두 전송이 모두 끝난 뒤 실패를 알리고, 완료한 사진은 RHF 폼 초안에 파일·그룹·ID·재사용 기한으로 보관한다. 실패한 사진만 다시 전송하며 최종 프로필 저장만 실패하면 사진 전송 없이 저장을 재시도한다. 입력·미리보기와 단일 하단 저장 행동은 유지한다.
- 재사용은 같은 그룹·같은 사진 칸·같은 `File` 객체에 한정한다. API 계약을 늘리지 않고 발급 응답의 `expiresAt`까지만 보수적으로 재사용하며, 이 기한이 지나거나 파일·그룹이 달라지면 새 티켓으로 올린다. 서버의 권한·완료 자산 검증과 실제 보관 기한은 바꾸지 않는다.
- 페이지를 떠난 뒤 완료 응답이 와도 초안이나 그룹 프로필을 저장하지 않는다. 임의 S3 객체 삭제·버킷 생성·S3 대역 서버 도입 없이 기존 테스트 전용 객체 경로와 정리 정책을 유지한다. 검증 결과는 피식 구현 기록과 이 변경의 PR에 남긴다.

### 화면 조립과 입력 검증

- `BoardsPage`는 공통 셸과 게시판 선택만 맡고, 피드백·전투 모집·코칭·친추판매·자유게시판이 각각 작성 행동, 자기 필터와 카드 구성을 조립한다. 동일한 목록 조회·서버 snapshot·페이지 추가·오류 경계만 `BoardPostList`로 공유한다. 게시판별 조건을 모두 받는 새 범용 페이지 템플릿은 만들지 않았다.
- `PostCard`는 컨테이너로 줄이고 메타 정보, 제목·본문, 작성자·활동 정보를 책임별로 나눴다. 게시판 5종뿐 아니라 홈·검색·공개 프로필·내 작성글도 직접 조립하도록 바꿨다. 이 네 목록에서 실제로 같은 도메인 요약만 공유한다. 카드의 작성자 링크·인증·시간·조회·답변 정보와 탐색 경로는 유지한다.
- 글쓰기·게시판 서버 경계, 공개 문서 접근 판정과 앱 경로 해석기의 같은 입력 계약은 bridge의 `BoardQuerySchema`로 통일했다. 게시판·게임·전투 유형·코칭 역할·피드백 상태와 조합 제약을 검증하고, 이후에는 검증된 값을 사용한다. 잘못된 입력은 분류 조회 전에 거부한다. 검색은 같은 경로 해석기를 사용한다.
- 실제 브라우저 회귀에서 잘못된 필터 URL이 스트리밍 뒤 200으로 응답하는 경로를 확인했다. Proxy가 공통 경로 검증으로 문서·RSC 요청을 조회 전에 404/noindex/no-store로 거부하도록 했다. 유효한 입력의 기본 게임, 글쓰기 미선택 분류와 상위 게시판, URL 필터·서버 본문은 보존한다.
- 루트 TypeScript 스킬에 화면별 조립·역할별 분해·검증된 값 재사용 원칙을 기록했다. 다른 서비스의 단순 locale/ID 가드, 서로 다른 권한 검사, 클라이언트의 필드별 필터 fallback은 같은 문제로 취급하지 않고 유지했다. 코드 행 수나 CPU 성능의 향상으로 주장하지 않는다.

### Provider·미사용 코드·날짜

- Game Mate의 공개 Provider 진입점을 `ServiceProviders` 하나로 합쳤다. 서버 전용 `serviceContext`는 유지하며 Theme/Language의 기존 `useSyncExternalStore` 서버 snapshot도 그대로 사용한다. 인스턴스별 QueryClient, 부모 재렌더의 캐시 유지, 사용자별 Overlay 수명을 보존한다. 별도 서버 데이터를 전역 외부 store에 복제하지 않는다.
- Knip 기준선은 **127→4개**다. 참조 없는 파일·배럴·export/type을 제거하고, 실제 CLI가 읽는 모바일 Playwright 설정·teardown은 진입점으로 등록했다. 새 ignore나 기준선 항목을 추가하지 않았다. 남은 네 항목은 GF API의 기존 `security.ts` 호환 export 3개와 toolkit의 공개 `IPushStore` 계약이며, 현재 전체 보고서와 기준선 검사가 일치한다.
- 제품·운영 코드의 날짜 생성·계산·비교를 기존 catalog의 dayjs로 옮겼다. 인증·업로드 TTL은 밀리초 경과 시간을, KST 월 범위와 블로그 날짜 전용 값은 기존 시간대 의미를 유지한다. 외부 Date 반환은 `.toDate()`, Intl/RSS 직렬화는 기존 표준 포맷을 사용한다.
- 예외는 명시적으로 남긴다. 외부 커서·GraphQL DateTime·datetime-local의 기존 거부/보정/DST 해석을 바꾸지 않도록 native 파싱 경계 4곳은 보존한다. 설치 없이 실행하는 배포용 `sentry-release.ts`는 무의존 CLI이므로 native Date를 유지한다. 단조 시계, 생성 코드, 기존 테스트 fixture는 일괄 치환하지 않았다. 날짜 mocking은 `Date.now`만 spy하는 대신 Date만 가짜 시계로 제어해 재시도 backoff도 검증한다.

## 2026-10-31 CI 실패·게시 재시도·SSR 집계 수정

PR #178 병합 뒤 `origin/develop`의 `0deb9209`를 기준으로 확인한 실패 경로를 수정한다. 기존 감사 점수는 주관적인 구조·운영 준비도 평가이며 업계 등급, 완성률이나 장애 확률을 뜻하지 않는다.

- 공용 인스턴스 CI는 호스트에서 smoke 스크립트를 실행하기 전에 고정 Yarn과 의존성을 설치한다. Docker 내부 설치만으로 호스트의 dayjs import가 해결된다고 가정하지 않는다.
- 피식 e2e의 미사용 import를 제거하고 프로젝트 lint가 Web·Mobile 자체 lint까지 위임하도록 연결했다. 루트 check의 성공과 개별 CI lint 실패가 갈리는 검사 누락을 막는다.
- Game Mate의 잘못된 게시판 문맥은 일반 텍스트 응답 대신 요청별 Provider·Suspense가 없는 정적 오류 라우트로 rewrite한다. 기존 404 화면과 실제 HTTP 404, noindex, private/no-store를 함께 유지한다. 동적 레이아웃 안에서 notFound를 호출하는 것만으로 스트리밍 200이 해결되지는 않는다.
- 피식 게시 요청에 사용자별 UUID 멱등 키를 추가했다. 같은 키의 링크 게시 재전송·동시 요청은 첫 게시물과 성공 이벤트만 남긴다. 완료된 파일은 같은 File 초안에서 재사용하며 파일을 바꾸면 새 업로드를 사용한다. 저장 성공 뒤 목록 재조회 실패는 작성 실패로 취급하지 않는다. nullable 열·복합 unique를 새 마이그레이션으로 추가하며 기존 데이터와 키 없는 클라이언트는 보존한다.
- Game Mate의 쿠키 없는 공개 상세 캐시는 유지한다. 차단 관계가 있는 SSR만 비공개 내부 경로에서 전체 활성 답변·도움됨 집계를 받아 합친다. 첫 페이지 길이로 총계를 추측하지 않으며 실패·잘못된 응답은 공개 집계로 대체하지 않는다. 내부 경로는 기존 edge 차단 대상이고 사용자별 결과는 no-store다.

관련 회귀 검사는 실제 PostgreSQL·S3, 생성 GraphQL 문서, production 브라우저와 JavaScript 없는 HTML을 사용한다. 실행 결과와 새 PR의 전체 CI 판정은 PR 본문에 기록한다. 개발·운영 DB와 실행 중인 개발 서버는 변경하지 않으며, 공용 Docker smoke는 로컬 Docker 검증과 GitHub CI 결과를 구분한다.

### 해결: 기존 CI의 하단 폼 배치 실패

후속 작업 중 확인한 기존 HEAD의 [Services 실행](https://github.com/jingeon27/side-project/actions/runs/41103104201)은 GF Web E2E 169개 통과·1개 실패로 끝났다. 실패는 `e2e/page-form-actions.spec.ts:3`의 글쓰기 하단 배치 검사이며 경계 차이 1.28125px가 허용값 1px를 넘었다. 이전 로컬 전체 통과와 구분하고 원인이나 간헐성을 단정하지 않는다. API 통합·PC 브라우저·공유 컨테이너/복원 검사는 같은 실행에서 통과했다. 이번 예약 수정이 이 배치 문제를 해결한 것으로 기록하지 않는다.

- 원인과 수정: CI trace의 실패 화면은 320×420이며 인증 안내가 폼 스크롤 영역 밖에 있었다. 이 고정 안내가 글꼴에 따른 줄바꿈과 짧은 화면에서 공간을 차지해 제출 영역을 밀어냈다. 안내를 `CreatePostForm`의 스크롤 본문 안으로 옮겨 안내·필드만 스크롤하고 제출 영역은 남도록 했다. 공통 FormActions나 임의 좌표 보정은 바꾸지 않았다.
- 검증: 원래 검사는 macOS에서 3회 통과했지만 320×360과 글자를 키운 320×420의 새 회귀는 수정 전 모두 실패했다. 수정 후 이 두 회귀와 기존 글쓰기·프로필 폼 검사를 5회씩 실행해 20개 통과했다. 인증 신청 버튼 접근·안내 스크롤·제목 초안 보존·가로 넘침도 검사하며 기존 1px 단언과 제한 시간은 완화하지 않았다.
- 소유: GF Web. 새 HEAD의 CI 결과는 [PR #176의 최신 검사](https://github.com/jingeon27/side-project/pull/176/checks)에서 확인하며, 이 로컬 결과를 CI 통과로 대신하지 않는다.

### 의존성 재검토의 시작점

최초 PR 브랜치 감사에서 기록한 보안 권고의 시작점은 다음 세 가지다. 현재 권고 전체나 최신 버전 상태를 뜻하지 않는다. 설치된 패키지가 있다는 사실만으로 운영 악용이 확인된 것은 아니며, 해결 여부는 작업할 때 registry와 공식 권고를 다시 확인한다.

- [node-forge / High](https://github.com/advisories/GHSA-86w9-cpqp-85rv): Expo CLI 경유. 서버 런타임의 RSA 검증 경로로 단정하지 않는다.
- [deepmerge / Low](https://github.com/advisories/GHSA-gcqx-w48m-w2h4): Expo 설정 경유.
- [Quill / Low](https://github.com/advisories/GHSA-v3m3-f69x-jf25): HTML export 관련. 현재 앱은 검증한 Delta를 저장·표시하며 해당 export를 쓰지 않는다.

`aa293438`의 전체 lockfile을 2026-10-31에 재검사한 결과는 **권고 16건(High 6, Moderate 5, Low 5)**이다. 사용 중단 경고 5건은 별도다. `node-forge` 12건, `deepmerge`·`glob`·`minimatch`·`quill` 각 1건이며 대부분 Expo 또는 개발·빌드 도구의 전이 의존성이다. 이 수치를 운영에서 악용 가능한 취약점 개수로 해석하지 않는다. 현재 CI 성공도 이 권고의 해결이나 위험 승인을 뜻하지 않는다.

다음 의존성 작업에서는 보고서를 CI artifact로 보존하고 각 권고에 도입 경로·사용 기능의 도달 가능성·수정 버전/호환성·완화책·재검토일을 연결한다. 검토되지 않은 새 High/Critical과 기한 지난 예외를 차단하는 기준을 정한다. Yarn 최소 배포 기간 게이트, Expo 호환 버전과 의도적으로 꺼 둔 자동 업데이트 정책은 유지하며, 모든 권고를 `resolutions`로 한꺼번에 덮어쓰거나 고칠 수 없는 경고를 출력 없이 숨기지 않는다.

```sh
yarn npm audit --all --recursive --json
yarn knip:report --reporter json
yarn knip
```

앞의 두 명령은 기존 경고를 포함하면 비정상 종료할 수 있다. 이를 출력 없이 성공으로 바꾸거나 테스트 실패와 혼동하지 않는다. 자격 증명·환경변수 값·서명된 업로드 URL을 보고서에 남기지 않는다.
