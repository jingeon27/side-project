### 해결: 기존 CI의 하단 폼 배치 실패

후속 작업 중 확인한 기존 HEAD의 [Services 실행](https://github.com/jingeon27/side-project/actions/runs/41103104201)은 GF Web E2E 169개 통과·1개 실패로 끝났다. 실패는 `e2e/page-form-actions.spec.ts:3`의 글쓰기 하단 배치 검사이며 경계 차이 1.28125px가 허용값 1px를 넘었다. 이전 로컬 전체 통과와 구분하고 원인이나 간헐성을 단정하지 않는다. API 통합·PC 브라우저·공유 컨테이너/복원 검사는 같은 실행에서 통과했다. 이번 예약 수정이 이 배치 문제를 해결한 것으로 기록하지 않는다.

- 원인과 수정: CI trace의 실패 화면은 320×420이며 인증 안내가 폼 스크롤 영역 밖에 있었다. 이 고정 안내가 글꼴에 따른 줄바꿈과 짧은 화면에서 공간을 차지해 제출 영역을 밀어냈다. 안내를 `CreatePostForm`의 스크롤 본문 안으로 옮겨 안내·필드만 스크롤하고 제출 영역은 남도록 했다. 공통 FormActions나 임의 좌표 보정은 바꾸지 않았다.
- 검증: 원래 검사는 macOS에서 3회 통과했지만 320×360과 글자를 키운 320×420의 새 회귀는 수정 전 모두 실패했다. 수정 후 이 두 회귀와 기존 글쓰기·프로필 폼 검사를 5회씩 실행해 20개 통과했다. 인증 신청 버튼 접근·안내 스크롤·제목 초안 보존·가로 넘침도 검사하며 기존 1px 단언과 제한 시간은 완화하지 않았다.
- 소유: GF Web. 새 HEAD의 CI 결과는 [PR #176의 최신 검사](https://github.com/jingeon27/side-project/pull/176/checks)에서 확인하며, 이 로컬 결과를 CI 통과로 대신하지 않는다.

### 의존성 재검토의 시작점

감사 기준 lockfile에서 확인한 보안 권고는 다음 세 가지다. 설치된 패키지가 있다는 사실만으로 운영 악용이 확인된 것은 아니다. 해결 여부는 작업할 때 registry와 공식 권고를 다시 확인한다.

- [node-forge / High](https://github.com/advisories/GHSA-86w9-cpqp-85rv): Expo CLI 경유. 서버 런타임의 RSA 검증 경로로 단정하지 않는다.
- [deepmerge / Low](https://github.com/advisories/GHSA-gcqx-w48m-w2h4): Expo 설정 경유.
- [Quill / Low](https://github.com/advisories/GHSA-v3m3-f69x-jf25): HTML export 관련. 현재 앱은 검증한 Delta를 저장·표시하며 해당 export를 쓰지 않는다.

```sh
yarn npm audit --all --recursive --json
yarn knip:report --reporter json
yarn knip
```

앞의 두 명령은 기존 경고를 포함하면 비정상 종료할 수 있다. 이를 출력 없이 성공으로 바꾸거나 테스트 실패와 혼동하지 않는다. 자격 증명·환경변수 값·서명된 업로드 URL을 보고서에 남기지 않는다.
