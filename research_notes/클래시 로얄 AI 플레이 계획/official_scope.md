# 클래시 로얄 공식 연동 범위와 실행 선택

기준일 2026년 11월 12일. 이번 조사는 계획 수립용이다. 계정 로그인, API 키 생성, 실제 게임 조작, 프로그램 설치는 하지 않았다.

## 공식 API로 게임을 플레이할 수 있는가

### Takeaway

공식 API는 게임 데이터를 활용하는 서비스의 출발점이며, 실제 경기의 화면 상태를 읽고 카드를 배치하는 게임 제어 인터페이스로 설계하면 안 된다. 프로필·덱·최근 전적은 보조 정보로, 경기 중 카드 선택·배치 좌표·시점은 별도의 관측과 제어 문제로 분리한다. 다만 이번 익명 조사에서는 공식 Swagger의 최신 필드 목록을 확보하지 못했으므로 정확한 응답 필드·보존 경기 수·리플레이 내보내기를 확정해서 쓰면 안 된다.

### Cited Findings

- 공식 개발자 포털은 안전한 게임 데이터 접근을 통해 서비스를 만들도록 소개한다. — [Clash Royale API 포털](https://developer.clashroyale.com/)
- 공식 Getting Started의 실제 배포된 프런트엔드 본문은 API 키에 허용 IP를 지정하며, 요청마다 JWT를 보내고, IP 및 rate limit 제약이 있다고 설명한다. JSON/UTF-8 응답과 HTTP 오류 상태를 사용한다. — [Getting Started](https://developer.clashroyale.com/#/getting-started), [현재 공개 배포 번들](https://developer.clashroyale.com/bundle.f3a36c.js)
- 현재 공개 문서 셸은 로그인 응답에서 제공하는 Swagger URL과 임시 API 토큰을 사용해 상세 문서를 로드한다. 익명 웹 도구는 상세 endpoint/response schema 본문을 읽지 못했다. 공개 HTML과 JS만 읽었으며 인증을 우회하거나 토큰을 구하지 않았다. — [공식 Swagger 문서 셸](https://developer.clashroyale.com/api-docs/index.html)

### Inferences

- 문서에서 사용할 표현: '공식 API는 프로필·덱·전적 같은 보조 데이터 조회에 쓰고, 실시간 보드 관측이나 카드 투입 API는 계획의 전제로 두지 않는다.' 'battlelog에서 모든 카드의 좌표·투입 타임라인을 바로 받는다'는 설명은 하지 않는다.
- 실제 구현 0단계에서 사용자 개발자 계정으로 공식 문서를 열어 필요한 read endpoint와 response schema를 검증·고정한다. 계정 비밀번호를 앱에 저장하지 않고 API 키는 서버 또는 로컬 비밀 저장소에서 사용한다. IP 변경·요청 제한·갱신 실패·오래된 데이터 처리를 둔다.
- 데이터 구조는 '전적 요약', '사용자가 제공한 녹화 영상', '영상에서 추정한 경기 상태', '에이전트가 선택한 행동'을 분리한다. 수집 출처와 추정 여부를 함께 보관한다.
- 화면 관측의 입력은 사용자가 제공한 경기 또는 리플레이 녹화 파일로 시작한다. 카드 손패·엘릭서·타이머·타워 체력·유닛 위치는 영상 인식의 검증 대상이며 공식 API가 실시간 제공한다고 가정하지 않는다.
- 리플레이에서만 보이는 상대 정보나 미래 이벤트를 학습 입력에 넣으면 실제 경기 성능이 과대평가된다. 플레이어 시점에서 그 시각에 관측 가능한 정보만 모델 입력으로 사용하고, 상대 손패·엘릭서는 관측 사실과 추정치를 구분한다.

### Gaps

- 공식 포털 상세 문서가 로그인 후 Swagger로 제공되어 최신 endpoint 이름·response field를 검증하지 못했다. 통상 알려진 /players/{tag}/battlelog 등의 경로를 이번에 공식 검증 완료한 계약으로 보고하지 말 것.
- 공식 replay 파일/행동 스트림 export API를 찾지 못했다. '기능이 절대 없다'고 확정할 근거는 아니지만 이 기능에 의존하는 계획은 세우지 않는다. 게임 안 재생, 전적 JSON, 영상 녹화 파일, 카드 행동 시계열은 서로 다르다.
- 최신 리플레이 보존 경기 수·시간·업데이트 후 소멸 조건은 공식 근거를 확보하지 못했다. 숫자를 넣지 말 것.

## 실제 클라이언트 자동 조작은 허용되는가

### Takeaway

Supercell은 봇과 gameplay automation scripts를 금지 대상으로 명시한다. 따라서 AI가 실게임 클라이언트에서 자동으로 플레이하는 방식은 계정 정지 위험이 있는 별도 선택이며, 친구와의 친선전·연습 모드·개인 계정이라는 이유로 허용되는 예외라고 설명할 수 없다.

### Cited Findings

- Safe and Fair Play Policy는 금지된 외부 소프트웨어의 예에 봇, 게임플레이 자동화 서비스·스크립트를 포함한다. 금지된 외부 프로그램으로 부당한 이점을 얻으려 하면 해당 계정 영구정지라고 명시하고 이 정책을 Clash Royale을 포함한 모든 Supercell 게임에 적용한다. — [Safe and Fair Play Policy](https://supercell.com/en/safe-and-fair-play/)
- 현재 게시 약관의 효력일은 2024-11-06이며, Use Limitations에서 automation software, emulators, bots 등을 열거한다. 게임 파일 변조·무단 접근·역공학 등에 관한 제한도 있으며 계정 제한·정지·종료 가능성을 규정한다. — [Terms of Service](https://supercell.com/en/terms-of-service/)
- 공식 지원 페이지는 Windows의 Google Play Games를 통한 Clash Royale 실행을 지원한다고 설명한다. 공식 PC 플랫폼 지원과 자동 플레이 허용은 별개다. 임의 Android emulator가 허용된다는 근거로 사용할 수 없다. — [공식 PC 지원](https://support.supercell.com/clash-royale/en/articles/clash-of-clans-clash-royale-now-on-pc-with-google-play-games.html)
- Fan Content Policy는 일반적인 가이드·가이드 앱·게임플레이 영상을 허용 범주의 예로 들되 조건을 둔다. Supercell 자산을 사용한 새 게임, 자동화·봇 관련 팬 콘텐츠, private server를 이용한 팬 콘텐츠는 별도 제한 대상으로 둔다. — [Fan Content Policy](https://supercell.com/en/fan-content-policy/)

### Inferences

- 간결한 사용자 안내 문장: '실제 클래시 로얄 자동 플레이는 기술적으로 설계할 수 있지만, Supercell 정책은 봇·자동화 스크립트를 금지하며 영구정지 사유로 명시합니다. 친선전도 예외라고 확인되지 않았습니다.' 이 사실을 계획 앞부분에 한 번 분명히 알린다.
- 자동화 연구와 실서비스 접속을 나눈다. 녹화 분석·자체 시뮬레이터를 기본 개발 대상으로 두고, 실클라이언트 action adapter는 Supercell의 명시적 허용 환경이 확보된 경우의 별도 단계로 취급한다. 상대 친구의 동의는 게임 운영사의 허용을 대체하지 않는다.
- 화면만 보고 탭을 보내는 방식도 게임플레이 자동화라는 분류가 바뀌지 않는다. 메모리 조작을 하지 않는다는 이유로 약관 준수가 된다고 설명하지 않는다.
- '탐지 회피', 인간 흉내 입력, 우회 계정, 테스트 계정이면 정지되어도 괜찮다는 방식을 계획의 해결책으로 삼지 않는다. 정책 문제와 모델 성능 문제를 각각 분리해 보고한다.
- Mac M5 Pro는 영상 분석·추론·자체 시뮬레이션 호스트로 사용한다. Windows 공식 Google Play Games 지원을 Mac 공식 클라이언트 지원으로 확대 해석하지 않는다.

### Gaps

- Supercell이 이 사용자의 연구용 실클라이언트 봇을 허가한 사실은 없다. 친선전·Practice Mode의 자동화 예외도 공식 문서에서 확인되지 않았다.
- 공식 약관의 제한 사실을 모든 나라에서의 불법이라는 법률 판정으로 바꾸지 않는다. 사용자에게 필요한 핵심은 제품 정책과 계정 제재 위험이다.

## 사용자 목적에 맞는 개발 경로는 무엇인가

### Takeaway

초기에는 '실제 녹화 영상을 이해하는 코치'로 관측 성능을 검증하고, '자체 환경에서 실제로 행동하는 에이전트'로 정책 학습을 검증한다. 이후 허용된 실행 환경이 있을 때만 동일 인터페이스에 실제 action adapter를 붙인다. 단순 한국어 해설 모델과 초 단위 행동 정책은 역할을 나눈다.

### Cited Findings

- Fan Content Policy의 coaching은 다른 플레이어에 대한 교육·안내로 설명되며, 공식 정책은 허용 범위의 팬 가이드와 영상 예를 든다. 단, 이것이 실시간 제3자 자동화나 모든 상업 AI 서비스에 대한 포괄 허가는 아니다. — [Fan Content Policy](https://supercell.com/en/fan-content-policy/)
- 공식 제어 API와 자동화 허가를 확인하지 못했고, 봇·자동화는 위 정책의 금지 대상이므로 실클라이언트 자동 플레이를 기본 MVP로 정하는 것은 운영 위험을 안고 시작하는 선택이다. — [공식 API 포털](https://developer.clashroyale.com/), [Safe and Fair Play Policy](https://supercell.com/en/safe-and-fair-play/)

### Inferences

- **경로 A: 경기 후 한국어 코치.** 사용자가 직접 플레이·녹화 → 프레임/시간 추출 → 화면의 카드·엘릭서·유닛 상태 추정 → 잘못된 추정 수정 → 의사결정 시점 분석 → 한국어 설명. 실제 경기 도중 입력을 주지 않는다. 결과물은 타임스탬프별 관측 사실·추정·대안·불확실성이다.
- **경로 B: 자체 시뮬레이터에서 자율 플레이.** 독자적인 단순 도형·명칭·규칙 구현으로 카드 선택·배치·대기 행동을 실행한다. 완전한 Clash Royale 복제나 private server 운영을 기본안으로 삼지 않는다. 관측 → 상태 추정 → 가능한 행동 필터 → 작은 정책 모델 → 시뮬레이터 실행 → 결과 기록을 반복한다. 시뮬레이터 성능을 실제 게임 승률로 보고하지 않는다.
- **경로 C: 허용된 실환경에서 AI 자동 플레이.** 녹화 관측 파이프라인과 정책을 재사용하고 action adapter만 바꾼다. 화면 좌표 변환, 오래된 관측에서의 명령 억제, 대기/no-op, 명령 응답 확인, 중복 행동 방지, 수동 중지, 접속 끊김/전투 종료 감지 등을 설계한다. 이 구성은 기술 아키텍처이며 현재 정책상 허용됐다는 뜻이 아니다.
- 현재 단계에서 필요한 산출물은 데이터 출처·수집 허용 범위, 경기 상태 스키마, 카드 슬롯/좌표/대기 행동 스키마, 오프라인 평가 세트, 실제 행동 전송이 없는 dry-run 로그, 자체 시뮬레이터 재현성 기준이다.
- 검증 지표는 프레임 상태 정확도, 카드 식별 오류, 좌표 오차, 결정 지연 p50/p95, 불가능한 행동 비율, 중복 명령 비율, 시뮬레이터의 동일 seed 재현, 관측 불확실 시 대기율로 나눈다. 전체를 임의의 'AI 실력 점수'로 합치지 않는다.
- Qwen은 전략 요약·사후 설명·실험 결과 분석을 한국어로 담당하고, 빈번한 화면 인식과 행동 선택에 전체 LLM을 매번 쓰는 구조는 지연을 측정한 뒤 결정한다. 실제 전투 상태에는 숨겨진 정보와 모델 오차가 있음을 유지한다.

### Gaps

- 실측 지연, 카드 인식률, 시뮬레이션 품질, 실게임 승률은 측정하지 않았다. 기술적 목표와 검증 계획으로만 제시한다.
- 특정 오픈소스 시뮬레이터·봇 저장소의 라이선스·작동 여부는 다른 조사 범위이며, 이번에는 추천 패키지를 설치하거나 실행하지 않았다.
