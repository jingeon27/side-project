# Python 엔진 경계

- `clash_bot.qwen`은 모델 추론·어댑터 학습·모델 채택 검사를, `clash_bot.arena`는 네이티브 전투·수읽기·자가대국을, `clash_bot.perception`은 CPU 인식·변환을, `clash_bot.trophy`는 검증된 내 실전 행동의 별도 CPU PPO를 소유한다. 트로피는 arena의 순수 특징·가중치 수치 계약을 재사용하되 네이티브 시뮬레이터·Qwen·상대 교사를 학습에 사용하지 않는다. 모듈 이름은 `clash_bot.*`로 가져오며 `sys.path`를 변경하지 않는다.
- 실행은 Node의 공통 Python 실행기를 통해 `python -m clash_bot...`로 한다. 작업 디렉터리에 의존하지 않으며 파일 경로는 `clash_bot.paths`에서 가져온다. `.data` 구조·체크포인트 형식·모델 지문·JSON 줄 단위 통신을 보존한다.
- 언어 간 공유 계약은 앱의 `contracts/`, 그림 참조는 `assets/`, 테스트 자료는 `test-fixtures/`가 소유한다. JSON 계약을 언어마다 복제하지 않는다.
- 통신 입력의 형식 검증과 학습·채택의 도메인 검사를 구분한다. 관측되지 않은 상태를 기본 정답으로 채우거나 읽기 전용 평가를 학습으로 전환하지 않는다. 캐시에는 고정 특징만 저장한다.
- 테스트는 구현 옆에 두고 앱의 Yarn 명령에서 실행한다. 여러 테스트가 함께 쓰는 준비 코드는 `*_fixture.py`로 두며 unittest 수집과 실행 동작 해시에서 빠진다. 전체 모델·실제 인식·병렬 전투 검사는 명시적으로 선택한다. 예열·검증 경기를 학습 횟수에 더하지 않는다.
- 실행 중인 모델 환경에 개발 도구를 설치하거나 가중치를 덮어쓰지 않는다. 수치 계산 변경은 기존 판정·기울기·체크포인트 보호 검사로 확인하고, 포맷 변경을 실력·속도 개선으로 보고하지 않는다.
