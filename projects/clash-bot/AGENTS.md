# Clash Bot

- 실제 클래시로얄 트로피 경기를 화면만 읽어 두는 로컬 봇의 학습 코어를 소유한다. 로컬 자가대국(arena)이 빠른 정책을 학습·채택하고, 명시적으로 요청한 트로피 자동개선(`src/trophy`·`clash_bot.trophy`)이 현재 관측·확인된 내 행동·최종 결과만으로 별도 CPU 정책을 학습한다. 상대 모방이나 정확한 비공개 손패를 요구하지 않는다. 자가개선 감독(`src/loop`)은 자가대국을 유지하고 새 시뮬레이터 챔피언을 트로피 실전 평가에 넘기며, 실전 경기를 시작하지 않는다. 화면 입력·인식 연결은 Git 밖 로컬 어댑터이며 코어 학습기와 구분한다. 실행 기록·모델·Python 환경은 Git에서 제외된 `.data`가 소유한다.
- 폴더 소유권과 실행 흐름은 [docs/architecture.md](docs/architecture.md), 학습 판정과 한계는 [docs/learning-design.md](docs/learning-design.md)·[docs/arena-learning.md](docs/arena-learning.md)를 따른다. 카드 스펙, 실제 클래시로얄 화면 라벨링, 시뮬레이터 보정과 지속 자가개선은 [docs/self-improvement-plan.md](docs/self-improvement-plan.md)의 순서로 진행한다. TypeScript 계층과 모듈 규칙은 `apps/agent/src/AGENTS.md`, Python은 `apps/agent/python/AGENTS.md`에 있다.
- 코드 파일(TS·Python, 테스트 포함)은 300줄 미만을 목표로 함께 바뀌고 함께 읽히는 책임 단위로 나눈다. 줄 수를 맞추려는 재수출 모듈이나 의미 없는 조각은 만들지 않고, 나눌 때는 동작을 바꾸지 않은 채 가져오는 쪽을 새 위치로 고친다. Python 패키지는 아래 패키지만 가져오고 `clash_bot/layers_test.py`가 검사한다. arena는 `catalogue`·`placement` ← `sim` ← `tables` ← `policy` ← `training` ← `league` ← `commands` ← `cli` 한 방향이고, qwen에는 루트 모듈만 가져오는 `action_prior`만 남는다. Node나 Git 밖 어댑터가 이름으로 실행하는 모듈(`action_prior`, `vision_worker`, `trophy_vision`, `runtime_setup`, 각 `setup`, `arena.cli`, `trophy.worker`)은 경로를 옮기지 않는다.
- Git 밖 어댑터가 읽는 인식 자산·데이터 경로(`apps/agent/assets/counterpush`, `.data/counterpush/detector`, `profiles/counterpush.json`)와, 바꾸면 arena `rulesID`가 바뀌는 계약 키(`contracts/arena.json`의 `liveDeck: "counterpush"`, `contracts/combat-projection.json`의 `counterpushCalibrated`)는 이름을 그대로 둔다. 바꾸는 시점은 계획 문서 0단계의 후속 작업을 따른다.
- 코드·계약·저장 형식은 [current-code-only](.agents/skills/current-code-only/SKILL.md)를 따른다. legacy 호환 없이 현재 코드와 현재 형식의 기록으로만 동작한다.
- 다른 실행의 `.data`와 프로세스를 바꾸지 않는다. 트로피 학습기(`trophy/learning/control/lock.json`)나 자가대국(`arena/control/lock.json`)이 실행 중이면 setup으로 venv·모델을 바꾸지 않으며, 워커 프로세스가 끝난 뒤에 잠금을 푼다. 자가개선 감독은 자신이 시작한 자가대국만 멈춘다.
- 적용 모델은 원본 증거를 재검사한 게시 경로로만 바뀐다. 채택 게이트 기준은 `apps/agent/contracts/qualification.json`, 빠른 정책의 특징 배치는 `apps/agent/contracts/fast-policy.json`, 카드·필드 오브젝트의 특징은 `apps/agent/contracts/card-catalogue.json` 하나를 TS와 Python이 함께 읽는다. 카탈로그는 손으로 고치지 않고 `arena catalogue`로 고정 엔진 수치표에서 다시 만든다.
- 트로피의 현재 계약은 `contracts/trophy-learning.json`, 감독의 주기와 재시작 한도는 `contracts/self-improvement.json`이다. 기존 읽기 전용 기록·평가·미확인 입력을 새 학습 자료로 바꾸지 않는다. 수집 분포와 PPO 확률을 일치시키고, 고정 평가 중 가중치를 갱신하지 않는다. 트로피의 학습·평가·게시와 arena 리그를 격리하고, 시뮬레이터 챔피언은 감독이 쓴 인계 파일(`simulation-candidate.json`)로만 받는다.
- 일반 검사는 `yarn workspace @side/clash-bot check`(lint·타입·Vitest 단위 레인)와 `check:python`·`test:python`(모델 없는 계약)이다. CI는 모델을 내려받지 않는다. 실모델 검사(`test:perception:model`, `test:arena:model`, `test:trophy:model`)는 명시적으로 실행하고, 보고할 때 실행한 검사와 건너뛴 검사를 구분한다.
