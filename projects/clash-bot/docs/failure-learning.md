# 2026-11-16 패배 원인과 학습 수정

## 확인한 문제

고정 Qwen v68과 후보 v72의 중단된 실전 비교 16판은 모두 패배했다. 가중치가 바뀌었다는 사실만으로 실력이 좋아졌다고 볼 수 없다. 원본 결과와 판단 293건을 다시 집계했다.

- 무덤이 손패에 있고 확인된 엘릭서 하한이 5 이상인 판단은 225건이었다. 이 중 무덤이 선택지에 있는 판단은 **1건**이었다. 기존의 전략 조건이 무덤을 사실상 금지했다.
- 화면 추적은 유닛 본체를 `kind`로 저장하고 새 카드 사용이 확인되지 않으면 `card=null`로 둔다. 기존 지원 유닛 판정은 `card`만 읽어, 보이는 기사도 없다고 판단할 수 있었다.
- 판단 지연 중앙값은 **4,640ms**, 입력 길이 중앙값은 **5,846자**였다. 판단 중 생긴 위협이나 손패 변화 때문에 실행을 취소하는 경로도 있었다.
- 확인된 사용은 용광로 37, 오두막 28, 얼음 마법사 40, 해골병사 36, 독 10, 바바리안 통 30, 기사 38, 무덤 1이었다. 모든 카드가 똑같이 학습됐다고 보고할 근거가 없다.
- 기존 루프는 1~2판의 작은 후보 업데이트 후 긴 고정 평가를 수행했다. 평가 중에는 의도적으로 학습하지 않는다. 이 때문에 프로세스가 살아 있어도 새 학습이 거의 진행되지 않는 시간이 길었다.

수정 후 첫 실전 경기의 캐시로 추가 검사한 결과, 기존 PPO는 전체 경기 학습 목적 함수가 **0.080939 → 0.081076**으로 나빠진 업데이트도 저장했다. 전술 정답 모방·상대 행동 모방·실전 보상이 같은 Adam 누적 상태를 공유했고, 수락 조건은 가중치 변화와 KL만 확인했다. 개별 행동의 확률 하나만 보고 학습 방향을 판단하지 않고, 실제 학습 목적 함수 전체를 다시 계산해 확인했다.

종결 패배만으로 각 배치의 좋고 나쁨을 알기 어렵고, 검증되지 않은 작은 자가대국 정책의 탐색 방문 수를 정답처럼 모방하는 것도 약한 감독이다. 상대 행동 모방이 같은 어댑터의 실전 판단을 흐릴 가능성은 코드에서 추론한 위험이며, 패배의 직접 원인으로 입증한 것은 아니다.

## 적용한 변경

배포 기준 v68의 동작은 고정하고 별도 후보에 controller 2를 붙였다. 자원이 있는 손패는 모두 비교할 수 있고, 무덤은 두 상대 타워에 항상 후보가 생긴다. 본체 종류와 카드 사용 기록을 구분한다. 합법성으로 전략을 강제하지 않으며 대기와 기존 수비 배치, 준비된 스킬도 유지한다. 후보와 실전 증거의 controller 버전이 다르면 채택을 거부한다.

이후 controller 3 후보로 바꾸면서 controller 2와 그 전술 자료 형식(`counterpush-tactical-targets-v2`)은 코드에서 지웠다. 지금은 챔피언이 controller 1, 후보가 controller 3을 쓴다.

실전과 시뮬레이터는 타일 좌표와 짧은 판단 계약을 공유한다. 화면 인식은 불완전하다는 점을 명시하고, 없는 탐지를 사망으로 간주하지 않는다. 같은 실제 화면 4개의 동일 모델 비교에서 평균 판단 시간은 **4,335.75ms → 2,155.25ms**였다. 온라인 인식과 입력까지 포함한 경기 전체 성능 측정은 아니다.

기존 무자격 탐색 자료 대신 **같은 공개 필드에서 행동과 대기를 각각 실행해 타워 피해 차이를 측정**하는 전술 자료를 추가했다. 무덤 수비, 접근하는 유닛 수비, 탱커 뒤 공격과 지원을 다룬다. 미래 상대 배치를 알지 못하는 12초 비교이며 80 이상 타워 체력 차이가 있는 경우만 보관한다. 수비 문제에서는 자신의 타워 보존을 우선한다. 이를 경기 승리 보상으로 꾸미지 않는다. 행동 순서는 상황마다 섞어 특정 글자를 외우는 편향을 줄인다.

초기 학습 자료 63개와 별도 seed의 미학습 점검 자료 16개를 만들었다. 자동 자가대국이 끝날 때마다 실제 훈련 경기의 복잡한 필드에서도 같은 비교를 수행해 추가 자료를 만든다. 8개 상황 묶음을 명시적인 3회 반복 학습하고 KL 상한과 손실 개선을 확인한다. 같은 자료를 새 자료로 속여 중복 학습하지 않는다. 별도 점검 자료는 학습 로더에서 거부한다.

후보는 초기 전술 학습 후 기본 8판씩 실전 PPO·상대 행동 모방을 진행한다. 상대 모방이 보관된 공격·수비 기준 상황의 손실이나 확률 분포를 크게 나쁘게 만들면 업데이트를 되돌린다. 기준·후보 고정 비교와 원본 증거 재검사에 통과한 경우만 배포 모델을 교체한다. 기존 16판의 원본과 비교 횟수 예산은 남기고, 변경된 후보는 새 평가로 시작한다.

학습 목적이 바뀔 때는 가중치를 유지하고 Adam의 누적 상태를 초기화한다. PPO는 경기 전체의 학습 목적 함수가 개선돼야 저장하며, 개선되지 않으면 작은 학습률로 재시도하고 끝내 개선되지 않으면 원복한다. 같은 실제 11개 판단을 동일한 v77에서 다시 학습한 별도 진단 후보에서는 목적 함수가 **0.080939 → 0.072427**로 개선됐다. 배포 기준은 변경하지 않았다. 이 검사는 학습 갱신의 방향에 대한 증거이며 경기 실력 평가와 구분한다.

새 자동 평가에는 탈락이 확정된 비교의 조기 종료를 추가했다. 남은 모든 쌍을 후보가 이겨도 사전 지정한 전체 표본 판정을 통과하지 못하면 학습으로 돌아간다. 원본 보고서는 미완료·탈락으로 남기며 조기 채택하지 않는다. 평가의 횟수 예산도 돌려받지 않는다. 작은 수동 점검과 기존 평가의 중단 규칙은 보존한다.

## 검증 범위

타입 검사, Vitest 102개, Python 학습 검사 38개 중 37개 통과·실모델 통합 1개 별도 건너뜀, 네이티브 시뮬레이션 검사 20개 통과. 실제 Qwen3.8의 별도 후보에 63개 전술 자료로 189번의 기울기 갱신을 수행했다. 8개 묶음 모두 학습 손실이 줄고 가중치가 바뀌었지만, 미학습 16개 상황에서 좋은 행동에 주는 평균 확률은 **6.48% → 6.98%**, 최상위 정답 수는 **1/16 → 1/16**이었다. 일반화가 개선됐다고 볼 근거가 부족하다. 배포 기준 v68은 동일 SHA로 유지했다. 구체적인 측정 결과와 원본 경로는 로컬 `.data/counterpush/analysis/failure-learning-20261116.json`、`optimizer-repair-diagnostic-20261116.json`에 남겼다.

실전 재개 후 첫 두 경기는 다시 패배했다. 두 번째 경기에서 확인된 무덤 사용 가능 판단 2개는 모두 무덤 선택지를 포함했고, 판단 지연 중앙값은 1,961ms였다. 첫 경기에서는 내 행동 11개와 상대 무덤·독 사용 2개가 실제 학습에 들어갔다. 네이티브 자가대국도 재개해 완료 경기로부터 새 전술 자료를 생성한 것을 확인했다.

검증 명령은 `yarn workspace @clash-bot/agent typecheck`, `test`, `test:learning`, `test:arena`다. 첫 추가 Python 검사에서는 새 목적 함수 전후 계산 때문에 기존 테스트의 함수 호출 수 가정이 실패했다. 각 경기의 보상이 모든 계산에 올바르게 전달되는지를 확인하도록 수정한 재실행에서 통과했다. 모델 전체를 읽는 통합 검사는 별도 건너뛰었으며 위 실모델 추론·학습과 캐시 진단은 실제 프로젝트 자료로 수행했다.

네이티브 시뮬레이션의 수치·생성 패턴과 Counterpush가 완전히 같다는 보장은 없다. 전술 정답 확률이나 손실 개선은 실전 승률 개선이 아니다. 타워 HP를 정확히 읽지 못한 실전 화면에 가짜 중간 보상을 붙이지 않았으며, 실전 평가는 계속 필요하다.
