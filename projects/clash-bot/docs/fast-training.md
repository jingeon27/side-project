# 1초 판단과 100판 학습

## 제한 없는 반복 실행

현재 연속 실행은 `--training-goal` 없이 시작한다. `hours=0`, `matches=0`은 시간·판수 제한을 두지 않으며, 16판 학습 → 후보를 고정한 비교 → 채택 또는 추가 학습을 반복한다. 모델 갱신 횟수를 승률 개선으로 세지 않는다. 로그인 만료·계약 불일치·지속적인 입력 실패는 정지 사유로 남긴다.

```sh
yarn workspace @side/clash-bot counterpush start --background --hours 0 --matches 0 --training-matches 16 --pairs 16
```

이전 100판 목표와 경기·가중치는 별도 기록으로 보존한다. 좌우가 바뀌지 않은 상대 반사 자료는 v5 학습 자료로 다시 만들고, 잘못된 라벨이 들어가기 전 후보에서 분기했다. 무덤의 넓은 시각 오차가 타워 정중앙까지 정답으로 묶지 않도록 가로 오차를 추가 제한한다. 이는 데이터 오류 복구이며 실력 향상이 입증됐다는 뜻은 아니다.

평가 보고서 v2는 가중치뿐 아니라 실행 코드·공유 계약·참조 그림·프로필의 해시를 고정한다. 중간에 이 값이 바뀌면 이전 경기를 섞어 재개하지 않는다. 게시 단계도 원본 경기의 행동 해시와 사전 등록 장부를 다시 검사한다. 기존 비교의 원본 증거와 사용한 유의수준 예산은 보존한다.

## 판단 경로

controller 3은 CPU가 인식한 손패·자원 범위·유닛·효과를 짧은 텍스트로 Qwen3.8에 전달한다. 모델·어댑터는 유지하고 이미지를 다시 처리하지 않으며 문장을 생성하지 않는다. 원본 화면은 증거와 인식 검증을 위해 보관한다. 인식되지 않은 유닛을 모델이 원본 이미지에서 보충하던 경로는 없어지므로 인식 누락은 여전히 제한이다.

규칙·비용·피해 범위·능력 조건 설명은 공유 계약의 고정 머리말로 모은다. 머리말과 현재 상태를 항상 같은 두 구간으로 실행하고, 고정 구간의 KV/순환 상태 하나만 재사용한다. 시시각각 바뀌는 필드·순환·엘릭서·행동 후보와 현재 어댑터의 확률은 매번 계산한다. 저장한 상태는 복제해 사용하므로 다음 판단이 이전 경기의 필드를 이어받지 않는다. 캐시는 256MiB 상한이며 실제 221토큰 머리말은 약 162.8MiB였다. 마지막 MLP 어댑터보다 앞의 고정 상태여서 어댑터 변경과 분리한다.

분할 계산은 이전 일괄 계산과 수치적으로 완전히 같지 않다. 실제 예비 비교 8장면에서 최대 로그확률 차이 0.273이 나왔으므로 이를 기존 모델과 동일한 출력의 최적화라고 주장하지 않는다. 현재 후보의 학습과 추론을 같은 분할 경로로 맞추고 특징 캐시 키도 `frozen-qwen-causal-prefix-text-v2`로 구분한다. 이전 일괄 계산 특징을 새 입력의 캐시로 읽지 않는다. 실전 적용 모델 v68의 controller 1은 유지하며 새 후보는 실전 고정 평가를 거쳐야 한다.

첫 선택 전에 모델·고정 머리말·인식을 예열한다. 예열은 가중치를 바꾸지 않으며 가짜 경기·정답·학습 횟수에 포함하지 않는다. Qwen이 판단하는 동안 필드 관찰을 계속하고, 예측이 끝나면 추가 350ms 주기를 기다리지 않는다. 입력 직전에는 새 화면으로 손패·자원·스킬·무덤의 새 보라색 영역을 가볍게 재확인한다. 1초를 넘긴 모델 응답은 기록하고 실행하지 않는다. 진행 중인 인식과 입력 확인을 포함한 전체 반응 시간이 항상 1초 이내라는 보장은 아니다.

실제 기록 12개를 쓴 초기 짧은 입력 실험은 **422~784ms**였다. 네이티브 점검 32개에서는 중앙값 **797ms**, 95백분위 **909ms**, 최대 **1,108ms**였다. 당시 한 사례가 목표를 넘었다. 이후 실제 대전 26개 판단은 중앙값 **609ms**, 최대 **860ms**였다. 화면 인식을 포함한 당시 중앙값은 약 **1,032ms**로 모델 시간과 구분한다. 이후에는 불필요한 일반 체력 막대 스캔을 생략하고 같은 PNG 화면 영역을 직접 캡처하는 경로도 추가했다. 이 경로의 첫 실전 21개는 모델 중앙값 **559ms**·최대 **696ms**, 화면 인식부터 선택 완료까지 중앙값 **893ms**였다. 모든 기기·장면에서의 최대 지연을 보장하는 수치가 아니다.

CPU 인식 8개 실제 화면에서 스레드 1→3은 중앙값 **253.6→178.6ms**였고 카드·유닛·효과와 좌표가 같았다. 3개로 제한해 사용한다. 회색 비활성 손패를 정상 사용 실패로 오판한 사례는 시각적으로 확인한 7장 참조로 보정했다. 회색 해골병사의 별도 참조는 아직 없으며 모르는 그림을 정답으로 채우지 않는다. 비어 있는 애니메이션을 기사로 읽던 경우도 대비가 없는 입력을 거부하도록 수정했다. 비용과 새 손패·지출 확인 조건을 느슨하게 하지 않았다.

## 학습 경로

Qwen의 고정 본체 특징은 모델 지문·정확한 입력·controller 버전으로 키를 만든 캐시에 저장한다. 마지막 LoRA만 학습하므로 같은 특징을 재사용할 수 있다. 현재 어댑터의 확률은 다시 계산하며 과거 확률을 현재 정책으로 재사용하지 않는다. 캐시는 최대 약 4,096개 파일로 제한하고 후보 특징과 체크포인트는 기존 소유 폴더에 남긴다.

네이티브 훈련 자료의 특징을 한 번 계산한 뒤 오답 손실이 높은 사례를 문제 종류별로 섞어 재학습한다. 이를 새 자료나 새 경기로 세지 않고 별도 `tactical_rehearsals`와 기울기 갱신 수로 기록한다. 실전 PPO→상대 행동 모방 뒤 새 자가대국 전술 자료와 최대 4회 재학습을 처리한다. 평가·점검 자료는 이 풀에 들어가지 못한다.

실제 후보에서 128개 자료의 초기 처리에는 약 **107.7초**, 캐시로 **3,072번** 더 갱신하는 데는 **10.6초**가 걸렸다. 별도 32개 점검의 최상위 정답은 **2→3개**였고 교차 엔트로피는 **3.566→3.245**였지만, 좋은 행동에 부여한 총 확률은 **13.04→11.84%**였다. 일반화나 실전 실력 개선을 입증하는 결과로 보지 않는다. 배포 Qwen v68은 그대로 두고 100판 실전 학습과 새 고정 평가를 수행한다.

같은 4개 자가대국을 순차·병렬로 실행한 비교는 **35.64→15.84초, 2.25배**였다. 시간 필드를 제외한 행동·공개 관찰·최종 결과가 같고 모두 종결·명령 거부 0을 확인했다. 이번 자가대국 실행은 16판씩 7세대, 총 **112판**을 실제로 완료하고 학습 체크포인트 v27을 저장했다. 실전 100판 목표와 이 수치는 별개다.

## 적용하지 않은 실험

- JIT: 선택 헤드 500회 실험은 평균 **0.963→1.153ms**로 오히려 느려 적용하지 않았다. 이는 해당 작은 계산의 결과이며 전체 Qwen JIT의 성능을 측정했다는 뜻은 아니다. [MLX 컴파일 문서](https://ml-explore.github.io/mlx/build/html/usage/compile.html).
- 이전 일괄 계산과 같은 출력이라고 가정한 KV/순환 상태 재사용: 첫 점검에서 최대 로그확률 차이 **0.321**이 나와 적용하지 않았다. 현재는 위의 분할 실행을 별도 후보 입력 계산으로 정의하고 학습·추론의 일치를 검사한다.
- JEPA: 영상에서 미래 표현을 예측하는 별도 모델과 행동 조건 학습이 필요하다. 이번 지연 병목을 줄인다고 검증하지 못했으므로 추가하지 않았다. [Meta의 V-JEPA 2 연구](https://ai.meta.com/research/publications/v-jepa-2-self-supervised-video-models-enable-understanding-prediction-and-planning/).
- 별도 Jev 서비스는 연결하지 않았다. 현재 선택값만 반환하는 구현을 Jev의 비공개 모델·훈련 방식과 동일하다고 주장하지 않는다. [Jev 공식 설명](https://docs.typesafe.ai/introduction).

## 이전 100판 실행

2026-11-16 오전 7시 40분(KST)에 첫 목표를 완료했다. 학습 100판은 **0승 100패**, 확인된 내 행동 2,171개와 상대 행동 208개가 갱신에 사용됐다. 이어 고정 기준 v68과 후보 v737은 각각 **0승 10패**였다. 남은 쌍을 모두 이겨도 사전 조건을 통과할 수 없어 후보를 조기 탈락시켰으며 v68을 유지했다. 이는 채택 성공이나 승률 개선 결과가 아니다. 원본 결과·모델 지문·평가 예산은 로컬 기록으로 보존한다.

이 100판의 모델 판단 3,322개는 중앙값 **564ms**, 95백분위 **703ms**였고 1초 초과 1개는 실행하지 않았다. 추가 학습 요청은 완료된 목표를 보관하고 시작 누적 수 105를 기준으로 새 **100판** 목표를 만들었다. 현재 진행은 `training-goal.json`에서 확인하며 프로세스 재시작으로 목표를 초기화하지 않는다.

```sh
yarn workspace @side/clash-bot counterpush start --background --hours 0 --matches 0 --training-matches 100 --training-goal 100 --pairs 16
yarn workspace @side/clash-bot counterpush status
```

이번 목표는 **실제 Counterpush 대전 100판의 학습 처리 후 새 고정 평가까지 완료**다. 자가대국·전술 상황·예열·평가 경기는 실전 목표에 더하지 않는다. `training-goal.json`이 완료되기 전에는 완료라고 보고하지 않는다. 새 평가에서 자격을 얻은 모델만 채택하며, 목표와 평가가 끝나면 실행기를 정지한다. 입력 복구 경기의 제외·재시도와 기준 모델 보호는 유지한다. 로그인 만료나 지속적인 인식 실패는 오류로 남기며 완료로 꾸미지 않는다.

백그라운드 프로세스가 실행하는 동안 전용 `caffeinate`로 최대 12시간 유휴 절전을 막는다. 해당 프로세스가 끝나면 이 절전 방지도 종료하며 시스템 설정은 변경하지 않는다. 전용 Chrome은 음소거·1개 탭을 유지한다.

## 초기 검증 기록

현재 타입·lint·Vitest **140개**, Python 핵심 **38개**, 학습 **59개**·시뮬레이션 **40개**를 통과했다. 일반 학습·시뮬레이션 검사에서는 선택적 실모델 검사를 각각 1개 생략한다. 별도로 실제 Qwen3.8-27B 통합 검사를 실행해 어댑터 적용, 체크포인트 복원, 분할 계산의 캐시 생성/재사용 특징 일치, 어댑터 변경 후 현재 확률 재계산을 확인했다. 처음에는 검사 코드가 지원하지 않는 배열 `.copy()`를 호출해 실패했으며 독립적으로 읽은 배열을 보존하도록 수정한 재실행이 통과했다.

새 분할 경로로 실제 긴 장면 8개를 재실행한 모델 판단은 331~715ms였다. 전체 입력의 특징 캐시는 모두 빗나갔고 고정 머리말만 재사용했으며, 이 측정으로 가중치는 바뀌지 않았다. 브라우저 캡처·필드 인식 시간을 포함한 실전 반응 시간과 구분한다. 이전 실전 1판에서는 36개 판단 중 7개가 1초를 넘어 입력이 거부됐으므로, 새 실전 기록으로 별도 확인해야 한다.

초기 병렬 비교는 결과 안의 측정 시간까지 같다고 가정해 실패했다. 시간만 제외하고 실제 게임 데이터를 비교한 재실행이 통과했다. 회색 손패 회귀 검사에서는 빈 그림 오인식이 드러나 이를 수정했고, 이동한 인식 설치 검사는 운영체제 기본 Python 대신 지정한 Python 3.11로 재실행해 통과했다. 실제 지연과 카드별 학습 건수는 실행별 원본 로그를 보존한다.

## 배경 학습의 GPU 부하 목표

`CLASH_BOT_GPU_TARGET=0.90`을 Counterpush 실행 환경에 지정하면 배경 학습에 협력적 속도 조절을 적용한다. 실전 `choose`와 고정 평가 추론에는 대기를 넣지 않는다. 상대 모방·자가대국 감독 자료의 특징 계산, PPO·모방·감독 학습의 각 갱신, 전술 재생의 표본 평가가 완료된 뒤 GPU 동기화와 짧은 대기를 수행한다. 수식·학습 표본·체크포인트·채택 기준은 바꾸지 않는다.

Apple GPU의 전체 사용률을 관리자 권한 없이 0.5초마다 읽고, 최근 20개 표본(약 10초)의 평균을 목표와 비교해 배경 작업 비율을 조절한다. 최초 비율은 목표의 85%, 과부하 시 감소, 여유가 있으면 목표까지 회복하며 한 번의 대기는 최대 2초다. 이 값은 물리적 최대 사용률 제한이 아니다. 실행 중인 GPU 명령·실시간 추론·다른 앱 때문에 순간 100%가 가능하며 시스템 전체 CPU나 RAM을 90%로 제한하지 않는다. 측정을 읽지 못하면 보수적인 작업 비율로 계속하고 측정값은 불명으로 남긴다.

`.data/resources/qwen-budget-<pid>.json`은 목표·최근 GPU 평균·표본 수·작업/대기 시간·처리 수를 기록한다. 대기 스레드는 MLX를 실행하지 않고 프로세스 종료 시 정리한다. 대상은 별도 실험의 학습 코어이며, 이미 진행 중인 다른 작업 공간의 트로피 평가·모델은 변경하지 않는다.
