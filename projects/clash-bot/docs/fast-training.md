# 1초 판단과 100판 학습

## 판단 경로

controller 3은 CPU가 인식한 손패·자원 범위·유닛·효과를 짧은 텍스트로 Qwen3.8에 전달한다. 모델·어댑터는 유지하고 이미지를 다시 처리하는 단계와 긴 설명 입력을 제거했다. 이전처럼 한 번의 전방 계산으로 행동 확률을 구하며 문장을 생성하지 않는다. 원본 화면은 증거와 인식 검증을 위해 보관한다. 인식되지 않은 유닛을 모델이 원본 이미지에서 보충하던 경로는 없어지므로 인식 누락은 여전히 제한이다.

첫 선택 전에 모델과 인식을 예열한다. 예열은 가중치를 바꾸지 않으며 가짜 경기·정답·학습 횟수에 포함하지 않는다. 새 판단 동안 추가 전체 인식으로 응답을 기다리지 않는다. 입력 직전에는 새 화면으로 손패·자원·스킬·무덤의 새 보라색 영역을 가볍게 재확인한다. 1초를 넘긴 모델 응답은 기록하고 실행하지 않는다. 전체 필드 인식과 카드 사용 확인은 계속 수행한다.

실제 기록 12개를 쓴 초기 짧은 입력 실험은 **422~784ms**였다. 네이티브 점검 32개에서는 중앙값 **797ms**, 95백분위 **909ms**, 최대 **1,108ms**였다. 당시 한 사례가 목표를 넘었다. 이후 실제 대전 26개 판단은 중앙값 **609ms**, 최대 **860ms**였다. 화면 인식을 포함한 당시 중앙값은 약 **1,032ms**로 모델 시간과 구분한다. 이후에는 불필요한 일반 체력 막대 스캔을 생략하고 같은 PNG 화면 영역을 직접 캡처하는 경로도 추가했다. 이 경로의 첫 실전 21개는 모델 중앙값 **559ms**·최대 **696ms**, 화면 인식부터 선택 완료까지 중앙값 **893ms**였다. 모든 기기·장면에서의 최대 지연을 보장하는 수치가 아니다.

CPU 인식 8개 실제 화면에서 스레드 1→3은 중앙값 **253.6→178.6ms**였고 카드·유닛·효과와 좌표가 같았다. 3개로 제한해 사용한다. 회색 비활성 손패를 정상 사용 실패로 오판한 사례는 시각적으로 확인한 7장 참조로 보정했다. 회색 해골병사의 별도 참조는 아직 없으며 모르는 그림을 정답으로 채우지 않는다. 비어 있는 애니메이션을 기사로 읽던 경우도 대비가 없는 입력을 거부하도록 수정했다. 비용과 새 손패·지출 확인 조건을 느슨하게 하지 않았다.

## 학습 경로

Qwen의 고정 본체 특징은 모델 지문·정확한 입력·controller 버전으로 키를 만든 캐시에 저장한다. 마지막 LoRA만 학습하므로 같은 특징을 재사용할 수 있다. 현재 어댑터의 확률은 다시 계산하며 과거 확률을 현재 정책으로 재사용하지 않는다. 캐시는 최대 약 4,096개 파일로 제한하고 후보 특징과 체크포인트는 기존 소유 폴더에 남긴다.

네이티브 훈련 자료의 특징을 한 번 계산한 뒤 오답 손실이 높은 사례를 문제 종류별로 섞어 재학습한다. 이를 새 자료나 새 경기로 세지 않고 별도 `tactical_rehearsals`와 기울기 갱신 수로 기록한다. 실전 PPO→상대 행동 모방 뒤 새 자가대국 전술 자료와 최대 4회 재학습을 처리한다. 평가·점검 자료는 이 풀에 들어가지 못한다.

실제 후보에서 128개 자료의 초기 처리에는 약 **107.7초**, 캐시로 **3,072번** 더 갱신하는 데는 **10.6초**가 걸렸다. 별도 32개 점검의 최상위 정답은 **2→3개**였고 교차 엔트로피는 **3.566→3.245**였지만, 좋은 행동에 부여한 총 확률은 **13.04→11.84%**였다. 일반화나 실전 실력 개선을 입증하는 결과로 보지 않는다. 배포 Qwen v68은 그대로 두고 100판 실전 학습과 새 고정 평가를 수행한다.

같은 4개 자가대국을 순차·병렬로 실행한 비교는 **35.64→15.84초, 2.25배**였다. 시간 필드를 제외한 행동·공개 관찰·최종 결과가 같고 모두 종결·명령 거부 0을 확인했다. 이번 자가대국 실행은 16판씩 7세대, 총 **112판**을 실제로 완료하고 학습 체크포인트 v27을 저장했다. 실전 100판 목표와 이 수치는 별개다.

## 적용하지 않은 실험

- JIT: 선택 헤드 500회 실험은 평균 **0.963→1.153ms**로 오히려 느려 적용하지 않았다. 이는 해당 작은 계산의 결과이며 전체 Qwen JIT의 성능을 측정했다는 뜻은 아니다. [MLX 컴파일 문서](https://ml-explore.github.io/mlx/build/html/usage/compile.html).
- 공통 KV/순환 상태 재사용: 첫 점검에서 원래 계산과 최대 로그확률 차이 **0.321**이 나와 적용하지 않았다. 고정 입력의 최종 특징 캐시만 사용한다.
- JEPA: 영상에서 미래 표현을 예측하는 별도 모델과 행동 조건 학습이 필요하다. 이번 지연 병목을 줄인다고 검증하지 못했으므로 추가하지 않았다. [Meta의 V-JEPA 2 연구](https://ai.meta.com/research/publications/v-jepa-2-self-supervised-video-models-enable-understanding-prediction-and-planning/).
- 별도 Jev 서비스는 연결하지 않았다. 현재 선택값만 반환하는 구현을 Jev의 비공개 모델·훈련 방식과 동일하다고 주장하지 않는다. [Jev 공식 설명](https://docs.typesafe.ai/introduction).

## 100판 실행

2026-11-16 오전 7시 40분(KST)에 첫 목표를 완료했다. 학습 100판은 **0승 100패**, 확인된 내 행동 2,171개와 상대 행동 208개가 갱신에 사용됐다. 이어 고정 기준 v68과 후보 v737은 각각 **0승 10패**였다. 남은 쌍을 모두 이겨도 사전 조건을 통과할 수 없어 후보를 조기 탈락시켰으며 v68을 유지했다. 이는 채택 성공이나 승률 개선 결과가 아니다. 원본 결과·모델 지문·평가 예산은 로컬 기록으로 보존한다.

이 100판의 모델 판단 3,322개는 중앙값 **564ms**, 95백분위 **703ms**였고 1초 초과 1개는 실행하지 않았다. 이 수치는 BlueStacks를 함께 실행하기 전 측정이다. 추가 학습 요청은 완료된 목표를 보관하고 시작 누적 수 105를 기준으로 새 **100판** 목표를 만들었다. 현재 진행은 `training-goal.json`에서 확인하며 프로세스 재시작으로 목표를 초기화하지 않는다.

```sh
yarn workspace @side/clash-bot counterpush start --background --hours 0 --matches 0 --training-matches 100 --training-goal 100 --pairs 16 --tabs 1
yarn workspace @side/clash-bot counterpush status
```

이번 목표는 **실제 Counterpush 대전 100판의 학습 처리 후 새 고정 평가까지 완료**다. 자가대국·전술 상황·예열·평가 경기는 실전 목표에 더하지 않는다. `training-goal.json`이 완료되기 전에는 완료라고 보고하지 않는다. 새 평가에서 자격을 얻은 모델만 채택하며, 목표와 평가가 끝나면 실행기를 정지한다. 입력 복구 경기의 제외·재시도와 기준 모델 보호는 유지한다. 로그인 만료나 지속적인 인식 실패는 오류로 남기며 완료로 꾸미지 않는다.

백그라운드 프로세스가 실행하는 동안 전용 `caffeinate`로 최대 12시간 유휴 절전을 막는다. 해당 프로세스가 끝나면 이 절전 방지도 종료하며 시스템 설정은 변경하지 않는다. 전용 Chrome은 음소거·1개 탭을 유지한다.

## 검증 기록

타입 검사·Vitest **109개**, Python 학습 검사 **43개 중 42개**·시뮬레이션 검사 **21개**, 실제 ONNX 인식 모델 검사 **1개**를 통과했다. CPU 인식 일반 검사도 실행했다. 실제 Qwen 추론·초기 학습·캐시 재학습과 실전의 확인된 카드 사용도 별도로 검사했다. 일반 Python 검사에서 전체 Qwen 모델 통합 1개는 별도로 건너뛰며, 이번에 동시에 두 Qwen을 올려 전체 통합을 다시 실행하지 않았다.

초기 병렬 비교는 결과 안의 측정 시간까지 같다고 가정해 실패했다. 시간만 제외하고 실제 게임 데이터를 비교한 재실행이 통과했다. 회색 손패 회귀 검사에서는 빈 그림 오인식이 드러나 이를 수정했고, 이동한 인식 설치 검사는 운영체제 기본 Python 대신 지정한 Python 3.11로 재실행해 통과했다. 실제 지연과 카드별 학습 건수는 실행별 원본 로그를 보존한다.

## BlueStacks 병행 검증

2026-11-16에는 한 Qwen 본체를 공유하면서 Counterpush 후보 학습, BlueStacks 트로피 관찰 플레이와 CPU 자가대국 2개를 함께 실행했다. 첫 트로피 경기는 0:2 패배였고 입력 28회 중 손패 변경·자원 감소 24회를 확인했다. 같은 왕관 수를 두 번 확인하고 로비에 복귀한 뒤 다음 매칭도 시작했다. 경기 전체에서 어댑터 SHA는 v743 하나로 유지됐다. 이 관찰을 모델 채택이나 트로피 학습으로 세지 않는다.

초기 병행 표본에서 단일 합법 행동을 제외한 모델 판단은 Counterpush 71개 중앙값 **572ms**·95백분위 **965ms**, 트로피 65개 중앙값 **589ms**·95백분위 **739ms**였다. 통신과 요청 대기도 포함한다. Counterpush 최대값 **1,107ms**처럼 마감 초과는 여전히 발생하며, 이런 판단은 실행하지 않는다. 트로피 요청 28개는 사용 중인 모델을 기다리지 않고 보류했다. 이 수치는 실행 초기 표본이며 승률 개선이나 지속적인 최대 지연을 보장하지 않는다.

추가 코드의 타입 검사·Vitest **112개**, Python 학습 검사 **47개 중 46개**, 시뮬레이션 **21개**, 일반 인식 **6개 중 5개**가 통과했다. 전체 Qwen 통합과 일반 인식의 실모델 통합 각 1개는 해당 검사에서 건너뛰었다. 실제 공유 Qwen 추론과 두 게임의 입력은 별도로 수행했다. 첫 공유 소켓 검사에서는 macOS 임시 경로의 `/var`와 `/private/var` 별칭 비교가 실패했으며 실제 경로로 통일한 재실행이 통과했다. 외부 추론 오류 후 어댑터 복귀, 고정 평가 중 거부, 저장 경로 제한, 트로피 자료의 학습 제외, 모델 소유자 종료 후 새 매칭 방지와 잠금 정리도 검사했다.
