# 덕담집 기록을 이어 쓰는 흐름

## 사용자가 경험할 순서

1. 쇼츠에서 공개 이야기 한 편을 열고, 덕담을 내 말투로 고쳐 엽서로 보낸다. 이야기 메뉴는 `/stories`에서 전체 회차를 보여준다.
2. 내 사주에서는 양력·음력 생일과 선택한 시각으로 네 기둥을 기기에서 계산한다. 일간의 뜻, 태어난 계절, 선택한 고민과 오늘 시도할 예를 순서대로 읽는다. 경험 원문과 생일은 서버 요청에서 제외한다.
3. 로그인 전에도 덕담을 만들거나 엽서로 보내고, 풀이를 받고, 해본 일을 적을 수 있다. 이 브라우저에 남긴 세 종류의 기록은 첫 로그인 때 선택한 계정으로 옮긴다. 사이트 데이터를 먼저 지우면 이 기기의 기록도 사라진다. 예전 버전에서 쓴 실천은 기록장에서 본인이 가져온다.
4. 다른 기기에서는 같은 제공자의 같은 계정으로 로그인해 기록을 이어본다. 두 제공자 계정은 독립적으로 관리한다. 결제는 로그인 후 상품과 금액을 다시 확인하고 직접 시작한다.

## 로컬 로그인과 검색

개발 서버에서 `DEOKDAM_LOCAL_LOGIN=1`을 켜면 로그인 화면에 테스트 계정 A와 B가 나타난다. 각각 별도의 고정 계정이며 실제 로그인과 동일한 세션과 기록 저장 경로를 사용한다. 브라우저 두 창에서 같은 계정으로 이어보기, 다른 계정으로 전환, 로그아웃 뒤 기록 접근을 검사한다. 개발 서버와 Playwright의 SQLite 파일을 분리한다. 운영 이미지에서도 이 플래그를 켜서 버튼이 사라지고 서버가 404를 반환하는지 검사한다.

공개 홈, 이야기, 사주 입력, 7일 풀이, 개인정보 안내와 공개 회차는 대표 주소와 제목·설명을 제공한다. 새 회차를 공개하면 사이트맵에 바로 들어간다. 검색 로봇에는 사이트맵 위치를 안내한다. 로그인·기록장·구매 내역에는 검색 제외를 지정하고 기록 API는 계정 세션을 검사한다. 공유 링크에는 공개 원본 회차의 이미지와 문구를 싣는다.

## 검증 기준

폼의 필드 오류와 재시도 버튼은 화면에서 계속 찾을 수 있어야 한다. 복사·저장·삭제 결과는 실제 작업 완료 뒤에 한 번 알린다. 지속 상태를 훅마다 복제하지 않는 기준은 [공통 TypeScript 스킬](../../../.agents/skills/typescript-code-style/SKILL.md)을 따른다.

Amplitude에는 로그인 제공자·진입 화면, 공개 회차·주제, 작업 성공 여부만 기록한다. 계정 식별자, OAuth 파라미터, 개인 메모와 출생 정보는 보내지 않는다. 광고 승인과 가맹점 설정은 사용자 인증과 별도로 실제 공급자 상태를 확인한다.
