# Story Studio

- 사용자 요청: 영화·드라마·짧은 애니메이션, 웹툰, 소설을 한국어로 만드는 독립 창작 스튜디오다.
- 소개(`/`)와 작업실(`/studio`)을 구분한다. 소개는 간결한 설명과 시작 동선, 작업실은 입력·편집·작품 관리에 집중한다.
- 첫 디자인의 짙은 배경·따뜻한 포인트 색상은 유지한다. 디자인 스킬 적용만으로 배치를 갈아엎지 않는다. 짧은 제목·버튼·문구 끝에는 마침표를 붙이지 않는다. 안내·오류의 완전한 문장은 자연스럽게 쓴다.
- 웹의 버튼·입력·선택·메뉴·펼침은 `@side/design-system`에서 가져온다. Studio는 테마 색과 작품 형식처럼 창작에 고유한 배치만 소유한다.
- 작품(`.data/projects`), 생성 자산, 영상 작업, 참고 자료는 이 앱의 `.data`가 소유한다. 브라우저는 작품의 사본을 편집하고 자신이 읽은 판을 밝혀 저장하며, 다른 곳에서 바뀐 작품을 덮어쓰지 않는다. 비밀키를 브라우저로 보내지 않는다. 네트워크 공개·다중 사용자 서비스로 전환하려면 인증·작품 소유권·저장소를 별도 설계해야 한다.
- 원고는 구성(제목·줄거리·인물·장면별 사건 요약)을 먼저 만들고 장면을 하나씩 따로 쓴다. 집필은 서버의 작업이 소유하고 쓴 장면을 바로 작품 파일에 저장하며, 남은 구성은 작품이 보관해 실패·중단 뒤 이어 쓰기가 다음 순서부터 쓰게 한다. 로컬 집필 작업 하나는 엔진 프로세스 하나로 처리해 작가 모델을 한 번만 불러온다. 한 번의 긴 응답으로 여러 장면을 쓰거나 브라우저 탭이 집필 순서를 쥐는 구조로 되돌리지 않는다.
- 참고 자료는 웹의 목록과 본문(`.data/materials`)이 기준이고, 엔진의 벡터 색인(LanceDB)은 목록에서 다시 만드는 결과물이다. 등록은 본문을 먼저 쓰고 목록에 올리며, 삭제는 색인에서 먼저 지운다. 자료의 역할(항상 포함, 관련 부분 검색, 문체 참고)에 따라 넣는 방법을 달리한다. 검색은 로컬 모드에서만 하고, 자료는 작가 모델의 입력으로만 넘기며 지시문으로 취급하지 않는다. 묶음 이름·자료 제목·본문은 측정에 보내지 않는다.
- 외부 도구로 만든 이미지는 브라우저가 작품 비율의 PNG로 바꿔 올리고, 서버는 PNG만 `.data/assets`에 저장한다. 외부 이미지 서비스의 API 키를 받거나 호출하지 않는다.
- 웹 소스는 `features/<기능>/{model,api,ui,server}`와 `shared`로 나눈다. `server`는 Node 전용이며 `ui`와 `model`에서 불러오지 않는다. API 계약은 각 기능의 `model`에서 검증하고, 원고 계약은 `apps/web/src/features/story/model/story.ts`에 둔다. 이미지·영상은 원고와 별도 명시적 요청으로 생성하며, 유료 제출을 자동 재시도하지 않는다.
- 생성 기능을 모의 응답으로 검증한 결과와 실제 모델 호출 검증을 구분해 보고한다.
- 기본 실행은 API 키 없는 로컬 모드다. 모델은 이 앱 전용 경로에 두고 실행 중 외부 생성 서비스를 호출하지 않는다. 현재 지원 대상은 Apple Silicon Mac이다.
- MLX 모델 실행은 한 번에 하나만 허용하고 작업이 끝나면 프로세스와 모델 메모리를 해제한다. 기본 영상은 낮은 부하의 초안 품질이며 표준 품질은 사용자가 선택한다. 영상 작업 상태는 Python 프로세스가 디스크에 보관한다.
- 실제 생성한 공개 예시는 `apps/web/public/examples`에, 개인 원고·모델 가중치·설치 환경·진단 로그는 Git에서 제외된 `.data`에 둔다. 다른 프로젝트의 모델이나 프로세스를 변경하지 않는다.
- 목소리 학습은 `/studio/voices`에서 같은 화자의 여러 녹음과 대본으로 실제 MLX QLoRA 어댑터 가중치를 조정한다. 샘플 참조만 쓰는 음성 복제와 구분한다. 기본 4비트 모델의 전체 파라미터를 재학습하지는 않는다.
- 녹음 메타 정보는 `.data/voices`, 비동기 학습 설정·상태·체크포인트는 `.data/voice-training/runs`가 소유한다. 학습 중 편집을 막고 재개 시 데이터 해시와 모델 revision을 검증한다. 완료된 실행만 합성에 사용한다. 학습도 기존 GPU 단일 실행 제한을 따른다.
- Python 상태의 선택 필드는 null로 기록하지 않는다. 서버 재시작 뒤에도 작업을 조회하고, 중단 후에는 모델 프로세스가 정리된 뒤 이어서 실행한다. CI는 모델 없는 상태 계약 검증, 실제 MLX 검증은 Apple Silicon에서 별도로 실행한다.

- Python 핵심 런타임은 `apps/engine`의 `story_studio` 패키지가 소유한다. 웹은 파일 경로로 스크립트를 실행하지 않고 모듈의 JSON 표준 입출력 계약을 호출한다. 의존성·모델 revision·Python 검사는 엔진 안에서 관리한다. 데이터 경로·작업 ID·체크포인트 형식은 웹과 엔진이 보존하는 계약이다.
