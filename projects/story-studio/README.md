# 장면 | 한국어 AI 창작 스튜디오

영화, 드라마, 짧은 애니메이션, 웹툰과 소설을 만들고 편집하는 독립 프로젝트입니다. 소개는 `/`, 작업실은 `/studio`에 있습니다. 기본값은 **API 키 없는 로컬 생성**입니다. 원고, 목소리, 영상은 이 컴퓨터의 모델로 만들고, 장면 이미지는 이 컴퓨터에서 생성하거나 다른 도구에서 만든 파일을 가져옵니다.

## 실행

현재 로컬 모델 실행은 **Apple Silicon Mac, Python 3.11, 메모리 32GB 이상 권장** 환경을 대상으로 합니다. 실제 검증 장비는 M5 Pro 48GB입니다. 처음 설치할 때 약 89GB의 여유 공간과 인터넷 연결이 필요하고, 설치를 마치면 약 54GB가 남습니다. 공개 저장소의 파일 크기와 변환 결과를 더한 추정치입니다. 설치 도구는 FLUX.2 Klein 원본(약 16GB)을 8비트로 저장하고 Wan2.2 원본(약 34GB)을 MLX로 변환한 뒤 각 원본을 지웁니다. 다시 설치를 실행해도 준비를 마친 모델의 원본은 받지 않으며, 고정 revision이 바뀌면 원본을 다시 받아 준비합니다. 설치 후 생성은 오프라인으로 실행합니다.

이전 설치를 갱신하면 `local:setup`이 새 원고, 자료 검색, 이미지, 영상 모델만 추가로 준비합니다. 기존 Wan2.1 파일(약 30GB 추정)과 이전 원고 모델인 Qwen3.8-27B(약 16GB)는 자동으로 지우지 않습니다. 더 이상 사용하지 않으므로 필요 없으면 저장소 루트에서 지웁니다. `STORY_STUDIO_DATA_DIR`을 쓴다면 그 경로의 `local/models` 아래 세 폴더입니다.

```sh
rm -rf projects/story-studio/apps/web/.data/local/models/wan-source projects/story-studio/apps/web/.data/local/models/video projects/story-studio/apps/web/.data/local/models/text
```

저장소의 Node.js 24와 Yarn 4.17.0을 사용합니다. 저장소 루트에서 실행합니다.

```sh
yarn install --immutable
cp projects/story-studio/apps/web/.env.example projects/story-studio/apps/web/.env.local
yarn workspace @side/story-studio local:setup
yarn workspace @side/story-studio dev
```

[소개](http://127.0.0.1:3400), [작업실](http://127.0.0.1:3400/studio), [목소리 학습](http://127.0.0.1:3400/studio/voices), [참고 자료실](http://127.0.0.1:3400/studio/materials), [실제 생성한 한국어 애니메이션](http://127.0.0.1:3400/studio?demo=1)

예시 원고 편집과 이미 생성한 예시 영상 재생에는 모델 설치가 필요하지 않습니다. 모델 준비 전에는 생성 버튼이 비활성화됩니다. 운영용 빌드는 `yarn workspace @side/story-studio build`, 실행은 `yarn workspace @side/story-studio start`입니다.

## 코드 구성

- `apps/web`: 한국어 작업실, HTTP 계약, 작품과 참고 자료의 저장, 집필 작업
- `apps/engine`: Python 패키지, 모델 준비·생성·음성 가중치 학습, 참고 자료 색인과 검색, 작업 상태와 GPU 실행 수명

웹 소스는 기능별 폴더로 나눕니다. 한 기능을 고칠 때 계약, 화면, 서버 코드와 테스트가 한 폴더에 모이게 하려는 구성입니다.

```text
apps/web/src/
  app/                  Next 라우트. 페이지와 API 핸들러만 두고 기능 폴더를 호출
  features/
    story/              원고 계약(model), 편집기와 장면 카드(ui), 구성·장면 작성과 집필 작업(server)
    library/            작품 저장 요청(api), 저장 대상 판단(model), 브라우저 동기화(ui), 작품 파일 저장소(server)
    media/              이미지 가져오기·영상 내보내기(model), 이미지·영상·음성 생성과 자산(server)
    materials/          자료 계약(model), 요청(api), 자료실과 묶음 선택(ui), 목록과 색인 동기화(server)
    voice/              목소리 계약(model), 요청(api), 학습 화면(ui), 녹음과 학습 저장소(server)
    studio/             작업실 화면 조립(ui)
  shared/               측정, 로컬 엔진 실행, 글 모델 호출, HTTP 오류
```

`model`은 화면과 서버가 함께 쓰는 계약과 순수 계산, `api`는 브라우저의 요청, `ui`는 컴포넌트, `server`는 Node에서만 실행하는 코드입니다. 테스트는 대상 파일 옆에 둡니다.

Python의 설치 의존성과 모델 revision, 테스트는 엔진이 소유합니다. 웹은 `python -m story_studio`에 JSON 작업을 전달하고 결과·진행 상태만 받습니다. 현재 체크아웃의 엔진을 실행하도록 경로를 명시하므로 공유 데이터 폴더의 가상환경이 다른 worktree에 설치되어 있어도 코드를 혼동하지 않습니다. 데이터·모델·가상환경의 기존 경로는 그대로 사용합니다. 자세한 구조와 독립 실행은 [엔진 안내](apps/engine/README.md)를 참고하세요.

## 모델과 제작 순서

| 역할                              | 로컬 모델                                          | 실행 방식                                 |
| --------------------------------- | -------------------------------------------------- | ----------------------------------------- |
| 한국어 구성, 집필, 시각 묘사 번역 | Gemma 4 31B의 mlx-community 4비트 변환본           | MLX VLM, 장면마다 따로 작성               |
| 참고 자료 검색                    | EmbeddingGemma 2의 mlx-community 8비트 변환본      | MLX VLM 임베딩, LanceDB 파일 색인         |
| 장면 이미지                       | 공식 FLUX.2 Klein 4B를 설치 때 8비트로 저장        | mflux, 인물 기준 이미지가 있으면 참조     |
| 짧은 영상                         | 공식 Wan2.2-TI2V-5B를 설치 때 MLX 8비트로 변환     | MLX Video, 장면 이미지가 있으면 첫 프레임 |
| 한국어 목소리                     | Qwen3-TTS-12Hz-1.7B-CustomVoice의 MLX 4비트 변환본 | 기본 음색 9종과 말투 선택                 |
| 목소리 가중치 학습                | Qwen3-TTS-12Hz-1.7B-Base의 MLX 4비트 변환본        | 로컬 QLoRA 미세학습                       |
| 자막, 음성, 장면 합치기           | 모델 계산 없이 로컬 ffmpeg                         | H.264 MP4, AAC 음성                       |

1. 참고할 글이 있으면 **참고 자료실**에 묶음 이름을 정해 텍스트 파일을 올립니다
2. 한국어 아이디어, 인물과 스타일을 입력하고 참고할 자료 묶음을 골라 원고를 만듭니다
3. 장면별 한국어 음성을 먼저 생성합니다
4. 장면 이미지를 생성하거나, **프롬프트 복사**로 다른 이미지 도구에서 만든 뒤 **이미지 가져오기**로 넣습니다. 같은 인물이 이어져야 하면 인물이 잘 보이는 장면에서 **인물 기준으로 사용**을 누릅니다. 이후 이 앱에서 생성하는 다른 장면의 이미지는 그 이미지를 참고해 그립니다
5. 필요한 장면의 영상을 생성합니다. 장면 이미지가 있으면 영상은 그 이미지에서 시작합니다
6. 내보내기에서 한국어 음성과 자막을 넣은 MP4, 말풍선을 넣은 웹툰 PNG, 원고 또는 JSON 백업을 저장합니다

인물 기준은 작품에 저장되며 지정한 장면의 현재 이미지를 사용합니다. 그 장면의 이미지를 다시 만들 때는 자기 자신을 참조하지 않고 새로 그립니다. 참조와 첫 프레임은 로컬 모드에서만 사용하며 클라우드 연결은 기존처럼 글로만 생성합니다.

한 번에 1~8개 장면, 컷, 장을 작성하고 이어쓰기로 작품당 최대 80개까지 확장합니다. 장편은 회차별로 쓰는 방식입니다. 참조 이미지는 얼굴과 의상을 가깝게 유지하도록 돕지만 영화 수준의 인물 일관성을 보장하지 않으며, 립싱크, 긴 연속 영상이나 전문 편집 타임라인은 포함하지 않습니다. 한국어 글자와 말풍선은 앱이 합성하므로 시각 모델의 문자 생성에 의존하지 않습니다.

모델과 런타임은 [모델 revision](apps/engine/src/story_studio/models.json), [Python 패키지와 의존성](apps/engine/pyproject.toml)에 고정했습니다. 공식 모델 설명: [Gemma 4 31B](https://huggingface.co/google/gemma-4-31B-it), [EmbeddingGemma 2](https://huggingface.co/google/embeddinggemma-2), [Qwen3-TTS](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-CustomVoice), [FLUX.2 Klein 4B](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B), [Wan2.2-TI2V-5B](https://huggingface.co/Wan-AI/Wan2.2-TI2V-5B). 원고, 자료 검색과 목소리의 MLX 변환본은 커뮤니티 배포이며 공식 원본과 구분합니다. Gemma 4와 EmbeddingGemma 2의 모델 카드는 Apache-2.0을 표시합니다. 원고 모델을 Qwen3.8-27B에서 Gemma 4 31B로 바꾼 뒤 두 모델의 한국어 원고를 같은 조건으로 비교한 결과는 아직 없습니다. 이미지와 영상은 공식 가중치를 이 컴퓨터에서 8비트로 저장하거나 변환하며, 두 모델 모두 Apache-2.0입니다.

### 원고를 쓰는 순서

원고는 한 번의 긴 응답으로 만들지 않습니다. 먼저 제목, 줄거리, 인물 설정과 장면별 사건 요약을 정하는 **구성**을 만들고, 이어서 장면을 하나씩 따로 씁니다. 장면을 쓸 때는 지금 쓸 사건, 뒤따를 사건, 직전까지 쓴 원고(최근 6개)를 함께 넘겨 앞 장면에서 이어 쓰고 뒤 사건을 앞당기지 않게 합니다. 긴 응답이 뒤로 갈수록 같은 내용을 되풀이하던 문제를 피하려는 구조입니다.

집필은 서버의 작업으로 실행합니다. 장면 하나를 쓸 때마다 작품 파일에 저장하므로 화면을 닫거나 다른 페이지로 가도 계속 쓰고, 다시 열면 진행 중인 작업을 이어서 보여 줍니다. 중간에 실패하거나 중단해도 쓴 장면은 남고, 아직 쓰지 않은 구성은 작품에 보관합니다. **이어 쓰기**를 누르면 남은 구성의 다음 순서부터 쓰고, 구성을 다 쓴 뒤에는 줄거리를 따라 자유롭게 이어 씁니다. 작업 상태는 서버 메모리에 두므로 웹 서버를 재시작하면 진행 중인 작업은 끝나고, 그때까지 쓴 장면과 남은 구성은 작품에 남습니다.

로컬 모드는 집필 작업 하나에 엔진 프로세스 하나를 쓰고 작가 모델을 한 번만 불러옵니다. 구성과 모든 장면을 같은 프로세스가 차례로 답하며, 작업이 끝나면 프로세스를 종료해 메모리를 반환합니다. 장면마다 모델을 다시 불러오던 때와 비교한 시간은 아직 재지 않았습니다.

### 참고 자료

참고 자료실(`/studio/materials`)에 올린 `.txt`, `.md` 파일은 약 900자 단위로 나누어 EmbeddingGemma 2로 임베딩하고 LanceDB에 저장합니다. LanceDB는 별도 서버 없이 `.data/materials/index` 폴더의 파일로 동작합니다. 작품에서 자료 묶음을 고르면 구성과 각 장면을 쓰기 전에 그 묶음에서 필요한 부분을 골라 작가 모델의 입력에 넣고, 장면에는 참고한 자료의 제목을 남깁니다.

자료를 올릴 때 원고에 넣는 방식을 고릅니다.

| 방식           | 쓰임                                         | 넣는 방법                                                                                                                        |
| -------------- | -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 관련 부분 검색 | 설정집, 취재 메모처럼 분량이 많은 자료       | 쓰는 장면과 가까운 구간을 의미 검색과 키워드 검색으로 각각 24개 찾아 순위를 합치고, 자료 하나에서 최대 2개씩 모두 6개를 넣습니다 |
| 항상 포함      | 인물 설정처럼 매번 필요한 6천 자 이하의 자료 | 고른 묶음의 자료를 요청마다 넣습니다. 합쳐서 6천 자를 넘는 뒷부분은 넣지 않습니다                                                |
| 문체 참고      | 본받을 문장이 담긴 글                        | 주제와 관계없이 구간 2개를 무작위로 뽑아 문체 견본으로 따로 넣습니다                                                             |

키워드 검색은 두세 글자 단위로 색인합니다. 한국어는 조사가 붙어 단어 단위로는 인물 이름이나 고유 용어를 놓치기 쉽기 때문입니다.

자료 목록과 본문이 기준이고 검색 색인은 거기서 다시 만들 수 있는 결과물입니다.

- 목록은 `.data/materials/catalog.json`, 본문은 `.data/materials/files`에 있습니다. 색인을 지워도 **색인 시작**으로 다시 만듭니다
- 자료를 올리면 바로 목록에 등록하고 색인은 뒤에서 진행합니다. 화면에서 진행 상황을 보고 중단할 수 있으며, 중단하거나 실패한 뒤 다시 시작하면 남은 자료부터 이어서 색인합니다. 색인한 자료만 원고에 쓰입니다
- 색인은 어떤 임베딩 모델 revision과 분할 기준으로 만들었는지 기록합니다. 둘 중 하나가 바뀌면 전체를 다시 색인해 서로 다른 벡터가 섞이지 않게 합니다
- 삭제는 색인에서 먼저 지운 뒤 목록에서 지웁니다. 색인 삭제가 실패하면 목록에 남아 다시 시도할 수 있습니다
- 색인 중에는 다른 로컬 생성 작업을 실행하지 않습니다

파일이 많으면 브라우저로 올리지 않고 `.data/materials/inbox/<묶음 이름>/` 폴더에 넣은 뒤 자료실의 **폴더에서 가져오기**를 누릅니다. 관련 부분 검색 자료로 등록하며 넣어 둔 파일은 지우지 않습니다. 이미 등록한 파일은 건너뜁니다.

- 자료 하나는 30만 자까지이며 더 긴 파일은 번호를 붙여 여러 자료로 나눕니다. 자료는 20,000개까지 저장하고, 묶음을 열면 최근 200개를 보여 줍니다
- 같은 묶음에 같은 제목과 분량의 자료가 있으면 건너뛰므로, 일부만 올라간 뒤에도 같은 파일을 다시 선택해 이어서 올릴 수 있습니다
- 구간이 10만 개를 넘으면 색인 정리 때 벡터 색인을 만듭니다. 그 전에는 전수 비교로 검색합니다
- 작가 모델에는 자료를 사실, 설정, 용어와 분위기의 근거로만 쓰고 문장을 그대로 옮기지 않도록, 문체 견본은 호흡과 어휘만 본받도록 지시합니다. 다만 모델이 이 지시를 항상 지킨다고 보장하지 않으므로, 남의 글을 자료로 썼다면 결과를 직접 확인해야 합니다
- PDF, 문서 파일, 이미지 자료는 지원하지 않습니다. 검색 품질과 색인 시간은 아직 평가하지 않았습니다
- 참고 자료 검색은 로컬 모드에서만 동작합니다

### 다른 도구에서 만든 이미지

장면의 **프롬프트 복사**는 그림체, 화면 비율, 인물 설정과 장면 묘사를 한국어 프롬프트로 복사합니다. 다른 이미지 도구에서 만든 PNG, JPG, WebP 파일을 **이미지 가져오기**로 넣으면 브라우저가 작품 비율에 맞춰 가운데를 기준으로 잘라 PNG로 저장합니다(16:9는 1920×1080). 가져온 이미지도 영상의 첫 프레임과 인물 기준으로 쓸 수 있습니다. 변환 과정에서 원본 파일의 메타데이터는 남지 않으므로, AI로 만든 이미지라는 표시가 필요한 곳에는 직접 표시해야 합니다.

## 목소리 학습

기존 설치에서는 아래 명령으로 약 2.3GB의 공개 Base 모델을 추가로 준비합니다. 기본 전체 설치에도 포함됩니다. API 키나 외부 음성 서비스는 필요하지 않습니다.

```sh
yarn workspace @story-studio/web local:setup:voice
```

1. 작업실의 **목소리 학습**에서 목소리 이름을 만듭니다
2. 같은 사람의 녹음 2~50개와 녹음에서 실제로 읽은 대본을 등록합니다
3. 녹음과 대본을 저장하고 반복 횟수를 정한 뒤 **새 학습 시작**을 누릅니다
4. 완료 후 작업실의 장면에서 목소리를 선택하고 한국어 음성을 생성합니다

음성 파일이 없으면 같은 화면의 **마이크로 녹음 시작**을 사용합니다. 처음에는 브라우저에서 이 사이트의 마이크 사용을 허용합니다. 하단의 **녹음 마치기**를 누르면 미리듣기와 대본 입력 항목이 추가됩니다. 30초가 되면 자동으로 마치며 WAV는 24kHz 모노로 준비합니다. **녹음과 대본 저장**을 누를 때 기존 로컬 저장 API로 전송하고, 취소하거나 화면을 나가면 마이크 트랙과 타이머를 해제합니다. 마이크를 지원하지 않거나 권한이 거부된 환경에서도 기존 파일 선택을 사용할 수 있습니다. [브라우저 녹음 API](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder)

각 녹음은 1~30초, 10MB 이하입니다. WAV, MP3, M4A, FLAC, OGG와 WebM을 로컬에서 24kHz 모노 WAV로 변환합니다. 긴 녹음을 자동으로 자르지 않으므로 대본과 음성이 어긋나지 않습니다. 배경 음악과 다른 화자가 없는 자료를 사용하세요. 파일 저장이 일부 실패해도 대본과 녹음 ID를 유지하고 같은 요청을 재시도해 중복을 피합니다.

이 기능은 샘플 음성을 참조하기만 하는 복제가 아닌 **실제 QLoRA 가중치 미세학습**입니다. 4비트 기본 모델은 고정하고, talker와 code predictor의 attention q/v에 rank 8, alpha 16 어댑터 1,810,432개 파라미터를 학습합니다. 전체 17억 파라미터를 재학습하는 방식은 아닙니다. 화자 특징도 함께 저장해 이후 합성에서는 참조 녹음을 다시 넣지 않습니다. 한국어 추론 prefix, 이전 프레임의 16개 코드와 잔여 코드 teacher forcing을 사용하며, MLX Audio 0.6.5 인터페이스에 맞춘 앱 자체 학습 구현입니다. [공식 Qwen SFT 구현](https://github.com/QwenLM/Qwen3-TTS/tree/main/finetuning)과 실행 환경은 다릅니다.

첫 단계, 5단계마다, 마지막 단계에 어댑터와 AdamW 계산 상태를 원자적으로 저장하고 마지막 체크포인트 두 개를 보관합니다. 화면을 나가거나 웹 서버를 재시작해도 시작한 Python 학습은 계속될 수 있습니다. **학습 중단** 후 **이어서 학습**을 선택하면 저장된 지점부터 진행합니다. 컴퓨터가 종료되면 자동으로 계산을 재시작하지 않습니다. 녹음이나 대본이 바뀌었거나 기본 모델 revision이 다르면 이어서 학습하지 않고 새 학습을 요구합니다. 학습 중에는 다른 로컬 모델 생성을 동시에 실행하지 않습니다.

실제 M5 Pro 48GB에서 합성 음성 두 개로 학습, 중단, 체크포인트 재개, 총 6단계 완료 후 새 프로세스에서 8.64초 한국어 합성을 확인했습니다. 이 실행의 MLX 최대 할당은 5.69GiB였습니다. 이 수치는 이 두 짧은 녹음의 결과이며 큰 데이터셋의 상한이 아닙니다. 합성 자료의 동작 검증이며 사용자의 목소리 유사도나 발음 품질을 검증한 결과는 아닙니다. 손실 값은 서로 다른 녹음 사이의 품질 비교 지표로 사용하지 않습니다.

완료된 학습본에 보정 프로필을 적용한 경우 로컬 Qwen3-ASR로 대사의 포함 여부를 확인합니다. 빠진 구간만 제한된 횟수로 다시 생성하고, 확인되지 않는 결과는 새 음성으로 저장하지 않습니다. 이 기능은 보정한 실행에만 적용되며 [엔진 안내](apps/engine/README.md)의 선택 설치 모델을 사용합니다. 다른 컴퓨터로 옮긴 보정 학습본도 대사 확인 모델을 함께 준비해야 합니다.

말투 보정은 학습한 음색과 함께 원음·대본을 문맥으로 사용해 말 빠르기와 억양을 참고합니다. 기준 원음은 해당 실행 폴더에서 해시로 검증하며, 요청한 대사에도 같은 누락 검사를 적용합니다. 사람과 똑같은 억양을 보장하는 기능은 아니므로 원음과 생성 음성을 함께 비교해야 합니다.

기본 음색 9종은 소희, 라이언, 에이든, 세레나, 비비안, 푸, 안나, 에릭, 딜런입니다. 차분함, 자연스러움, 밝음, 단호함의 말투를 선택할 수 있습니다. 한국어 기본값은 소희이며 다른 언어 기반 음색의 한국어 품질은 같다고 보장하지 않습니다.

## 성능과 자원 사용

큰 부하는 웹 서버보다 로컬 영상 모델 계산에서 발생합니다. 영상은 Wan2.2의 24fps로 장면 길이만큼 생성하되, 품질별 최대 프레임보다 긴 장면은 생성한 프레임을 늘려 재생합니다. `빠른 초안`은 낮은 해상도와 적은 생성 프레임을 사용하므로 움직임의 세밀함과 화질에 차이가 있습니다.

| 품질      | 영상 설정 (16:9)                | 늘리지 않는 최대 길이 | 장면 이미지 (16:9) |
| --------- | ------------------------------- | --------------------- | ------------------ |
| 빠른 초안 | 832×480, 최대 49프레임, 12단계  | 약 2초                | 1024×576, 4단계    |
| 표준      | 1280×704, 최대 81프레임, 30단계 | 약 3.4초              | 1360×768, 4단계    |

이 설정은 아직 실제 모델로 측정하지 않았습니다. 이전 Wan2.1 1.3B는 2026-11-15 M5 Pro 48GB에서 13초 초안 장면에 53.55초, MLX 최대 할당 13.58GiB였습니다. Wan2.2 5B는 모델이 더 커서 같은 장면에 더 오래 걸릴 것으로 예상하므로, Apple Silicon에서 시간과 최대 할당을 다시 재고 이 표를 갱신해야 합니다. MLX 할당량은 전체 시스템 메모리나 다른 앱의 사용량과 다릅니다.

- T5 인코더의 가중치를 공식 Wan 설정과 같은 bfloat16으로 유지하고 영상 복원을 작은 구역으로 나눕니다
- 모델 작업은 한 번에 하나만 실행합니다. 중복 요청은 모델을 추가로 올리기 전에 거절하며, 완료 후 자식 프로세스 종료로 모델 메모리를 반환합니다
- CPU 작업의 우선순위와 ffmpeg 스레드 수를 낮춥니다. 영상 생성은 작업실에서 중단할 수 있습니다
- 작품 저장은 마지막 입력 후 500ms에 바뀐 작품만 보내고, 화면 이탈과 새로고침 때 저장하지 못한 편집을 보관했다가 다음에 보냅니다
- 같은 영상 상태는 작품 객체를 다시 만들지 않습니다. 숨긴 탭은 조회를 쉬며 다음 조회는 10초 간격입니다
- 이어쓰기는 작품 ID만 보내고 서버가 작품 파일에서 최근 6개 장면을 작가 모델에 넘깁니다. 첫 장면 뒤의 영상과 음성은 필요할 때 불러옵니다
- 외부 웹 폰트 요청을 제거하고 설치된 한글 글꼴을 사용합니다

`mx.set_memory_limit`은 엄격한 상한이 아닌 할당 가이드입니다. 원고 모델에는 24GB를 지정하지만 이를 24GB 메모리 제한이 보장된다고 해석하지 않습니다. Gemma 4 31B의 가중치는 약 17GiB이며 실제 최대 할당은 아직 재지 않았습니다. [MLX 문서](https://ml-explore.github.io/mlx/build/html/python/_autosummary/mlx.core.set_memory_limit.html), [공식 Wan T5 설정](https://github.com/Wan-Video/Wan2.1/blob/main/wan/configs/shared_config.py)

## 저장과 복구

작품은 `.data/projects`에 작품마다 파일 하나로 저장하며 최대 200개까지 둡니다. 브라우저는 작품의 사본을 편집하고 마지막 입력 0.5초 뒤에 바뀐 작품만 저장합니다. 저장할 때 자신이 읽은 판을 함께 보내므로, 집필 작업이나 다른 창이 먼저 바꾼 작품은 덮어쓰지 않고 저장된 내용을 다시 불러옵니다. 저장하기 전에 화면을 닫으면 저장하지 못한 편집을 브라우저에 잠시 보관했다가 다음에 열 때 먼저 보냅니다. 읽을 수 없는 작품 파일은 지우지 않고 개수로 알립니다.

이전 버전에서 브라우저(`story-studio.library.v1`)에 저장한 작품은 처음 열 때 `.data/projects`로 옮기고, 원본은 `story-studio.library.v1.moved`로 남깁니다. 같은 작품이 이미 있으면 저장된 쪽을 유지합니다. 이전 저장본이 손상되어 읽지 못하면 그대로 두고 알립니다.

개인 생성 파일은 앱의 `.data/assets`, 영상 상태는 `.data/tasks`, 모델과 설치 환경은 `.data/local`에 있습니다. 참고 자료는 `.data/materials`에 본문(`files`), 목록 정보(`documents`), 검색 색인(`index`)으로 나누어 저장합니다. `STORY_STUDIO_DATA_DIR`로 전용 저장 폴더를 지정할 수 있습니다. 이 폴더, 로그, 모델 가중치와 `.env.local`은 Git에서 제외됩니다.

목소리 이름과 녹음별 대본은 `.data/voices`, 학습 실행과 가중치는 `.data/voice-training/runs`에 저장합니다. 목소리를 다른 컴퓨터로 옮길 때는 두 폴더와 `.data/assets`, 동일 revision의 Base 모델을 함께 보존하세요. 작품 JSON 백업에 목소리 가중치는 포함되지 않습니다.

**작품 파일과 JSON 백업에는 미디어 자체가 포함되지 않습니다.** 다른 컴퓨터로 옮길 때 `.data/projects`와 `.data/assets`를 함께 옮기거나 PNG, MP4와 WAV를 별도로 받으세요. 작품 삭제는 작품 파일만 지우며 생성 파일을 자동으로 삭제하지 않습니다.

영상 생성은 Python 프로세스가 진행 상태와 결과를 디스크에 원자적으로 저장합니다. 새로고침 뒤에는 기존 작업을 조회합니다. 서버 재시작 중에도 이미 시작한 비동기 영상 프로세스는 진행할 수 있지만 컴퓨터 종료나 강제 종료는 복구 실행되지 않습니다. 종료된 작업은 실패로 표시하고 새로 생성할 수 있습니다. 조회의 일시적 실패 때는 새 요청 없이 기존 작업을 다시 확인합니다. 모델 실행 제한과 자동 확인 제한은 60분입니다.

실행 중에는 `HF_HUB_OFFLINE`, `TRANSFORMERS_OFFLINE`을 적용하고 원격 코드 실행을 끕니다. 기본 로컬 모드에 외부 내용 심사 API는 없습니다. 모델에 학습된 응답 거절 성향은 남을 수 있으며 모든 콘텐츠에 대한 응답을 보장하지 않습니다. 기존 클라우드 어댑터는 명시적으로 `STORY_STUDIO_PROVIDER=cloud`일 때만 선택합니다.

## Gemma에 직접 질문하기

일반적인 기본 설치에서 앱 폴더를 연 뒤 실행합니다. 작업실의 원고용 시스템 지시문과 JSON 응답 제약을 사용하지 않습니다.

```sh
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 \
.data/local/.venv/bin/python -m mlx_vlm.generate \
  --model .data/local/models/text-gemma-4-31b-it-4bit \
  --prompt "한국어로 답해줘. 여기에 원하는 질문을 입력하세요" \
  --thinking-mode disabled --max-tokens 512
```

연속 대화는 `--chat`을 덧붙입니다. 이 명령은 작업실과 별도의 모델 프로세스를 실행하므로 작업실의 생성이 끝난 뒤 사용합니다. 저장 경로를 바꿨다면 가상환경과 모델 경로도 같은 경로로 지정하세요.

## 검증

```sh
yarn workspace @side/story-studio check
yarn workspace @side/story-studio test:e2e --workers=2
yarn workspace @side/story-studio build
```

Python 엔진의 모델 없는 검사도 위 `check`에 포함됩니다. 별도 실행은 `yarn workspace @story-studio/engine check`입니다. 실제 MLX 가중치 변경·기본 가중치 보존·옵티마이저 복원 검사는 [엔진 개발 안내](apps/engine/README.md)의 Apple Silicon 명령을 사용합니다. MLX가 없는 환경의 검사는 이 한 가지 네이티브 검사를 명시적으로 건너뜁니다.

Vitest는 로컬 기본값, 키 미전달, 오프라인 환경, 동시 생성 차단, 프로세스 중단, 실패 후 재시도, 원고 검증, 자산 범위 요청과 상태 변경 시의 참조 보존을 확인합니다. 구성과 장면별 집필 요청, 참고 자료 검색 요청, 자료 저장과 실패 후 정리, 가져온 이미지 저장도 확인합니다. 참고 자료의 임베딩과 LanceDB 검색 자체는 모델과 패키지가 필요해 CI에서 실행하지 않습니다. 모델 계산은 가벼운 자식 프로세스나 모의 응답으로 대체합니다. Playwright는 별도 포트 3411, `.e2e-build`, 별도 저장 폴더에서 모바일과 데스크톱의 편집, 백업, 실패 복구, 영상 및 음성 재생을 확인합니다. 작품 저장소는 테스트마다 같은 저장 계약을 따르는 메모리 대역으로 바꿔 서로의 작품이 섞이지 않게 하고, 실제 파일 저장소와 집필 작업은 Vitest로 확인합니다.

실제 모델로 만든 [공개 예시](apps/web/public/examples/project.json)는 약 13.4초의 한국어 음성 및 자막 포함 MP4입니다. Qwen 원고, Qwen3-TTS 음성과 이전 영상 모델인 Wan2.1 1.3B의 생성 프레임을 ffmpeg로 합쳤으며 정지 이미지 이동 효과로 대체하지 않았습니다. 모델의 미적 품질이나 인물 일관성에 대한 광범위한 평가는 하지 않았습니다.

첫 오프라인 화면 검사에서 Google Fonts 요청이 확인됐고 외부 폰트를 제거한 뒤 다시 검사했습니다. 추가 검사 결과와 최신 CI 상태는 PR에 기록합니다. 모델 가중치는 CI에서 다운로드하지 않습니다.

## 행동 측정과 접근 경계

로컬 기본 설정은 측정 키가 없어 SDK를 로드하거나 이벤트를 전송하지 않습니다. 측정을 명시적으로 구성한 경우에만 `landing_start_clicked`, `studio_opened`, `studio_request_clicked`, `studio_request_succeeded`를 보냅니다. 속성은 고정된 진입 종류와 작업 종류뿐이며 원고, 제목, 인물, 파일명, 경로와 사용자 ID를 수집하지 않습니다. 영상의 HTTP 제출 성공은 영상 계산 완료와 구분합니다.

원고 요청의 작업 종류는 새 작품 집필(`write`)과 이어 쓰기(`continue`)입니다. `studio_request_succeeded`는 서버가 집필 작업을 받았다는 뜻이며, 작업이 끝난 결과는 `studio_writing_finished`의 고정된 `status`(succeeded, failed, cancelled)로 따로 남깁니다. 화면을 닫은 뒤 끝난 작업은 이 이벤트를 남기지 않습니다. 참고 자료실 진입은 속성 없는 `studio_materials_opened`, 자료 추가와 삭제, 폴더 가져오기, 색인 시작과 중단은 기존 요청 이벤트의 `material-add`, `material-delete`, `material-import`, `material-sync`, `material-stop`, 자료 묶음 선택은 `studio_collection_clicked`의 고정된 `action`(select, clear)으로 측정합니다. 묶음 이름, 자료 제목과 본문은 보내지 않습니다. 외부 이미지 가져오기는 요청 이벤트의 `image-import`, 프롬프트 복사는 `studio_prompt_clicked`의 `action`(copy)이며 프롬프트 내용은 보내지 않습니다.

인물 기준 지정은 `studio_reference_clicked`의 고정된 `action`(set, clear)으로만 측정합니다. 브라우저 원고만 바꾸는 동작이라 서버 성공 이벤트는 없습니다. 기준 이미지를 참고한 생성의 요청과 성공은 기존 `studio_request_clicked`, `studio_request_succeeded`의 `image`로 남으며, 장면 ID와 이미지 경로는 보내지 않습니다.

이 앱은 127.0.0.1에 바인딩된 개인용 도구입니다. 네트워크 공개, 공동 작업과 로그인은 이번 범위에 포함하지 않습니다. 공개 서비스로 전환하려면 인증과 작품 소유권을 별도로 설계해야 합니다.

직접 녹음은 `studio_recording_clicked`의 고정된 `action`(start, stop, cancel), `studio_recording_started`와 `studio_recording_completed`의 고정된 `source`(microphone)로만 측정합니다. 클릭, 실제 마이크 시작, 로컬 WAV 준비 완료를 구분하며 서버 저장 성공은 기존 `studio_request_succeeded`의 `voice-upload`입니다. 녹음 내용, 대본, 파일명과 장치 정보는 보내지 않습니다.
