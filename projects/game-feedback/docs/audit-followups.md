# API 감사 후속 결정 (2026-10-28)

[API 감사 #108](https://github.com/jingeon27/side-project/pull/108)의 숫자는 초기 운영값으로 유지한다. 코드의 제한 단위와 화면 동작을 검토한 판단이며, 운영 트래픽이나 부하 시험으로 용량을 입증한 결과는 아니다.

| 항목                        | 유지할 값                    | 판단과 조정 기준                                                                                                                            |
| --------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 게시물·프로필 문서/RSC 조회 | 주소당 분당 240회            | 초당 평균 4회이며 prefetch도 포함한다. 같은 NAT의 이용자가 공유하므로 정상 방문의 429가 반복되면 주소 제한을 조정한다.                      |
| 내부 읽기 / 내부 상세 조회  | 각각 분당 3000회             | 캐시 미스가 공유하는 예산이다. 방문자 제한과 별개이며 두 버킷을 합치지 않는다. 여러 인스턴스의 전체 용량을 보장하는 값은 아니다.            |
| Supercell 조회              | 사용자 또는 주소당 분당 10회 | 미리 보기·계정 저장·온보딩이 같은 예산을 써 우회가 없다. 서버 전체의 upstream 호출 상한은 아니므로 실제 외부 한도와 오류율을 확인해야 한다. |
| 업로드 완료 유예            | presign 만료 후 30분         | 느린 전송과 완료 재시도를 허용한다. S3 POST 서명의 수명을 늘리는 값은 아니며, 완료할 때 소유권·HEAD 검증은 유지한다.                        |
| SSE 연결                    | 세션당 4개, 사용자당 8개     | 웹 탭과 앱의 동시 사용을 허용하고 초과하면 오래된 연결을 닫는다. 프로세스별 제한이므로 여러 API 인스턴스에서는 합산 상한이 아니다.          |
| 저장 게임 계정              | 최근 5개                     | 초기 알파에서 유지한다. 6번째 저장은 오래된 계정을 제거하므로 여러 계정을 관리하는 실제 수요가 있으면 정책을 다시 정한다.                   |
| 익명 조회수                 | 게시글·주소별 24시간 5회     | 페이지 접근 제한이 아니라 조회수 집계 상한이다. NAT에서 실제 방문을 적게 셀 수 있으므로 고유 방문자 수로 해석하지 않는다.                   |
| 답변 페이지                 | 30개                         | 이어 보기 계약이 있어 응답 크기를 제한하면서 나머지 답변도 볼 수 있다.                                                                      |
| 관리자 문의 페이지          | 앱 20개 / API 기본 12개      | 앱이 크기를 명시하고 커서로 이어 받으므로 기본값을 맞추기 위한 변경은 필요하지 않다.                                                        |

프로필 편집은 정보·사진·링크 중 저장하지 않은 변경이 있으면 다른 화면으로 가기 전에 확인한다. 취소하면 입력을 유지하고, 각 영역을 저장하거나 값을 원래대로 돌리면 해당 초안은 이탈 확인의 원인에서 빠진다. 링크·상단 돌아가기·브라우저 기록 이동·앱의 화면 열기/돌아가기를 같은 확인에 연결한다. 새로고침·탭 닫기는 브라우저가 제공하는 기본 확인 문구를 사용한다.

웹에서 참조하지 않는 `demoLoginMutationOptions`, `testAccountLoginMutationOptions`, `testAccountListOptions`와 이 옵션만 사용하던 API 래퍼·입력 타입을 제거한다. API·SDK의 데모/테스트 인증은 테스트 실행과 명시적 데모 모드에서 사용하므로 유지한다.

## 검증

- `yarn workspace @game-feedback/web typecheck`, `lint` 통과.
- `yarn workspace @game-feedback/web test` 통과: 75개 파일, 256개 테스트. 이탈 취소 시 초안 보존, 브라우저 기록 복구, 저장 후 확인 해제, 정보·사진·링크 각각의 초안을 포함한다.
- `test:e2e e2e/navigation.spec.ts`는 API 준비 단계의 `S3 media storage requires a bucket and valid S3 settings.`로 실행되지 못했다. 테스트 DB는 격리된 worktree의 전용 포트에서 시작했고 확인 후 종료했다. 실제 브라우저·WebView 확인은 완료로 기록하지 않는다.
- API 제한값은 바꾸지 않았으며 실제 서비스의 부하·S3·Supercell 검증은 수행하지 않았다.
