# 조사 페이지

- 기존 웹의 디자인 토큰과 `@side/design-system`의 버튼 및 하단 행동 영역을 사용한다. `EvidenceCaseBriefing`은 사건 소개, `InvestigationTimeline`은 눌러 이동하는 진행도에 사용한다.
- 사건마다 `apps/web/cases/<slug>/index.html`을 둔다. 빌드가 이 디렉터리를 읽는다. 앱 라우트와 사건 목록에 등록하고 제목, 소개, 표지, 설명 메타데이터를 맞춘다. 공유 주소는 사건 소개에서 열리고 이어서 조사를 선택할 수 있어야 한다.
- 320×568px부터 사건 시작, 단서, 주요 조작 버튼을 확인한다. 제목은 짧게 두고 증거를 넓게 보여 준다. 작은 글자와 색에만 의존하는 단서는 텍스트로도 읽을 수 있게 한다. 단서 확인 뒤 다음 버튼을 강조하고 이동은 사용자가 선택하게 한다.
- 조사 단계는 `createInvestigationFunnel`의 브라우저 히스토리에 둔다. 진행은 사건별 키에 저장하고 query와 hash는 이동과 함께 유지한다. 오답 피드백은 확인할 증거를 가리키고 입력을 유지한다.
- 기존 Amplitude 이벤트에 사건 ID와 단계, 우선 이동 여부, 유입 출처를 연결한다. 이벤트에는 정해진 속성과 값만 전송한다. 키가 없는 환경에서 전송이 생략되는 계약을 지킨다.

타입 검사, 제작 빌드와 기존 사건의 브라우저 회귀 테스트를 실행한다. 새 사건은 모바일 직행 주소, 조사 시작, 타임라인 이동, 오답 후 재시도, 새로고침 후 복구를 검증한다.
