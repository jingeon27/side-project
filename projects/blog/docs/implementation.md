# 구현과 검증 기록

## 범위와 결정

- `jingeon27/side-project`의 `feat/blog-mdx-migration` 브랜치와 별도 Git worktree에서 구현했다. 앱은 `projects/blog/apps/web`, 집계 workspace는 `@side/blog`다.
- 기존 Yarn 4 workspace 패턴과 공용 TypeScript 설정을 사용했다. 다른 프로젝트의 소스와 실행 중인 서버는 변경하지 않았다.
- Next.js 16.4·React 19·TypeScript 5.9·Tailwind 4·next-intl·`@next/mdx`·Shiki를 사용한다. UI와 도메인은 FSD 레이어로 나누고 ESLint로 상위 레이어 import를 제한한다.
- 이번 요청에 따라 개발 계획의 마이그레이션 제외 조건을 변경했다. 티스토리에 공개되어 있고 `resume/blog`에 대응 파일이 있는 27편만 공개 원문에서 가져왔다. 비공개 수정본과 미발행 초안은 복사하지 않았다. 이후 요청받은 문장·이미지 수정은 저장소의 MDX에 반영했다.
- 한국어 27편과 영문 번역 27편을 제공한다. 언어별 본문·제목·검색 설명·목차와 고정 주소를 사용하고, 상세에서 같은 글의 다른 언어로 이동한다. 번역이 없는 새 글에 대한 안내도 유지한다.

## 통합 검색 검증 (2026-10-17)

## 본문과 이미지 편집 검증 (2026-10-17)

장식형 커버 5장과 목록에서 읽기 어려운 세로 도표 썸네일 5장을 글 주제에 맞는 SVG 도해로 바꿨다. 커버는 같은 SVG를 1280×720 PNG로 렌더링해 본문·목록·OG에 연결했다. 본문 설명용 도표 27장은 유지했다. 기존 이미지 32장과 체크섬은 보관하고, 교체한 5장의 경로는 `content/image-replacements.json`에 명시했다. 최초 가져오기 스크립트를 편집본 위에 덮어쓰지 않도록 지침도 보완했다.

콘텐츠·TypeScript·ESLint·Prettier, Vitest **64개**, Production build(정적 페이지 **98개**), 데스크톱·모바일 Playwright **36개**를 통과했다. 코드 블록 180개와 원본 이미지 32장의 체크섬, 교체 경로, 커버 로딩과 OG 일치, 한국어·영어 날짜 표기를 확인했다. 데스크톱과 390px 모바일 다크모드에서 본문 이미지와 표를 직접 확인했고, 가로 넘침과 브라우저 오류가 없었다.

기존 `/sitemap.xml`은 중복 없는 URL 166개를 제공하며 한국어·영어 글 54개와 홈·목록·소개·카테고리·태그를 포함한다. 글별 수정일과 실제 번역 주소를 유지했다. `/robots.txt`가 `/_next/` 전체를 차단하던 규칙을 제거해 렌더링에 필요한 JS·CSS·이미지 접근을 허용하고 `/api/`만 제외한다. 사이트맵 주소는 `SITE_URL`을 기준으로 제공하며 운영 도메인 변경 시 재빌드하도록 문서화했다.

콘텐츠·TypeScript·ESLint·Prettier, Vitest **67개**, Production build(정적 페이지 **174개**), 데스크톱·모바일 Playwright **38개**를 통과했다. 실제 XML 파싱으로 54개 글 주소·수정일·양방향 번역 연결과 URL 중복을 검사하고, 두 루트 경로의 리다이렉트 없는 200 응답·Content-Type, robots의 사이트맵 주소와 공개 페이지·렌더링 파일 수집 허용을 확인했다.

## 사이드 프로젝트 설계 글 추가

사용자가 공유한 설계 대화와 로컬 Codex 세션의 사용자 요청, 실제 Git 기록을 바탕으로 `side-project-design` 글을 작성했다. 한국어 제목은 「사이드 프로젝트 저장소를 만들고 서비스를 늘려 간 과정」이며 전체 영문판도 제공한다. 여러 분야를 서비스에 필요한 수준까지 다루며 여러 아이디어를 병렬로 기획하고 출시해 보려는 작성자의 동기에서 시작해, 모노레포와 공통 패키지를 선택한 이유로 이어진다. 사진 대회 초기 구성(`0f09b13`), 통합 사진 피드(`1a78b1a`), 공통 린트 규칙(`27255a5`)과 preset 정리(`617d837`), `develop` 기준 브랜치 운영과 후속 서비스 추가를 다룬다. 게임 피드백의 첫 답변 검증과 REST 선택, 계정 확인, MDX 운영, 프로젝트 격리도 포함한다. 본문은 작성자의 경험과 결정으로 서술하며, 가운데 점과 장식용 구분자를 사용하지 않았다. 사용자 모집이나 실제 배포를 완료한 성과로 표현하지 않았다.

한국어 본문과 소제목은 해요체를 사용한다. 저장소, 사진 서비스, 게임 피드백, 블로그, 공통 린트, 디자인 시스템과 develop의 GitHub 링크 7개를 두 언어에 연결했고 모두 HTTP 200을 확인했다. 게임 피드백과 디자인 시스템은 기능 브랜치가 삭제되어도 읽을 수 있도록 확인한 커밋의 코드로 연결했다.

언어별 SEO, 고정 slug와 번역 연결, 프로젝트와 공통 패키지를 그린 SVG 썸네일을 추가했다. 썸네일은 목록 매핑으로 연결하고 공유 이미지는 기존 PNG 생성 경로를 사용한다. 제목과 소제목을 고친 뒤에도 기존 한국어와 영어 글 URL을 유지했다.

콘텐츠 검증(언어별 본문 **56개**, 정적 import **56개**, 기존 리다이렉트 **27개**), TypeScript, ESLint, Prettier, Vitest **67개**, Production build(정적 페이지 **180개**), 데스크톱·모바일 Playwright **38개**를 통과했다. 새 글의 1440px 데스크톱과 390px, 320px 모바일에서 썸네일 로딩, 목차 11개, 한영 전환과 테마 유지, 가로 넘침 없음을 확인했다. 공유 이미지는 기존 `/og/ko/side-project-design`의 PNG 생성 경로를 사용한다.

## 최초 발행일 표시와 소제목 정리

티스토리의 공개 원문 27편을 다시 조회해 `article:published_time`, 각 글의 `publishedAt`, 최초 이관 manifest가 모두 일치함을 확인했다. 기존 발행일을 보존하고 목록과 상세에 `발행`/`Published`를 명시했다. 상세의 `수정`/`Updated`와 구분하며 한국 시간을 기준으로 표시한다. [원문 대응표](migration.md)에 당시 발행일을 추가했다.

챗봇, 도메인 간 토큰 전달, TypeScript 패턴 세 글의 한국어와 영어 소제목에서 `0.`, `1.`, `9-1.` 같은 번호를 제거하고 번호로 다른 문단을 가리키던 본문도 고쳤다. 수정한 글의 `updatedAt`만 실제 편집 시각으로 갱신했다. 코드 예제와 원본 이미지의 무결성 검사는 유지한다.

전체 검증을 다시 통과했고, 추가 브라우저 확인에서 이관 글 54개 상세의 원문 발행 시각, 발행과 수정 표시, 번호 없는 소제목과 실제 목차 anchor를 확인했다. 1440px, 390px, 320px에서 기존 글의 날짜가 함께 표시되고 가로 넘침이 없었다. 이관 글 전체 확인 중 브라우저 오류도 없었다.

## 동의 배너 제거와 개인정보 처리 안내 (2026-10-26)

동의 배너와 화면 오른쪽 아래의 통계 설정 버튼을 없앴다. 모든 방문자에게서 GA4 방문 통계와 Clarity 히트맵·세션 재생을 수집하고(opt-out), 방문자는 개인정보 처리 안내의 ‘수집 끄기’로 이 브라우저의 수집을 끄거나 다시 켠다. 끄면 GA 쿠키를 지우고 전송을 멈추며 Clarity도 consentv2 denied와 stop으로 멈춘다. 저장 값은 `blog:analytics-consent`의 `denied` 하나이며, 이전 배너가 저장한 `granted`·`statistics`는 켜짐으로 읽는다. 저장소가 막히면 끄기 선택을 기억할 수 없으므로 수집하지 않는다.

Clarity에는 처음에 동의 신호를 보내지 않는다. Clarity가 EEA·영국·스위스 방문자에게 기본 동의 모드로 쿠키를 만들지 않도록 맡기기 위해서다. 끄기를 되돌린 경우에만 방문자의 직접 조작으로 보고 동의 신호와 함께 재개한다. GA4는 지역을 가리지 않으므로 유럽 방문자에 대해서는 규정상 위반 소지가 남는다. 중간에 한국 방문자 한정, 시간대별 동의 방식을 거쳤으나 배너 없이 모두 수집하기로 한 사용자 결정에 따라 정리했다.

수집 범위, 쿠키, 처리 위탁과 국외 이전, 보관 기간, 끄는 방법을 담은 `/ko/privacy`·`/en/privacy` 페이지를 추가하고 푸터에서 연결했다. 보관 기간 문구는 실제 서비스 설정을 확인해 구체화해야 하며 법률 검토는 거치지 않았다.

콘텐츠 검증, TypeScript, ESLint, Vitest **100개**, Production build(정적 페이지 **177개**), 데스크톱·모바일 Playwright **40개**를 통과했다. 분석 ID를 비운 CI와 같은 조건이다. 별도로 가짜 측정 ID로 빌드하고 외부 요청을 모두 차단한 Chromium에서 서울·베를린 시간대 모두 배너·떠 있는 버튼 없이 GA·Clarity를 로드하고 Clarity에 초기 동의 신호를 보내지 않음, 안내 페이지의 ‘수집 끄기’ 뒤 `denied` 저장·GA 비활성화와 다음 페이지의 외부 요청 0건, ‘다시 켜기’ 뒤 저장 값 제거를 확인했다. 실제 GA4·Clarity 대시보드 수신은 확인하지 않았다.
