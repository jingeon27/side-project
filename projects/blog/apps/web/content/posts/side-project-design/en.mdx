When building Pisik, Game Mate, and this blog, I chose the features and architecture and delegated implementation to an AI agent. I let it decide screen layouts and the implementation sequence. I tried the results and explained what I wanted changed. I skimmed the overall code structure, while the agent handled implementation details, test writing, and execution.

The first project was Pisik, a photo community whose directory is `photo-contest`. The idea came from a streamer's segment called a “Yeongdo contest.” I thought it would be fun for close friends to share funny photos and vote within their own groups.

I initially requested group invitations, photo submissions, and voting. The resulting screen showed group lists before photos, with long explanations over the images. I asked for those parts to change and specified behavior I had left open, including anonymous history and membership approval.

## I wanted photos before the group list on Pisik's home screen

The first home screen was mostly about choosing a group. I wanted the latest photos from my groups as soon as I entered. I asked for the group list to move to My Page and for photos to appear on the home screen.

It also felt limiting to stop posting when a contest ended. I requested ongoing posts without a submission period, support for videos and edited images, administrator deletion, and the month's popular posts.

I asked for guidance covering photos to be shortened and for a story-style border to be removed when there was no story feature. I also opened the desktop layout and requested changes to photo sizes, spacing, and placement.

On a public group's contest page, joining did not immediately show the button for publishing a post. Leaving the page and returning made it appear. I asked for posting to be available on the same screen after joining, and the membership update was changed to refresh posting permissions too.

The entry screen brings login, signup, and “Start anonymously” together. I left social login out so people could use the service without linking an external account. Anonymous visitors can browse public groups; private groups require an account and membership approval.

## Keeping anonymous activity after signup

I asked for someone who had posted and joined groups anonymously to keep that activity after signing up. Signup converts the existing anonymous profile into an account, preserving public-group memberships and authored content.

Logging out before signup makes that profile and its history inaccessible. Saying the history is deleted could imply that posts visible to others disappear too. I asked for the copy to explain that the author would lose access to the profile.

I also requested changes to the My Page explanation about a browser session. The logout confirmation now explains the loss of access first and asks people to sign up if they want to keep using their profile.

## Requiring approval even through a private-group invitation

Pisik has invitation links for bringing friends into groups. Forwarding a link should not expose private posts. I made public groups browsable before joining, while private groups require login and membership approval. I asked for those conditions to be checked on the server too.

I split management permissions between owners and moderators. Moderators can remove ordinary members; an owner must transfer ownership before leaving. I did not want to leave a group without anyone able to manage it.

Leaving or being removed does not automatically delete the member's posts and comments. I did not want conversations involving other members to disappear with them. Returning to a private group requires approval again.

## Defining contest submission and voting deadlines

Contests have upcoming, submission, voting, and completed phases. I asked for “Enter the contest” to appear only during submissions, but a form already open could still be sent after the deadline. Submissions could also close during an upload, so the server checks the time when saving.

A request arriving at the submission deadline belongs to voting, and one arriving at the voting deadline belongs to the completed phase. I chose the server clock for that decision.

Contest voting is limited to one vote per registered account. People cannot vote for their own or hidden entries. I delegated implementation and verification that simultaneous requests could not store two votes. I excluded anonymous profiles because they are easy to recreate; registered accounts alone do not prevent one person from creating several accounts.

I kept likes separate from contest votes and set a per-person limit on how many contest entries could receive a like. Results distinguish a tie for first place from a contest with no votes. Calling every zero-vote entry a joint winner seemed wrong, so winners only appear when the highest vote count is greater than zero.

When the guidance became long enough to cover photos, I asked for it to be shortened. The screen keeps the actions available now and the limits people need, while the server continues checking the agreed conditions.

## Handling cancelled photo selections and failed uploads

I asked for cancelling the file picker to preserve the existing selection. I also delegated checks for selecting the same file again and for a failed preview. Video support needed limits on file types, sizes, and duration too.

Someone could publish before an upload finished, use an expired upload, or leave the group in the meantime. I requested checks of file readiness and posting permissions when saving the post.

I did not want an upload failure to erase a post someone had already written. I asked for the screen to explain which step failed, preserve the input, and let that step be retried.

## Game Mate began with friend-add sales and coaching

In the Clash Royale communities I followed, overseas players used Twitter, while Korean players used KakaoTalk, DC Inside, and Naver Cafe. Getting added by top-ranked overseas players was difficult, and I often saw posts looking for someone to teach the game.

I wanted a place to find friend-add sales and coaching posts, compare their terms, and start a conversation. The Clash Royale communities I knew were also where I could reach initial users, so I chose to start with that game. I considered Brawl Stars and League of Legends but decided against supporting several games at the beginning.

Under Clash Royale, I added boards for friend-add sales and coaching alongside feedback, friendly matches, and general discussion. More games could use the same categories later. I left account trading out because of the risk.

Friend-add sales have a price field. Coaching posts can list an hourly fee, a fee for a fixed period, or a total fee until a goal is reached. Either students or coaches can post. The service provides listings and chat; I did not add payments.

I asked for an empty fee to appear as “Fee negotiable” instead of zero. Goal-based coaching asks for the target rating and the total fee until it is reached. I requested “Fixed period” instead of “Monthly,” and “Until the goal is reached” instead of “Target rating achieved,” so readers could distinguish a fixed duration from coaching through a target.

Payment and refunds remain between the users. I kept the screens from suggesting that the service processes payments. Pisik and Game Mate also have separate accounts and data: I did not see a need for people sharing photos and people seeking friend-add sales or coaching to use the same account.

## Adding reply notifications and Helpful to the feedback board

The feedback board needed people to answer questions. Game profiles and translated posts would not give someone a reason to return if their question went unanswered.

```text
Someone posts a question
  → Another player replies
  → The requester receives a notification
  → The requester reads it and marks whether it helped
```

I added reply notifications and the `Helpful` action after reading. I want to see how many requests receive at least one reply marked helpful. Several helpful replies on one request still count as one request. I also want to look at time to the first reply and the proportion answered within 24 hours.

I have not recruited people to answer yet. I am considering starting with five to ten people and manually connecting them to questions in the communities I know.

## Returning the stored message on a chat retry

A connection can drop after the server saves a message but before its response reaches the sender. The screen may show a failure. I asked for retrying to avoid storing a second copy.

Retries of the same message use the same request identifier. If the server has already saved it, it returns that result. Reusing the identifier for another conversation or different content is rejected.

I asked for read receipts to advance only through messages the client had confirmed. New messages can arrive after someone enters a conversation, so entering alone does not mark everything read. Clearing history affects the range removed from my view and leaves the other person's record intact.

When signing out and entering with another account, I asked for previous lists and late responses to stay off the screen. Account changes cancel active queries and clear the previous results.

## Choosing what remains after deletion or blocking

I did not want deleting a comment to erase someone else's reply. In Game Mate, replies by other people remain after the original comment is deleted. Account withdrawal separates clearing the departing author's content and personal information from preserving other people's answers and comments. Authors can also delete their own content after a moderator has hidden it.

Blocking prevents starting a new conversation and sending messages in an existing one. I delegated implementation and verification that those restrictions also apply when the other person initiates the request or calls the API directly.

I added reporting, but someone still needs to review submissions and act on them. The operational criteria for handling reports remain to be decided.

## Separating game profile lookup from ownership verification

Game profiles load from a Player Tag. Someone can enter another player's tag, so I asked for a successful lookup to carry no ownership verification. Connected profiles start unverified, and an administrator-verified user status is separate from game-account ownership.

I originally intended to save a deck and game-information snapshot with each post. I later chose to register game profiles on the user account and asked for deck attachments to be removed from the writing screen. Profile verification requests start a one-to-one chat with an administrator.

Changing the primary game tag clears the existing verification and requires another review. A status checked for the old tag must not carry over to a new one. I also asked for unavailable game APIs and tags that cannot be looked up to be handled separately.

Connecting a game profile is optional at signup. People can look up their tag immediately or join with a nickname and the required agreements, then connect later.

As the form grew, I asked for a scrolling body with the completion button at the bottom. I checked short viewports to make sure inputs and buttons did not overlap.

Profile editing moved from an expandable section to a Bottom Sheet, then to a separate page in Game Mate. I asked for the fields to be editable in one place with a save action at the end. Web addresses in the bio also became clickable on the profile.

For mobile sheets, I requested Cancel beside Save instead of an X. The final field and buttons needed to remain reachable after scrolling.

Buttons, inputs, and dialogs use a shared [design system](https://github.com/jingeon27/side-project/tree/65c3d13a/packages/design-system). I requested separate layout and spacing adjustments so Pisik gave photos room and Game Mate made the game and author's situation easy to read.

## Showing a way back from directly opened links

Someone opening a post directly or arriving from another site may have no previous screen inside the service. I asked for a destination that would keep Back from simply taking them out of the service.

Contest details show the group and contest names in the header, with Back returning to the group. I asked for the group's Posts, Contests, and Hall of Fame tabs to be removed from that detail screen. Public profiles also show navigation in the header and keep the body for the profile.

For an action requiring login, I requested an explanation before leaving the screen, with cancellation keeping the current page. Completing login returns to the page the person was viewing.

## Making replies readable when posts are translated

I planned Game Mate for Korean, English, and Japanese. I initially requested translated menus and posts, but someone could answer a translated Korean question in Japanese, leaving the requester unable to read it. I requested reply translation too.

Language routes are in place, while translation features and running the service for each language still need work. The mobile app shares web screens through a WebView. I want to refine asking and reading replies on the web before handling app distribution and the stores.

## Asking for the resume to be removed from the blog

I originally kept my posts in a separate repository. Moving them over to Tistory to publish was cumbersome, and building a blog of my own had become less expensive, so I decided to make this one.

The agent also built a resume I had not requested. I asked for it to be removed and for the about page to keep only contact information. Korean and English editions appear only when an actual translation exists.

Switching languages in dark mode exposed a warning from rendering the theme initialization script. I compared direct URL entry with navigation inside the site and requested a fix.

## Skimming the code structure and giving feedback

While looking through folders and modules, I asked for imports into another feature's internal files to be corrected. I requested public entry points and gave feedback on where screen composition and data queries should belong.

Apollo or TanStack Query would own fetched values, while forms would own input in progress. I asked for wrappers that only called and returned a library query hook to be reduced, while keeping options that defined a request and its cache updates together. The agent implemented this feedback and checked the detailed logic and tests.

In Pisik, I requested a fix for a list error that remained after switching categories. The filter stayed usable, while changing the group, contest, or category reset that list's error.

I asked for recurring feedback to be reflected in `AGENTS.md` and task-specific skills. ESLint checks cover import boundaries and duplicated state, and I looked again at the revised structure and screens.

The API and cache choices, along with the server and database structure, are covered in [How I chose the technology for two side projects](/en/blog/choosing-the-stack-and-boundaries-for-two-side-projects).

## Delegating checks for search entry points and shared links

I asked for Game Mate's public posts to have titles, descriptions, canonical URLs, share images, and structured data. I delegated verification that posts and comments remained readable without JavaScript. The sitemap includes public posts and profiles, while chat and settings pages are excluded from indexing.

Public posts cache responses fetched without a login cookie. A signed-in reader's blocked authors are filtered separately so personalized results do not enter the shared cache.

I requested cache updates after post edits and comments. If the API saves successfully but cache invalidation fails, a pending record stays in the database for a retry. I delegated implementation and verification of the browser query updates too.

## Choosing what to send to Sentry

I had Sentry connected to the web apps and APIs to investigate errors after deployment. Reports distinguish services and releases, and separate expected input failures from unexpected server errors.

I did not want someone's posts or chat messages sent along with an error. I asked for request bodies, cookies, and headers to be excluded. Prisma error messages can contain query arguments, so reports retain the error kind, code, and stack locations. I also had the agent check payloads and receipt and report the results.
