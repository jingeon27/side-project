*화면을 고쳐 나가는 모습을 그린 삽화예요.*

관심 있던 아이디어를 직접 서비스로 만들어보고 싶었어요. 사진 커뮤니티와 Game Mate, 개인 블로그를 함께 만들고 있어요. AI에 구현을 맡기고, 나온 화면을 직접 써보면서 다시 고칠 부분을 요청해요.

처음 만들기 시작한 건 `photo-contest`였어요. 그룹에 친구를 초대하고 사진을 올린 뒤 투표하는 서비스였어요. 제출 기간과 투표 기간을 나누고 공동 우승이나 득표가 없는 경우도 처리했어요.

![Game Mate 피드와 회원가입, 사진 커뮤니티의 그룹 탐색 화면](/images/posts/side-project-design/01-service-screens.png)

*개발 중인 화면이에요. 표시된 내용은 테스트 데이터예요.*

## 사진을 보러 왔는데 그룹 목록부터 나왔어요

처음 띄운 홈은 그룹을 고르는 화면에 가까웠어요. 제가 원한 건 가입한 그룹의 사진이 최신순으로 보이는 화면이었어요. 그룹 목록은 마이페이지로 옮기고, 홈에서는 바로 사진을 보게 했어요.

대회가 끝나면 닫히는 공간도 아쉬웠어요. 기간을 정하지 않고 계속 사진을 올릴 수 있으면 좋겠다고 생각했어요. 사진뿐 아니라 동영상과 합성 이미지도 올리도록 바꿨어요. 관리자가 게시물을 지우거나 이달의 인기 게시물을 보는 기능도 추가했고요.

디자인도 실행해 보니 고칠 게 있었어요. 사진을 가리는 배치는 바꾸고, 스토리 기능이 없는데 붙어 있던 테두리는 지웠어요. 데스크톱에서 봤을 때 여백과 배치도 따로 확인했어요.

시작 화면에는 로그인, 회원가입, '익명으로 시작하기'를 모았어요. 익명으로 들어와 공개 그룹을 둘러볼 수 있게 했고, 비공개 그룹은 로그인과 가입 승인을 거치게 했어요.

## Game Mate는 클래시로얄부터

사람들을 직접 모아서 서비스를 운영해 보고 싶었어요. 게임을 하다 막힌 사람이 자기 상황을 올리면 다른 사람이 조언해 주는 서비스를 생각했어요. 제가 접근할 수 있는 커뮤니티에서 첫 사용자를 찾으려면 클래시로얄이 좋겠다고 봤어요.

브롤스타즈나 롤도 생각했지만 처음부터 여러 게임을 다루지는 않기로 했어요. 게임이 늘어날 때 게시판을 붙일 수 있도록, 클래시로얄 아래에 피드백·친추판매·친선전·게임코치·자유게시판을 두는 식으로 만들었어요. 계정 거래는 위험 부담이 커서 뺐어요.

친추판매에는 금액을, 코칭에는 시간당·월·목표 점수까지의 수강료를 입력하게 했어요. 수강생이 코치를 찾을 수도 있고 코치가 수강생을 모집할 수도 있어요. 조건을 보고 채팅으로 이야기할 수 있게 하되, 서비스 안에서 결제하는 기능은 넣지 않기로 했어요.

사진 서비스와 Game Mate의 계정이나 데이터도 합치지 않았어요. 둘 다 다른 사람의 의견을 받는 서비스이긴 하지만, 사진을 보러 오는 사람과 게임 조언을 구하는 사람이 같은 계정으로 써야 할 이유는 없었어요.

## 질문을 올리면 누가 답해줄까

게임 프로필 연동이나 다국어 기능을 만들고 있었지만, 첫 질문에 답해줄 사람이 있어야 했어요. 글을 올렸는데 아무 답도 없으면 다시 들어올 이유가 없으니까요.

```text
고민을 올린다
  → 다른 사람이 답변한다
  → 요청자에게 답변을 알린다
  → 요청자가 읽고 도움 여부를 표시한다
```

처음에는 글과 답변을 저장하는 데까지 생각했어요. 그런데 답변이 달렸다고 알려주고, 질문한 사람이 다시 들어와 읽는 것까지 필요했어요. 답변 알림과 `도움됨` 표시를 넣은 이유예요.

우선 도움됨으로 표시한 답변이 하나라도 있는 요청이 얼마나 되는지 보려고 해요. 같은 요청에 유용한 답변이 여러 개 달려도 요청 한 건으로 세어요. 첫 답변까지 걸린 시간과 24시간 안에 답변을 받은 비율도 같이 보려고 해요.

먼저 답변해줄 사람 5~10명을 찾아서 기존 커뮤니티의 질문과 수동으로 연결해 볼 생각이에요. 아직 모집은 하지 못했어요.

## 게임 프로필을 불러왔다고 본인 계정은 아니었어요

게임 계정 연결은 Player Tag를 입력해서 프로필을 불러오도록 만들었어요. 그런데 다른 사람의 태그를 넣어도 조회는 돼요. 프로필을 불러오는 데 성공했다고 본인 계정이라는 인증 표시를 붙이면 안 됐어요.

연결된 프로필은 우선 소유권 미확인 상태로 두기로 했어요. 운영자가 확인하는 사용자 인증 표시도 게임 계정의 소유권과 따로 봤어요. 실제로 확인하지 않은 내용을 화면에서 인증됐다고 보여 주고 싶지는 않았어요.

처음에는 글을 쓸 때 덱과 게임 정보를 스냅샷으로 남기려고 했어요. 작업하면서 게임 프로필은 사용자 계정에 등록하는 쪽으로 정리하고, 글쓰기 화면의 덱 첨부는 뺐어요. 프로필 인증을 요청할 때는 관리자와 1:1 채팅을 시작하도록 했어요.

## 가입할 때 안 해도 되는 것들

게임 프로필은 가입할 때 꼭 연결하지 않아도 되게 했어요. 바로 연결하고 싶은 사람은 태그를 조회하고, 나중에 하고 싶으면 닉네임과 필수 동의만으로 가입할 수 있어요.

입력할 게 길어져서 본문만 스크롤하고 가입 완료 버튼은 아래에 남도록 바꿨어요. 높이가 짧은 화면에서도 입력과 버튼이 겹치지 않는지 확인했어요.

프로필을 펼침 메뉴에서 수정하는 방식도 마음에 들지 않았어요. '프로필 수정'을 누르면 Bottom Sheet가 열리고, 닉네임과 자기소개를 한곳에서 바꾸도록 했어요. 자기소개에 적은 웹 주소는 프로필에서 누를 수 있게 했고요.

![사진 커뮤니티의 그룹 게시물과 Game Mate의 프로필 수정 화면](/images/posts/side-project-design/09-product-interactions.png)

*그룹 게시물과 프로필 수정 화면이에요. 여기도 테스트 데이터를 넣어 확인했어요.*

버튼과 입력, 모달은 두 서비스가 함께 쓰는 [디자인 시스템](https://github.com/jingeon27/side-project/tree/65c3d13a/packages/design-system)으로 만들었어요. 사진 서비스에서는 사진을 크게 보는 게 중요했고, Game Mate에서는 게임 종류와 작성자의 상황이 잘 읽혀야 했어요. 공통 UI를 쓰면서도 각 화면의 배치와 여백은 따로 고쳤어요.

## 게시글만 번역하면 답변은?

Game Mate는 한국어, 영어, 일본어를 생각하고 만들었어요. 처음에는 메뉴와 게시글을 번역하면 될 줄 알았어요.

그런데 한국어 질문을 일본어로 읽고 답변한 사람이 있으면, 질문한 사람은 그 일본어 답변을 못 읽을 수도 있었어요. 피드백을 주고받으려면 답변도 번역해야 했어요.

언어별 경로는 먼저 만들었지만 번역 기능과 각 언어권 운영은 아직 확인할 게 남아 있어요. 모바일도 웹 화면을 함께 쓰는 WebView로 만들었어요. 우선 웹에서 질문하고 답변을 확인하는 걸 다듬고, 앱 배포와 스토어 운영은 그다음에 하려고 해요.

## 블로그 소개에 이력서까지 넣을 필요는 없었어요

블로그는 저장소와 티스토리에서 같은 글을 관리하는 게 번거로워서 만들기 시작했어요. 익숙한 편집기에서 글을 고쳐서 발행하고 싶었어요.

소개 화면에 이력서와 프로젝트 소개까지 넣을까도 생각했어요. 그러면 글을 읽는 곳에 보여주고 싶은 게 너무 많아질 것 같아서 연락처만 남겼어요. 한국어와 영어 글도 실제 번역이 있는 경우에만 해당 언어로 볼 수 있게 했어요.

지금도 화면을 직접 써보며 고치는 중이에요. Game Mate는 질문할 사람과 답해줄 사람을 찾아보는 일이 남았어요. 답변을 받은 사람이 다시 들어와 읽는지부터 보고 싶어요.
