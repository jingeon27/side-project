오렌지 작성 버튼, 사진 중심 인기 목록, 익숙한 앱 패턴은 유지했다. 장식을 늘리지 않고 실제 그룹 작업의 위치와 연결을 다듬었다.

- **P1 해결:** 모바일에서 9개 게시물 뒤 y4929에 있던 초대·멤버 도구로 가는 진입을 소개 아래 y165에 제공한다. 기존 details를 열고 summary에 포커스를 옮겨 관리 내용과 상태를 복제하지 않는다.
- **P2 해결:** 큰 빈 인기 패널을 한 문장으로 줄였다. 멤버의 첫 게시물 행동은 현재 그룹 작성 화면으로 바로 연결하며 390×900에서 y815.6, 높이50으로 첫 화면 안에 들어온다.
- **P2 해결:** 아바타를 위로 정렬하고 긴 소개를 전체 폭에서 읽게 했다. 그룹 소개·탭·카테고리를 같은 최대 폭에 정렬했다.
- **크기 판정 정정:** 기존 카테고리는 시각 높이36px이지만 공통 pseudo-element로 유효 hit area44px이었다. 이전 터치 기준 위반으로 세지 않는다. 이번 변경은 시각 크기44px와 확대된 글자의 줄바꿈을 개선한다.

처음 방문한 사용자는 멤버와 첫 작성 행동을 찾기 쉬워지고, 모바일 사용자는 긴 피드를 내려 초대 도구를 찾을 필요가 줄었다. 긴 글자·권한을 점검하는 사용자는 기존 경계를 유지하며 복구 행동을 받는다. 반복되는 큰 빈 안내가 줄고 작성 행동에 도달하는 흐름이 짧아졌다.

320px·200% 사용자 글꼴에서 긴 카테고리로 생긴 document width371px가320px로 바뀌었다. 추가 확장 검증에서 기존 초대 링크 재생성 버튼의 넘침도 확인해375→320px로 고쳤다. 공유·복사·재생성은 버튼 폭과 줄바꿈 규칙을 적용하고 모바일은 한 열로 표시한다.

승인 재확인을 offline에서 실행하면 기존 대기 안내를 유지하면서 실패를 알린다. 연결 후 같은 버튼으로 재시도한다. 서버 오류를 별도 useState로 복제하지 않고 QueryRef에서 읽는다. 미가입자·승인 대기자에게 작성 버튼이나 비공개 피드를 노출하지 않는다.

## 근거와 남은 관찰

A는 독립 v1에서 같은 역할·상태·폭23건을 비교하고 v2에서는 빈·장문6화면과 초대 확장1상태를 추가 확인했다. B는 기본 글꼴32건과 실제 Chromium 사용자 글꼴200%12건을 비교했다. 폭은320/390/768/1440px다. 후 검사에서 가로 넘침과 pageerror는0건이다. 키보드 작성 직행, 기존 details 열기·포커스 이동, 카테고리만 제거하며 나머지 query·중복 키·hash 보존, 피드 실패와 승인 재조회 복구를 확인했다.

소스 detector는0건이다. 숨겨진 Activity의 이전 FAB가 토스트 위치를 잘못 잡을 가능성은 실제 SPA 전환으로 재현되지 않아 finding이나 감점으로 기록하지 않았다. 이전 관련 작업에서 거절된 DOM 교체·렌더 overlay는 재실행하거나 우회하지 않았다. 일반 탐색·실제 사용자 글꼴 설정·앱 E2E를 근거로 삼았다.

남은 디자인 관찰은 **P3 두 건**이다. 인기 게시물을 먼저 보여 주는 기존 제품 순서 때문에 게시물이 있는 모바일 화면에서 최신 목록이 낮게 시작한다. 390×900 빈 피드에서 본문 첫 작성 링크의 오른쪽 약20px가 고정 FAB와 겹치지만 문구와 중앙 클릭은 가능하고 두 링크의 목적지도 같다. 새 P0/P1은 없으며 이 관찰을 완전 해결로 표시하지 않았다.

실기기 제스처·실제 스크린 리더·Lighthouse·CPU/프레임 성능을 검증했다고 주장하지 않는다. 테스트는 별도3320/4320, PostgreSQL55434의 실행별 스키마와 tests/ S3 prefix를 사용했다. 개발 데이터·사용자 로그인 세션은 변경하지 않았다. 로컬 평가 원본·캡처는 `projects/photo-contest/.data/design-review/group-detail-polish/`, critique 전후 기록은 worktree의 `.impeccable/critique/`에 보존하며 세션·DB·머신 경로가 포함된 로컬 자료는 PR에서 제외한다.

질문 생략: 사용자가 이미 polish와 push/PR을 요청했고, 남은 관찰은 P3 두 건이다.
